# PicoAide 应用构建（WASM 应用）

一句话：**你写一个 Go 程序，编译成 `wasm32-wasip1`，上传到平台；应用只在桌面客户端内打开
（应用中心点开，或点开分享的深链），由客户端把它转发到平台执行。**

平台已经把"能做什么"限死了：只有一张数据库（每个应用一个）、一份随包的静态资源、
一行日志。**这不是配置问题，是能力不存在** —— 所以照着下面的黄金路径走，不要试图绕过。
（**AI 不在这张清单里**：wasm 侧没有 AI 能力；应用里的 AI 走**前端桥**，
见下文「应用里的 AI：前端桥」。）

## 什么时候用

- 用户要一个内部小工具：共享便签、登记表、值班表、报销备注、清单勾选、小型计算器。
- 数据量小（几千行以内）、界面简单（一两个页面）、只给一小撮同事用。
- 用户说"能不能在这个平台上做个应用 / 发布到应用中心 / 我们自己搞一个"。

**不要用**（能力不存在，硬做只会卡住）：

- 需要访问外部系统 / 调外部接口 / 打开外部网页 → 应用**不能主动发起网络请求**（`fetch`/`XHR` 一律被拦）。⚠️ **不要对外说成"平台不能联网"**（见「访问方式与硬限制」里的边界说明）。
- 需要读写文件、跑命令行、起后台任务、开定时器 → 平台没有这些能力。
- 需要图片/视频/大文件处理、需要几十 MiB 以上的数据 → 体积与内存上限都很小。
- 需要 Python/Java/Node 生态 → 只支持 Go（Rust/Zig 可用但不承诺）。
- 需要"每个用户只看自己的数据" → 同一应用内数据是共享的（见硬约束第 3 条）。

## 黄金路径

1. **问清三件事**再动手：一句话用途；谁能用（账号名单，手填）；要存什么（表 + 字段）。
2. **拷骨架**：把 `examples/go/` 整个目录拷到会话工作区，改业务逻辑。
   三段式：`read_request` → 调宿主（JSON-RPC）→ `write_response`，不要自创协议。
3. **写 `picoaide.app.json`**（和 wasm 一起上传）：`access`（写侧只有 `login` / `whitelist`；
   历史 `public` 读取侧按 `login` 处理，新版本不要再写）
   + `whitelist` / `purpose` / `data_sensitivity` / `owner`；字段规格与必填项以
   `references/app-config.md` 为准（从平台源码生成，不要凭记忆写字段名）。
4. **本机编译 + 本地自测**：先按 `references/publishing.md` §0 确认工具链（`go version`），
   再按 §1 的**固定步骤**把四条状态目录（`GOCACHE`/`GOMODCACHE`/`GOPATH`/`TMPDIR`）指向会话
   工作区，然后 `GOOS=wasip1 GOARCH=wasm go build`，最后用 Node 自带的 `node:wasi`
   当假宿主跑一遍。**这四条目录不是可选项**——漏了会看到 `package fmt is not in std`。
5. **预检 → 发布**：用 `wasm_app_validate` 预检（不占版本号），通过后用 `wasm_app_publish` 发布
   （`wasm_app_list` 可查标识是否被占用、当前版本号是多少）；
   任何失败都带 `code` / `details` / `hints`，按 hints 改完重发即可 —— **失败的发布不占版本号**。
   `IMPORT_NOT_ALLOWED` / `IMPORT_SIGNATURE_MISMATCH` 这类**导入面**问题不要靠试错：平台放行的
   全部符号与签名在 `references/imports.md` 里，先对照它再改代码。
6. **交付**：给用户**深链** `<渠道 scheme>://app/<app_id>`（scheme 由该客户端的渠道配置决定，
   **不要写死 `picoaide://` 之类**），并提醒他：不在名单里的人打开会看到
   一页"你不在名单里 + 你的账号是 xxx"，让用户自己核对名单拼写（平台不校验账号是否存在）。

## 访问方式与硬限制（动手之前先读）

- **只在桌面客户端内打开**：应用**没有浏览器地址** —— 不存在 `<app_id>.<域名>` 这种 URL，
  平台也不签发应用域名/证书。打开方式只有两种：客户端「应用中心」点开，或点开上面那条深链。
  应用在客户端里的 origin 是 `<渠道 app 源 scheme>://<app_id>`（**scheme 由渠道配置决定**，official/beta 取值才是 `picoaide-app`，**不要写死**），每个应用一个 origin。
- **不能用 cookie**：自定义协议下 cookie **完全不可用** —— 页面的 `document.cookie` 恒为空、
  服务端 `Set-Cookie` 不会落盘。要保存状态请放进**应用库**（`db.define` / `db.query` /
  `db.exec`）；登录态由宿主在每一帧里交给你，不要自己存会话。
- **不能主动发起网络请求、不能读文件**（见硬约束里"不能主动发起网络请求"那一条）：沙箱与 CSP 挡住的是**应用自己
  发起的 `fetch`/`XHR`**（`connect-src 'self'`），HTML/CSS/JS/图片必须编进 wasm，外部 CDN 与
  对外 `fetch` 一律失败。⚠️ **但这不等于"不能联网"、也不是数据外带防线**：**CSP 不管顶层导航
  与弹窗** —— 应用页可以用 `location.href='https://…'` 把数据带出去，导航/弹窗由客户端窗口闸门
  与外链策略兜底。**对外文案与排障话术都不要写"不能联网"。**
- **一律要求登录**：平台没有匿名面，每个请求都带已登录的使用者身份。

### 存储放哪里（**选错会丢数据**）

| 存储 | 可用 | 生命周期 | 用途 |
| --- | --- | --- | --- |
| 服务端**应用库** `db.*` | ✅ | **不随清缓存 / 切账号被清**；跨设备一致 | **一切要留存的东西**（业务数据、设置） |
| `localStorage` | ✅ | 按 origin 隔离；**随客户端清缓存 / 切账号被清** | 可再生的界面偏好 |
| `sessionStorage` | ✅ | 同上，且随窗口关闭消失 | 单次打开的临时态 |
| `IndexedDB` | ✅ | 按 origin 隔离；**随清缓存 / 切账号被清** | 体积较大的可再生素材缓存 |
| **`Cache Storage`（`caches.open` / SW 缓存）** | ❌ **禁止依赖** | — | `caches.open()` 会成功，但 `cache.put(new Request('<app scheme>://…'))` 必抛 **`TypeError: … Request scheme '<app scheme>' is unsupported`**；不要写"离线优先" |
| cookie | ❌ | — | `document.cookie` 恒为空、`Set-Cookie` 不落盘 |

⇒ **要留存 → 放应用库；浏览器存储只当可再生的缓存。** 完整对照表与实测口径（含"仅 Linux 单平台实测、Windows/macOS 未复核"的认账）见作者手册 `docs/wasm-app-authoring.md` §1.2。

### 窗口尺寸（`window.*`，可选）

`picoaide.app.json` 的 `config` 里可以声明窗口：

| 字段 | 取值 | 语义 |
| --- | --- | --- |
| `window.ratio` | `"W:H"`（如 `"16:9"`）或浮点（如 `1.7778`） | **强制锁定**的宽高比（客户端 resize 时按比例约束）；**合法区间 `0.25`–`4.0`**，越界（含 `0`/负数/非数字）⇒ **发布期 `APP_CONFIG_INVALID`** |
| `window.width` / `window.height` | 像素数字，可选 | 首次打开的默认尺寸；缺省 **1280×720**，随后按 `ratio` 校正 |

`ratio` 是**锁定**不是建议：布局要能适配同一比例下的不同像素尺寸；窗口尺寸只决定"首开默认"，之后由客户端按应用/按用户记忆。

### 员工侧会看到什么（**产品级口径**）

| 场景 | 员工看到 |
| --- | --- |
| 应用**被冻结**（管理员停用） | **不列进应用中心**（冻结不进目录）；但深链/历史仍能打开 ⇒ 给**「已被管理员停用」+ 联系负责人**（**不是**"应用不存在"，两句话不得混用） |
| 应用**被下架** | **仍列在目录里**，条目带「已下架」标记；直接打开 ⇒ 「已下架」 |
| 应用**被删除** | 直接打开 ⇒ 「应用不存在」 |
| 我**不在 `whitelist` 里** | 应用**照常出现在目录**（权限不参与目录过滤）；点开由**应用自己**返回 403（页面显示本人账号） |
| 目录**没有可用项** | ①一个都没有 ⇒ 引导"让 AI 做一个"；②列表非空但**每一行都是已下架** ⇒ 给"全部已下架"那一档提示（说明原因）。"目录里全是冻结"**结构性不可达**（冻结不进目录） |
| 应用**很多** | 支持按名称 / 一句话 / 负责人**搜索** + 「**我发布的**」筛选；条目多时分批展示 |
| **打开计数** | 应用详情会显示「**今日已被打开 N 次**」（平台记录的运营数据，隐私说明里有写明）—— 不要在自己页面里重复造计数 |

**排障口诀**：员工说"应用不见了" ⇒ 先分清**被冻结**（管理端动作，**目录里真的不见了**、深链仍可开、文案「已被管理员停用」）/ **被下架**（作者动作，**目录里还在**、带「已下架」标记，点开文案「已下架」）/ **权限不符**（应用仍在目录，点开 403）。三者处置完全不同。

## 十一条硬约束

1. 编译目标是 **`wasm32-wasip1`**（Go：`GOOS=wasip1 GOARCH=wasm`）；官方支持的语言只有 **Go**。
2. 应用**无状态**：实例每个请求新建，全局变量存不住任何东西 —— 状态只能进数据库。
3. **同一应用内所有用户共享数据**；要区分用户就在自己的表里加一列存 `user.username`。
4. **stdout 只写协议帧**（`RS` + 十进制长度 + `\n` + JSON）；**日志走 `log` 宿主调用**
   （单条不超过 4 KiB，每个请求最多 100 条）。
5. **服务端没有 `ai.chat` 这个能力**（该宿主能力已删除）：AI 只能由应用**前端**经保留路径
   `POST /__picoaide/ai/chat` 调客户端（由客户端本地处理，不经服务端）；wasm 侧不再有任何
   AI 能力，不要把它写进应用逻辑（见「应用里的 AI：前端桥」）。
6. **不能主动发起网络请求、不能读文件、不能开线程**（**不要对外说成"不能联网"**：CSP 不约束顶层导航与弹窗）
   ；HTML/CSS/JS/图片都必须编进 wasm（外链与对外 `fetch` 一律失败）。
7. **准入由你自己判**：`access` 写侧只有 `login` / `whitelist`（历史 `public` 读取侧按
   `login` 处理）；入口第一件事就是读 `picoaide.app.json` 的 `whitelist` 并比对；
   无权限页**必须显示本人账号**（`user.username`），这是作者发现名单拼错的唯一途径。
8. **平台不提供员工名录**：名单只能手填已知账号；**改名单 = 发一个新版本**，运行期改不了。
9. **不要依赖 `$HOME`**：四条状态目录（`GOCACHE`/`GOMODCACHE`/`GOPATH`/`TMPDIR`）**必须**
   指向会话工作区（`references/publishing.md` §1 的固定步骤），否则你会看到
   `package fmt is not in std` 这种指向完全错误方向的报错。
10. **发布前先本地自测**：Node 自带的 `node:wasi` 零依赖就能跑产物（读 stdin 帧、写 `RS` 帧）。
11. **应用名就是标识**：`app_id` 同时是应用 origin 的 host 段（`<渠道 app 源 scheme>://<app_id>/`，渠道参数化：official/beta 取值 `picoaide-app`）；
    小写字母/数字/连字符、不超过 63 个字符、
    不能纯数字、不能 `xn--` 开头、不能是平台保留字；**一经发布不能改名**。

## 应用里的 AI：前端桥

**wasm 侧没有 AI 能力**：平台删掉了原来的 AI 宿主调用，Go 代码里调不到模型。
应用里的 AI 只有一个入口 —— **应用前端 JS 调宿主**，走**保留路径**：

```js
const res = await fetch('/__picoaide/ai/chat', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ messages: [{ role: 'user', content: '把这段便签总结成一句' }], stream: true }),
})
```

- **谁处理**：客户端（桌面客户端的协议 handler）**本地**处理，**绝不转发平台服务端**。
  应用不得定义 `__picoaide/` 前缀的路由（发布校验直接拒），其余 `__picoaide/*` 路径一律 404。
- **请求契约**：`{messages:[{role,content}], stream:bool}`，**未知字段一律拒**；`messages`
  只有本次传入的这一份 —— 不注入记忆、不注入用户会话历史、不注入系统提示。
- **返回形态**：`stream:true` ⇒ `text/event-stream`，逐段发 `delta` 事件、以 `done` 收尾；
  `stream:false` ⇒ 一次性返回 `{content, usage?}`。
- **只做对话**：没有工具、没有文件、没有连接器、没有记忆、没有用户历史；应用**不允许**声明
  提示词 / 模型 / 温度（平台统一默认）。
- **会话**：每个应用一个**隐藏会话**（不出现在侧边栏，诊断与审计里可查），多轮上下文由它承载。
- **授权**：**首次调用由使用者授权一次**（按 使用者 × 应用 记录），可在客户端设置里撤销；
  未授权时先出一次性说明卡，拒绝 ⇒ 403 `app_ai_denied`，且不消耗任何 token。
- **计费**：走**使用者本人**既有的 LLM 链路（扣他自己的余额）＋**应用维度归因**
  （应用详情页能看到这个应用的 AI 用量）。
- **仅前台**：应用页面一关闭，这一轮就被取消 —— **不存在**后台跑 AI 的通道。
- **时间与并发**：这一路 AI 由客户端处理，**不占应用自身的请求并发**（业务层不设上限）；
  真正的边界在传输层（连接有超时兜底），不要当"可以无限等"。
- **错误码**（一律 JSON 信封）：`app_ai_denied`（未授权）/ `app_ai_unavailable`（宿主不可用）/
  `ai_balance_insufficient`（余额不足：提示去桌面客户端看余额，**不显示金额、不要重试**）/
  `ai_rate_limited`（稍后重试）/ `ai_cancelled`（页面关闭或主动取消，属正常收尾）。

**老应用硬切，不静默**：仍导入 `ai.chat`（服务端已删除的旧 AI 宿主调用）的产物在**导入期
就被拒**（`IMPORT_NOT_ALLOWED` ＋迁移指引），发布校验同步拒绝。迁移形态只有一条：
**前端调 AI → 结果回传 wasm 落库** —— wasm 里不再有 AI 调用；让前端把 AI 结果（或它的入参）
POST 回应用自己的路由，再由 `db.exec` / `db.query` 落库与展示。

## 并发与队列（默认值，运维可在控制台改）

同一应用默认最多 **4 个请求并发**（读并发；**写仍串行**，SQLite 只有一个写者）。
但**单个用户在同一应用内默认只有 1 路**（`user_per_app_running=1`）：自测时用同一个账号
打并发看不到 4 路，这是**排队规则不是平台串行**（被排队的只是同一个用户）——不同账号才吃满 4 路。

队列 32、每用户同应用排队 4 个、每用户跨应用在跑 4 个、全局实例 32 都是**默认值**，
不是固定值：运维可在控制台「应用中心 → 限制项」改（队列可调到 4096、全局实例可调到 256）。
作者不可调这些值；撞到 `APP_QUEUE_FULL` / 429 时按 `references/diagnostics.md` 处理。

## 包内资源与保密（放机密之前必读）

`assets.read` 读到的资源**默认不对外公开**（它只在宿主磁盘上，按包内逻辑路径读，
没有文件系统语义，外面也列不了目录）。**唯一例外是"非保留资源"**：
`picoaide.app.json` 之外的一切包内文件（HTML/JS/CSS/图片/字体/数据文件）会被宿主
**按路径直出给任何能打开应用的人** —— 这正是"静态资源编译进 wasm"的用法，
也是平台能把静态响应缓存起来的依据。

因此：

- **不要把机密、账号名单、内部说明、口令、内网地址放进非保留资源**：
  `GET /data/users.json` 任何能打开这个应用的人都能拿到，**与 `access` 无关**
  （登录只决定**谁**能打开应用；能打开的人在应用内取子资源照样直出）。
- **名单放 `picoaide.app.json`**：它是平台保留资源，**不会被直出**；只有应用自己用
  `assets.read` 读得到它，访问者拿到的是应用自己写的（404/403）页面。

## 三条最容易踩的坑

- **把日志打到 stdout**：非 `RS` 开头的输出会被平台当日志丢掉（不会污染协议，但你也看不到
  级别/条数管理）—— 用 `log` 宿主调用。
- **把不该做的事放进事务**：事务内只允许数据库读写（`db.query` / `db.exec` + 两个出口
  `tx_commit` / `tx_rollback`）；`log` / `assets.read` / `db.define` 与再开一个事务
  一律报错（详见 `references/abi.md` §3.3）—— 需要它们就先提交事务再做。
- **表结构想改就改**：不能用 DDL，也不能自动迁移；改结构 = 用 `db.define` 建新表或加列，
  自己搬数据（一个应用最多 16 张表、每张最多 16 列）。

## 渲染页面：模板可以直接用

**`html/template` / `text/template` 的 `Parse` + `Execute`（渲染）是被允许的**——
把页面模板编译进 wasm、渲染成 HTML 再写成响应体，是本平台最主要的用法。
标准库的常用面（`encoding/json`、`strings`/`strconv`/`sort`/`regexp`、`net/url`、`time`、
`base64`、`hash/*`、`io`/`bufio`/`bytes`、`context`、`sync` 等）同样可用。
不要因为"平台限制多"就自己手写字符串拼接去绕开模板。详见 `references/abi.md` §8。

## 数据边界（要主动告诉用户）

这是一个**内部小工具**：同一应用里所有人看到同一份数据，应用自己不做行级隔离；
应用在客户端内以独立 origin（`<渠道 app 源 scheme>://<app_id>`，渠道参数化）打开，与主站、与其它应用都不同源，
但**应用拿不到任何平台凭证**，宿主只会告诉它"当前使用者是谁"。
需要"按人隔离"或"敏感数据"时，先跟用户确认再动手。
