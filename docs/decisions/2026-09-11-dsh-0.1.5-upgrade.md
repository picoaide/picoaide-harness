# 2026-09-11 上游 DSH 升级 0.1.2-rc.1 → 0.1.5-rc.2

## 背景

上游 `deepseek-ai/deepseek-harness` 自 0.1.2-rc.1（2026-09-03）起推进到 0.1.5-rc.2（2026-09-10），
中间跨越 1490 个提交 / 6774 个文件（+208,236 −58,164）。评估结论见
[`docs/planning/2026-09-11-dsh-0.1.5-upgrade-assessment.md`](../planning/2026-09-11-dsh-0.1.5-upgrade-assessment.md)
（含逐项 file:line 证据与四份子代理深挖，原始产物在 `temp/dsh-compat-015/`）。

产品决策（2026-09-11，用户拍板）：

1. **现在就升**到 `dsh-v0.1.5-rc.2`（上游至今无正式版，不存在"等稳定版"的明确时点）；
2. **右侧栏改用官方实现**，退役 vendored 的 `dsh-better-sidebar`；
3. **回滚姿态 = 前向 only**：不为降级做兼容，改为"升级前备份 + 整目录恢复"的运维口径。

## 变更内容

### 1. Pin 与依赖族

- submodule pin → `dsh-v0.1.5-rc.2` = `fb2c4b9e698e30edb738bca4cf0618587db7d203`，`upstream.json` 同步；
- 全部 `@deepseek-ai/dsh*` 依赖/补丁 resolution 升到 `0.1.5-rc.2`；
  **npm `latest` 仍是 0.1.5-rc.1，升级必须显式指定 tag**（`scripts/upgrade-upstream.mjs --to dsh-v0.1.5-rc.2`）。

### 2. 桌面 advanced frame 重写（P0，否则静默白屏）

rc.2 把根布局槽位从 `sidebar / conversation / details / shell.overlay` 改成
**`sidebar / main(keyed) / rightbar / shell.overlay`**，`ctx.layout` 也从 `openDetails/closeDetails`
换成 `selectPanel / beginNavigation / toggleSidebar / openRightbar / closeRightbar`，并新增根标准源
`usePanelInfo`。桌面 profile 一直禁用 `ui-layout` 行、由自己持有 frame，因此这些契约必须自持实现：

- `client/layout-state.ts`：实现 rc.2 `ILayout`，列宽数学对齐上游 `columns.ts`
  （`CENTER_MIN=400`、`RIGHTBAR_MIN=300`、`RIGHTBAR_MAX_RATIO=0.7`、`RIGHTBAR_DEFAULT_RATIO=0.45`），
  并发布 `panelInfo` 根标准源；
- `client/advanced-shell.ts`：声明新子槽、`slots.provideRoot({ hooks: { panelInfo } })`、
  订阅 `main` 键集合做选中态收敛；
- `client/AdvancedFrame.tsx`：`renderSlot('main', {}, { entryKey: activePanelId ?? 'conversation' })`
  + `renderSlot('rightbar', { width, viewportWidth, canShow })`；`details` 列与 `SessionProvider` 包裹移除
  （rc.2 的 `rightbar` 是 root 作用域，会话绑定由官方 `rightbar.session` 自持）；
- `client/contracts.ts`：不再自行 `declare module` 槽位与 `Context.layout`，改为 import 上游声明
  （自持声明会与上游冲突或在 `skipLibCheck` 下静默漂移 —— 正是这次 `conversation`→`main` 的教训）。

失败形态是**静默**的：`slots.inject` 等不到声明就永不回调，窗口能开、会话区空白、无 console 错误，
且 `verify-profile-boot` 只查包名，照样绿。

### 3. 右侧栏改用官方实现，退役 `dsh-better-sidebar`

- 新增官方三行（web bundle 默认启用）：`ui-sidebar-right`、`ui-sidebar-file`（文件树）、
  `ui-sidebar-documentpreview`（预览）；
- cron 的「计划任务」tab 从 `ctx.betterSidebar.registerTab` 迁到官方
  `ctx.sidebarRightTabs.register({ id, kind, title, guide })` + keyed `sidebar.right.pane.tab` 正文注册；
- 删除 vendored 包及全部引用：desktop 依赖 / `profile.ts` 覆盖层 / prebuild 列表 / 门禁包表 /
  `verify-layout` 名字表 / CI `workspace-build` 归档 / `THIRD_PARTY_NOTICES` /
  `sidebar-policy.ts`（其策略随包消失）/ Windows 标题栏共存 CSS。

**能力变化（有意为之）**：官方右栏是"只读预览 + 文件树 + 任意插件 tab"的底座，
不含编辑器、交互式终端、Git 面板、内嵌浏览器视图与底部面板；`README` 中相关表述已同步删除。
node-pty 仍然保留（上游 `subprocess-local` 自身依赖它）。

### 4. 打包层改名（P0，且原门禁空转）

上游把原生插件 `@deepseek-ai/node-addon-landlock-run*` 改名为 **`@deepseek-ai/node-addon-system*`**
（新包另带 rc.2 会话写入所需的 `flock` 预编译模块）。改动：

- `build.asarUnpack` glob → `**/node_modules/@deepseek-ai/node-addon-system-*/bin/landlock-run`；
- `REQUIRED_UNPACKED_RUNTIME_ENTRIES` 的 linux 条目、`mac-runtime.ts` 的 darwin 条目（新包 darwin 侧只有 `bin/system.node`，无启动器）；
- `package.spec.ts` 的 glob 字面量与 resolutions 断言。

原门禁对"整包目录不存在"的条目是跳过（`verify-packaged-runtime.ts` 的"平台不适用"分支），
所以改名后它会**带着缺失的沙箱启动器通过**。新增回归测试
`keeps the native sandbox glob matched to the installed addon package family`：把 asarUnpack glob
与实际安装的包名做匹配断言 —— 改名的包名不可能再"空转过关"。

### 5. 补丁表

| 补丁 | 处置 |
| --- | --- |
| `dsh-llm-deepseek` | **删除**：上游 `acceptIdentity()` 已严格覆盖（空串/null 视为"无更新"），三方运行时证明见 `temp/dsh-compat-015/proof/` |
| `dsh-win32-process` | **重切**：上游把继承路径合并进 `spawnJobProcess`，上下文位移；替代补丁已按 rc.2 产物重制并校验（真机 Windows 复验仍待做） |
| `dsh-agent-presets` / `dsh-client-ui-brand-official` / `dsh-plugin-package-inventory-deepseek` | **原样保留**（产物字节相同，干净应用） |

顺带修好两个升级脚本缺陷（都会在下次升级复现）：

- `scripts/upgrade-upstream.mjs` 的 resolution **脱字符键**未被改名（`@npm:^0.1.2-rc.1` 保持旧版本，
  导致上游以 `^` 范围请求的传递副本拿不到补丁）；
- 同脚本重写的 `scripts/platform-modules.mjs` **缺逗号**（生成的数组字面量非法，tsdown 加载配置即语法错）。

### 6. 会话格式 v0 → v3（数据面）

我们的 pin 是格式 **v0**（`SESSION_FORMAT_VERSION = 0`），rc.2 当前为 v3，链上 v0→v1→v2→v3 均可迁。
迁移是**副本式**：`list()`/`stat()` 只读头部；**read open 只在内存迁移**；首次 **write open**（恢复会话）
才在同目录发布 `session.v3.jsonl[.zstd]`，**源文件逐字节保留**。没有任何开关可控制迁移。

**降级是静默有损的**：rc1 只认 `session.jsonl[.zstd]`，回滚后 rc2 期间新建的会话不可见、
迁移过的会话读到旧内容；再升回 rc2 时选最高世代 v3，**丢掉 rc1 期间写入的尾巴**。
因此本产品采用**前向 only**：

- 升级前备份 `<DSH_HOME>/sessions/` 与 `<DSH_HOME>/storages/session_projcache.json`（整个 `DSH_HOME` 最稳）；
- 需要回滚时**整目录恢复**（含停止写入），**不允许**只换回旧二进制。

### 7. 升级当天的 Yarn 隔离门（运维注意）

Yarn 4.10+ 默认 `npmMinimalAgeGate: "1d"`：发布时间不足 24 小时的版本会被判为 quarantined
（`YN0016 All versions satisfying "…" are quarantined`），CI 用的裸 `yarn install --immutable`
同样受此约束。本次升级当天本地迭代用 `YARN_NPM_MINIMAL_AGE_GATE=0` 临时放行
（**未写入 `.yarnrc.yml`**，仓库的供应链默认未改），并在放行窗口过后用默认策略重跑安装自证。

⇒ **以后升级上游时**：pin 到"当天发布"的 tag 后不要立即推分支，否则 CI 会在 install 步假红；
要么等 24 小时窗口，要么先本地验证、窗口过后再推。判断方法：
`npm view <pkg> time --json` 取该版本发布时间，加上 24 小时即为放行时刻。

## 验证

- `corepack yarn check`：12 → 11 个任务（少一个 vendored 包）全绿；
- 桌面单测 683 例（新增 rc.2 布局用例：`main` 选中/拒绝未注册键、右栏 track 与首选宽度、窄屏 rail 复展）；
- `e2e:client`：新增两条断言 —— 「rc.2 根槽位已声明（`main`/`rightbar` 存在、`details` 消失）」
  与「会话主区已挂载且无 `[data-slot-error]`」，正是这次静默失效的回归守卫；
- 打包产物：`package:dir` + `afterPack` 原生条目校验（含改名后的沙箱启动器）。

## 遗留

- `dsh-win32-process` 的隐藏控制台补丁只在本机 Linux 上做了产物级校验，**需一次 Windows 真机打包运行**确认 `SW_HIDE` 生效；
- 官方右栏的交互（tab 拖拽/分栏/浮动/预览）尚未做真机 UI 走查，随下一个 beta 观察；
- 上游 CLI 现已硬拒绝 `desktop` profile 名（`dsh --profile desktop` 与 `dsh plugin --profile desktop`），
  第三方插件改由 `~/.picoaide-harness/cordis.patch.yml` 用户层加入（架构文档已同步）。
