# DSH 0.2.1-rc.2 升级：三条必须留痕的裁决（2026-10-18）

> 决策记录。事实面的入口是 `upstream.json`（固定点）、`scripts/upgrade-upstream.mjs`
> （唯一的升级入口）与本文。
> 状态：**已收口** —— `yarn check` 全绿；8 个自研包的伴生入口、打包清单与棘轮已同步。
> 分支：`chore/dsh-v0.2.1-rc.2`（不直接进 master）。

## 背景

上游固定点从 `dsh-v0.2.0-rc.2`（`639ed015397290b3745d163aafe02ffee4aa3f84`）升到
`dsh-v0.2.1-rc.2`（`687f282e8625c6b8d11ff58211a90524be2e4317`），中间 **1925 个提交**。

上游包集这次不是"干净升级"：删除 3 个包、新增 31 个包、10 个包换了路径。

- 删除：`@deepseek-ai/dsh-experimental-schedule-bundle`、
  `@deepseek-ai/dsh-invariants`、`@deepseek-ai/dsh-subagent-in-process-driver`；
- 新增（节选）：`dsh-plugin-market` 系、`dsh-cua` / `dsh-experimental-cua-macos`、
  `dsh-experimental-*` 一批实验包、`dsh-working-directory` / `dsh-tool-working-directory`、
  `dsh-web-deepseek-api`、`dsh-ssh-helper-runtime` 等；
- 路径迁移：`hooks/*`、`webhook/*`、`skill-badge`、`tool-ralph`、`tool-terminal` 等
  10 个包移入 `packages/experimental/`（包名不变，只有仓库内路径变化）。

前两项由上游升级指南明确给出迁移口径（`docs/upgrade-guide/v0.2.0-rc.2/`）；第三项是
纯库退役。三条裁决都记在下面。

## 裁决一：运行时不变式服务退役，8 个伴生入口全部删除

**上游变更**：`@deepseek-ai/dsh-invariants`、`InvariantRegistry`、`InvariantInstaller`、
`InvariantFailure`、`InvariantError` 以及所有 `<package>/invariant` 子路径在 0.2.1 全部删除；
`sdk-minimal` profile 不再挂载 `invariants` / `*-invariant` 五行。上游指南：
`docs/upgrade-guide/v0.2.0-rc.2/remove-runtime-invariants/guide.zh.md`。

**本仓影响**：我们有 8 个包各自发布一个 **no-op** 的 `./invariant` 伴生插件
（`src/invariant.ts`：`inject = ['invariants']`，`ctx.invariants.register(...)`），
并在桌面打包清单里登记了对应的 `lib/invariant.js`。上游服务删除后这些行无法装配，
且 `@deepseek-ai/dsh-invariants` 不再发布。

**定案**：按上游指南整批删除，而不是保留兼容：

- 删除 8 个 `src/invariant.ts`（`account-card`、`branding`、`wasm-apps`、`browser`、
  `connectors`、`cron`、`enterprise`、`wasm-apps-host`）；
- 各包 `package.json` 删除 `exports["./invariant"]`、devDependency
  `@deepseek-ai/dsh-invariants`；
- 各包 `tsdown.config.ts` 删除 `invariant: 'src/invariant.ts'` 入口；
- 桌面 `package.json` 删除 `@deepseek-ai/dsh-invariants`；
- `scripts/verify-packaged-runtime.ts` 删除 5 条真实的 `lib/invariant.js` 必需项与 2 条
  `@picoaide/*/invariant` specifier；测试同步删除对应断言；
- `REQUIRED_WORKSPACE_PACKAGE_COVERAGE` 每包三条计数各减 1，生效清单总下限
  **129 → 122**（棘轮仍贴住真实条目；理由必须与本次升级同批写明，见常量上方注释）。

`branding` 的 `tests/plugin.spec.ts` 只保留宿主插件的两条用例；`invariant` 伴生用例删除。

## 裁决二：`dsh-subagent-in-process-driver` 退役，桌面不再直接声明

**上游变更**：旧的共享 run driver 库被拆成两个独立的 in-process backend：
`@deepseek-ai/dsh-subagent-spawn-in-process` 与
`@deepseek-ai/dsh-subagent-fork-in-process`，各自持有 run 生命周期；旧的
`dsh-subagent-in-process-driver` 不再发布。

**本仓影响**：桌面 `dependencies` 直接声明了旧库，但**没有任何 import**——它原本是
in-process backend 的传递依赖，列出来只是为了固定版本。新 backend 由消费方自己持有，
本仓的组合里也没有直接挂载它们（继续走 `@deepseek-ai/dsh-subagent` 的 provider 面）。

**定案**：删除桌面的直接依赖，不新增 backend 行。若未来组合需要 fork/spawn backend，
按上游包名单独声明，不再通过 driver 库。

## 裁决三：`@modelcontextprotocol/client` 钉回 2.0.0

**问题**：`@deepseek-ai/dsh-mcp-client@0.2.1-rc.2` 声明 `@modelcontextprotocol/client@2.2.0`，
而本仓 `packages/host/connectors` 声明 2.0.0。Yarn 因此在 `dsh-mcp-client` 名下嵌套了第二份
2.2.0，触发我们自研的 MCP transport fence：fence 要求"本包解析到的 SDK"与"mcp-client 解析到的
SDK"是**同一个物理模块**（`R3-N3`），否则拒绝注册并报
`McpTransportFenceUnavailableError`。

2.2.0 还改了静态 header 的优先级：`StreamableHTTPClientTransport` 会把声明好的
`Authorization` 覆盖成框架 bearer（`Bearer at-…`），直接违反 `R10-F5`「声明值原样上线」
和 `R8-B-1`「connector 自己的凭据」两条契约。

**定案**：在根 `resolutions` 钉 `@modelcontextprotocol/client: 2.0.0`，并把 connectors 的
直接依赖改回 2.0.0，保证**单副本**；`dsh-mcp-client` 走同一份 2.0.0。

- 验证：connectors 71 个测试文件 / 577 条用例全绿（含 fence、header-credential、
  token-refresh 三组）；`mcp-http-redirect-fence.spec.ts` 的版本断言仍为 2.0.0。
- **代价与复查条件**：这是有意的版本钉，不是"升级漏改"。2.2.0 的安全修复不会自动进入；
  下次升级或上游要求 2.2.0 时，必须同时改 fence 与 header 契约测试，而不是只改 resolution。
  复查入口：`packages/host/connectors/src/mcp-transport-fence.ts` 与
  `tests/r10f5-header-credential.spec.ts`。

## 服务面与类型面的 0.2.1 变化（门禁暴露后逐条修）

除了三条裁决，0.2.1 还改了若干本仓直接依赖的服务/类型面；这些不是"包集 diff"能发现的，
由 `yarn check` 的包级 typecheck/test 逐条暴露：

- **`webRuntime` 服务被删除**：桌面行的 `inject` 原本同时声明 `webServer` 与 `webRuntime`
  （0.1.x 的兼容写法）。0.2.1 只提供 `webServer`，于是桌面行永远停在
  `pending (waiting for service: webRuntime)`，壳不注册、窗口不调度。已从 `inject` 删除
  `webRuntime`（现为 `webServer / appExit / settings / connection`）。这是**升级必须改的
  一行**，不改则打包版无窗口。
- **`webServer.port` 由必选变可选**：桌面行在无 Web carrier 的 headless profile boot 里
  会拿到 `undefined`。已改为 `ctx.webServer.port ?? 0`（真实桌面 profile 始终有绑定端口；
  `0` 仅保证 headless boot 的注册/调度路径是 total 的），并去掉了原先的强断言。
- **`@deepseek-ai/dsh-session-persistence-jsonl` 取消默认导出**：测试改用命名空间导入
  （`import * as SessionPersistenceJsonl`）。
- **`@deepseek-ai/dsh-agent-preset-registry` 删除 `livePresetMounts`**：改用
  `agentPresets.inspectCompositions()`（`AgentPresetInspection.id`）读取挂载集合。
- **新增 5 个 first-party peer 需要桌面直接声明**：`verify-runtime-closure` 报
  `dsh-working-directory` / `dsh-experimental-worktree` / `dsh-schedule` /
  `dsh-plugin-manager` / `dsh-experimental-translator` 缺失（它们由 0.2.1 新增的
  `dsh-tools` / `dsh-web-app` / `dsh-experimental-*` 链传递要求，但不在桌面的
  `dependencies` 里）。已按 `0.2.1-rc.2` 补进桌面依赖，closure 现为
  "320 first-party nodes closed"。
- **上游技能语料 sha 变化**：`skill-invocation-upstream-parity.spec.ts` 的冻结件
  `server/internal/skillmanifest/testdata/upstream-invocation-boolean.json` 按上游新源码
  重新生成（`UPDATE_UPSTREAM_FIXTURE=1`），不是放宽判据。
- **设置入口改由账户 launcher 承载**：0.2.1 的 `settings.launcher` 由
  `dsh-client-ui-settings-account` 的账户菜单占用，侧栏不再有独立「设置」按钮。
  客户端 E2E 先点账户 launcher（`aria-haspopup="menu"` + aria 含「账号」）再点菜单里的
  「设置」；账号页步骤复用同一路径；侧栏「设置仍在」的判据接受这条入口。
- **`app-ai-release-gate.spec.ts` 的 CI-only flake**：`whenIdle` 加宽窗口从固定 `sleep(120)`
  改为 `waitFor(handles.length >= 2)`（窗口开到新轮句柄真的发布为止；判据强度不变）。
- **`dsh-agent-preset` 可能嵌套安装**：0.2.1 的 `@deepseek-ai/dsh` 自带一份嵌套的
  `@deepseek-ai/dsh-agent-preset`，与 `desktopRequire.resolve()` 命中的提升副本不是同一
  物理路径。`real-cordis.spec.ts` 的来源判据从"以提升副本的 skillsDir 开头"改为
  "路径包含 `@deepseek-ai/dsh-agent-preset/skills/...`"——仍能咬住"技能来自该包"，
  不绑定提升位置。
- **sharp 0.35.5（0.2.1 的 `dsh-attachment-local` 精确要求）**：桌面 devDependency 与
  `mac-runtime.ts` / `verify-packaged-runtime.ts` 的 `sharp-linux-x64-0.35.5.node` /
  `sharp-darwin-arm64-0.35.5.node` 同步升到 0.35.5（`@img/sharp-libvips-*` 随之 1.3.4）。
  不升会让 electron-builder 的 pack-root 只拿到传递依赖的 0.35.5，而 afterPack 断言仍按
  0.35.3 找文件，Linux 打包直接失败（CI 实测）。
- **`channel-prepare` 测试需要注入 `runtimes` 替身**：0.2.1 的打包准备默认随包
  node/pnpm/python 运行时（真实现联网拉 ~90MiB），两条语音载荷用例只传了 `speechModel`
  替身，现补 `runtimes: runtimesStub()`（与同文件其余用例一致；生产仍走真实现）。
