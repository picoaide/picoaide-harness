# 企业 AI 平台的对外表达：同类产品调研与我们的口径

> 目的：把官网上线以来偏「产品功能清单」的表达，换成**企业视角**的表达 —— 平台要抬高的是
> **整个组织的 AI 水位线**，而不只是给个人发一个好用的工具。
>
> 调研方式：直接抓取同类产品的官网与公开报道正文（原文留档在 `temp/site-docs/research/`，
> 不入库）。**本文只写结论与可复用句式，不抄原文、不写客户名、不写域名**。

## 一、同类产品在讲什么（四类叙事）

### 1. 基础设施叙事：AI 是「能力层」，不是「项目」
最主流的一种。典型表达把企业 AI 演进切成三段：
个人尝鲜（自下而上、分散、安全盲区）→ 部门试点（项目制、重复建设、成果无法横向复制）
→ 组织基础设施（平台化、统一治理、能力复用），再往后是「AI 原生组织」。

配套的四个「层」几乎是行业共识，也是我们产品**已经具备**的四层：

| 行业说法 | 对应我们的东西 |
|---|---|
| 统一接入层（一个 Key 管理入口、统一网关调用模型） | 服务端模型网关 `/v1/*` + 模型目录；上游密钥只存服务端 |
| 统一管控层（按部门/项目归因 Token、配额与成本预警、敏感数据过滤） | 用量中心（部门/成员/模型拆账）、余额闸门与账本、权限与沙箱 |
| 能力复用层（知识库一次建设多业务共享、工作流模板化、Prompt 资产统一管理、员工离职带不走） | 能力中心（技能/智能体共享 + 审批 + 归属）、五轨记忆、应用中心 |
| 可观测层（谁调用了哪个模型、花了多少钱、结果好不好） | 审计日志（哈希链）、用量明细、服务器信息 |

**可借用的句式**：「AI 能力应该像水电煤一样随时取用，但由统一的基础设施支撑」
「新业务接入从人日降到配置」「模型切换从改代码变成改配置」「AI 成本从糊涂账变成可归因」。

### 2. 治理叙事：能安全地规模化，才叫企业级
代表产品的表达集中在四个词：**Context / Intelligence / Permissions / Efficiency**，
以及一句很值得抄的定位：*AI only works in the enterprise when answers are secure,
explainable, and permission-aware.*（AI 只有在答案安全、可解释、按权限可见时，才在企业里成立。）

它们的「企业就绪」几乎都是同一张清单：SSO/RBAC/审计日志、防篡改审计与 SIEM 对接、
按需部署（自托管/隔离网络/K8s）、数据主权（数据留在企业边界内、自带密钥、不用于训练）。
合规徽章是标配（SOC 2 / ISO 27001 / ISO 42001 / HIPAA / GDPR）—— 我们没有徽章，
**不能编**，所以改用「可验证的实现细节」替代徽章：加密算法与密文前缀、令牌存储与吊销语义、
沙箱机制与可写面、出站边界、审计哈希链、默认拒绝的 404 语义。

### 3. 落地叙事：从试点走向日常生产力
按**部门/行业**给一行「结果承诺」是通用做法（例如「业务团队自己搭 Agent」
「从试点应用走向日常生产力」「一套私有平台覆盖所有业务单元」）。
关键洞察：企业买家不看功能清单，看的是**我这个部门能不能少花时间**。

对我们的启示：能力矩阵不该按「模块名」列，而该按**员工每天都在做的事**列
（这也是本次首页改版已经采用的口径：对话与工作区 / 能力中心 / 连接器 / 定时任务 /
浏览器 / 语音 / 记忆 / 应用中心）。

### 4. 水位叙事：组织能力是可以被度量的
公开报道里已经出现非常直白的做法：把「具备中级以上 AI 能力的员工占比」当 KPI
（例如从 9% 提到 20%，并要求全员完成入门课程）。这说明企业真正想买的是
**可度量的组织能力提升**，不是并发数。

我们的产品里天然能支撑这件事的三样东西：
1. **采用面**：用量中心按部门/成员/模型拆开的调用与费用（谁在用、用在哪）；
2. **沉淀面**：能力中心的共享技能/智能体数量与采用（经验有没有变成资产）、
   应用中心的自建应用（业务自己造工具）；
3. **治理面**：审计日志与余额闸门（成本可控、行为可回溯）。

**结论**：官网上应该出现一个明确的「水位阶梯」段落 —— 让访客自己定位在第几级、
下一级需要什么、平台对应提供什么。这是本次改版新增 `#adoption` 版块的由来。

## 二、我们**不能**抄的三件事

1. **客户 Logo 墙与客户证言**：我们没有可公开的客户身份（仓库是公开仓，
   渠道与客户身份属私有仓）。用「能力清单 + 可验证实现」替代社会证明。
2. **合规徽章**：没有做过的认证不写。
3. **夸张数字**（节省 X 万小时、效率提升 N 倍）：我们没有可公开的测量口径。
   我们的替代物是**结构性事实**：一个镜像、客户端随服务端发布、密钥只在服务端、
   数据只落在部署目录 —— 这些是可以被验证的，而且比形容词更有说服力。

## 三、落到官网上的改动（本次）

1. **首屏**从「让每位员工拥有自己的 AI 操作助手」升级为「把 AI 从个人技巧，变成组织能力」——
   个人价值仍在（每位员工一个助手），但主语换成组织；
2. 新增 `#adoption`：**AI 水位四级阶梯**（个人尝鲜 / 部门试点 / 平台化复用 / 可度量的 AI 原生），
   每级写「典型特征 + 平台提供什么」，并在第三、四级强调**沉淀**与**度量**；
3. 能力矩阵保留「员工每天在做什么」的口径（对应上面的落地叙事）；
4. 管控面补充**可度量**的表达：用量按部门/成员/模型拆账 → 管理层能看到水位；
5. 安全段改用「为 IT 与安全团队准备」的框架，每条给出可验证实现；
6. 新增**按角色进入**（员工 / 管理员 / IT 运维）三张卡，让三类读者 5 秒内找到入口。

## 四、可直接复用的句式（中英）

| 中文 | 英文 |
|---|---|
| 把 AI 从个人技巧，变成组织能力 | Turn individual AI habits into organisational capability |
| 抬高整个组织的 AI 水位 | Raise the AI water line across the organisation |
| 员工的经验不再随人流失 | Know-how stops leaving with the person |
| 用完即走 → 沉淀可复用 | From one-off wins to reusable assets |
| 成本从糊涂账变成可归因 | AI spend goes from a black box to an attributable ledger |
| 接入新模型从改代码变成改配置 | Adding a model is a configuration change, not a code change |
| 能在企业里用起来的前提是安全、可解释、按权限可见 | Enterprise AI only works when it is secure, explainable and permission-aware |
