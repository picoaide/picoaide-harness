## 二、P0 三条（安全 / 资金）

### P0-1｜`browser_get_snapshot` 把连接器密码明文交回模型
- **位置**：`packages/host/browser/src/snapshot.ts:51`（`textOf()` 在无 placeholder 时落到 `el.value`）
- **链路**：`browser_fill_credentials` 写入密码 → 后续快照把 `el.value` 原样返回 → 进模型上下文与会话记录
- **触发**：装连接器 + AI 填凭据 + 密码框无 placeholder + 任意一次后续快照（模型常规操作，无需攻击者）
- **修复**（三层）：
  1. 探针内 `type=password` **不读** `el.value`（保留元素与编号，用 placeholder 或 `(password field)`）
  2. `runtime.snapshot()` 漏斗按本 tab **实际注入过的凭据值**精确擦除 → 覆盖所有调用方
  3. 出口只返回布尔（`{username, password}`），错误路径不含值
- **主控验证**：还原 `snapshot.ts` 到基线 → 新测试 **3 条红**（内容级断言）；恢复后 **16/16 绿**
- **方法论盲区**：原 `snapshot.spec.ts` 11 条只断言 `kind/selector/visible/disabled`，**从不断言 `text` 内容** —— 这正是它长期漏过去的原因。新断言是内容级的。

### P0-2｜上游负 token ⇒ 员工余额被凭空充值
- **位置**：`server/internal/serverstore/usage.go:169-184`（`costOfAt` 只钳 `cacheTokens`/`missTokens` 派生值，`promptTokens`/`completionTokens` **本体不钳**）
- **链路**：负 token → `costOfAt` 算出**负费用** → `settleUsageCostTx` 的 `delta = -(负数-0) > 0` → 记成 `refund` → `balance_money + delta`
- **关键**：账本不变量 `balance == SUM(ledger)` **仍自洽** → 事后审计看不出来
- **触发**：可控上游响应体（第三方中转 / 明文 `http://` 上游的 MITM —— 网关明确允许 http）
- **修复**：`clampTokens()` 作为**唯一计费入口**（覆盖 chat/completions/responses/messages/embedding 全路径）+ `settleUsageCostTx` 对 `targetCost < 0` / NaN / Inf 直接报错
- **主控验证**（真 PG，红→绿见 §四）

### P0-3｜余额并发透支
- **位置**：`server/internal/serverstore/balance.go:192-216`（`UPDATE users SET balance_money = balance_money + ?` **无下限钳制**、无 reserve/in-flight）
- **修复**：
  - 条件 UPDATE 加下限：`AND (balance_money + ? >= ? OR ? >= 0)`（refund 不受下限约束，避免卡住历史欠款账户回补）
  - 0 行时**区分**「未开通余额账户」（返回 nil，设计语义）与「余额不足」（`ErrInsufficientBalance` → **调用方回滚整个事务**）
  - 修掉原 `:204-206` 直接 `return nil` 让 usage 行照样落账（"记了账没扣钱"）的隐患
- **主控验证**（真 PG，红→绿见 §四）

## 七、方法论盲区反思（本轮沉淀）

1. **"测了字段存在，没测字段内容"** —— P0-1 的密码泄漏在 11 条既有测试下活了很久，因为它们只断言 `kind/selector/visible/disabled`。**安全断言必须是内容级的**。
2. **"账本自洽 ≠ 资金安全"** —— P0-2 负 token 充值后 `balance == SUM(ledger)` 仍然成立，**不变量 I1 抓不到它**。审计不能只看对账等式。
3. **"代码路径存在 ≠ 攻击者可达"** —— 复核员据此把 memory P0-1 从 P0 降到 P1（审计员抓到了 LNA 拦截的反证却放过了）。安全定级必须验证**发起方可达性**。
4. **"注释即契约，双向"** —— 它可能被证伪（memory P1-1 锁域不一致），也可能**正好否定你的结论**（memory P1-4 的折叠是明写的设计语义）。判定"数据丢失"前先读被改函数的 doc。
5. **"别处的兜底要写进定级依据"** —— 审计员常漏看不在同一函数里的守卫（如 `main.go` 启动补算把月分区竞态窗口收窄为"跨月运行"）。
6. **"矩阵里实跑与推断必须在单元格文字里区分"** —— 只用符号标记，读者会当成"全部已复现"。
7. **复核的价值在于推翻** —— 本轮复核 17 条里下调 2 条定级、收窄 1 条触发条件；如果只做"抽查+签字"，这 3 处都会原样进排期。
