## 0. 三句话结论

1. **目标版本可用**：`0.1.6-alpha.2` 已发布到 npm（`alpha` dist-tag），上游 313 个 `@deepseek-ai/*` 包中 **307 个已发布**，未发布的 6 个全是上游自己的私有包（`dsh-desktop` / `dsh-desktop-host` / `dsh-root` / `website` / `benchmarks` / `node-addon-system-workspace`），我们一个都不依赖。**会话格式仍是 v3**（两版一致）⇒ 没有 0.1.2→0.1.5 那种会话世代迁移风险，回滚只需换二进制。
2. **⚠️「按上游客户端方式、不启用本地端口」在目标版本上不成立**：上游在 rc.2 → alpha.2 之间**主动删除**了整套零端口设计，改回 loopback 端口 `19387`。见 §2。这是本次必须由产品拍板的第一个决策点。
3. 升级本身工作量可控但**面很宽**：去重后测得 **P0 阻断 9 类 / P1 功能静默失效或行为分叉 13 类 / 打包与门禁 10 类**，其中 3 条会**静默**破坏（计费口径错位、会话原文出境、MCP 传输护栏失效），另有 1 条**启动期静默**（自有插件行不再阻塞启动），必须在升级 PR 内一并修掉。

## 2. ⚠️ 前提失效：上游已放弃零端口客户端

用户目标里的「按上游的客户端方式，不启用本地端口」基于 2026-09-14 那份上游桌面端调研（`docs/planning/2026-09-14-upstream-desktop-study.md`）。该结论**对 rc.2 成立、对 alpha.2 已被上游推翻**：

| 证据 | rc.2（基线） | alpha.2（目标） |
|---|---|---|
| `apps/desktop-host/config/desktop.cordis.patch.yml` | 存在（34 行，`disabled: true` 关掉 `webserver`/`web-runtime`/`web-startup`/`client-hmr`） | **整个文件被删除** |
| `apps/desktop-host/src/wire.ts` | 存在（184 行，fd3/fd4 帧管道） | **整个文件被删除** |
| 启动参数 | 无端口 | `apps/desktop-host/src/index.ts:24` → `args: ['--no-open', '--port', '19387']` |
| 取宿主地址 | 帧管道 | `apps/desktop-host/src/index.ts:73` → `ctx.connection.authenticatedUrl('http://127.0.0.1:' + ctx.webServer.port)` |
| README 第 5 行 | “It opens **no** listening port” | “Desktop defaults to port **19387**, separate from Web's 3080” |
| `docs/architecture.md:55` | 零端口描述 | “Desktop defaults to port `19387`; profile configuration can override it.” |

alpha.2 的实际形状 = **loopback 端口 + `dsh-app://` 薄壳**（`dsh-app://app/` 只从磁盘服务 `/`、`/index.html`、`/assets/*`、`/favicon.svg`、`/manifest.webmanifest`，其余 HTTP 转发到端口，WebSocket 直连端口）。

**含义**：在目标版本上，「照搬上游」与「不启用端口」互斥。上游没有留下任何可抄的零端口实现，且它回退的动机很可能正是模块 E 实测出的那些阻塞点（信任链、WS、CSP）。

**三条路线（需拍板，见 §6-D1）**：

| 路线 | 内容 | 改动面 | 风险 |
|---|---|---|---|
| **A（推荐）** | 接受 loopback 端口，跟随上游 alpha.2 的新形态 | 0 | 放弃「不启用端口」这条诉求；仍是仅回环监听 |
| **B** | 升级 alpha.2，同时**自研**零端口承载层（自建同名同形 `webServer` 服务 + `protocol.handle` 分发） | 大（41 条路由 + 7 个 `inject` 需零改动保留；自建 Node↔Fetch 适配；重建信任链；CSP 与 5 处 loopback 闸需重做） | 高；且与上游当前方向相反，**永久自持** |
| **C** | 暂不升级，先在 rc.2 上按上游当时的零端口设计落地 | 中 | 该设计上游已删，同样永久自持；且拖延版本升级 |

模块 E 实测的零端口阻塞（若走路线 B，必须全部解决）：**5 P0 / 8 P1 / 2 P2**，其中最硬的三条：
- 关掉 `webserver` 行会让 **7 个 `inject: ['webServer']` 的插件整片静默不 apply**（桌面壳 / 登录页 / 连接器 / cron / 浏览器 / wasm 本机面 / 账号卡）；
- `dsh-auth-<hash(Host:port)>` cookie 靠 `GET /?token=` 303 换票，零端口无 authority ⇒ `write-proof.ts` fail-closed 503 ⇒ 登录/登出/SSO/更新安装/目录选择/渲染引导/cron 动作/连接器写面/wasm 发布**全部拒绝**；
- 窗口 CSP 的 `onHeadersReceived` 判据只认 `http/https/file` ⇒ `dsh-app:` 下 **CSP 整块失效**（含刚修过的 `worker-src 'self' blob:`）。
