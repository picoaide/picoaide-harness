# 上游 DSH 升级评估：0.1.1-rc.2 → 0.1.2-rc.1 / 0.1.3-alpha.1

日期：2026-09-05
状态：仅评估，未实施。本仓库当前 pin 仍为 `dsh-v0.1.1-rc.2`。

## 1. 结论先行

- 上游当前最新 **git** 版本为 `dsh-v0.1.3-alpha.1`（2026-09-04，即 origin/master HEAD），
  但 **npm 上未发布**（npm dist-tags：latest=next=`0.1.2-rc.1`，alpha=`0.1.2-alpha.5`）。
- 本仓库 desktop 客户端从 **npm** 安装 `@deepseek-ai/dsh*`（100+ 个精确版本依赖），
  因此**唯一可升级的目标 = `0.1.2-rc.1`**（git tag 与 npm 一致）。`0.1.3-alpha.1` 会造成
  submodule pin（git）与 npm 依赖脱节，不可作为 desktop 升级目标，只能作源码参考。
- 0.1.2 是一次大版本（+38.1 万 / −16.1 万行），**核心是会话格式迁移链**，本仓库多个插件
  直接消费 `@deepseek-ai/dsh-session*` 包，是最大风险面。
- 建议：**暂不升级**。等上游发布 `dsh-v0.1.2` 正式 tag 或 `0.1.2-rc.2` 再升；若上游较长时间无
  正式版且内部需要新特性，再按下文路径升 `0.1.2-rc.1`。

## 4. 本仓库耦合点（升级时需改动/验证处）

### 4.1 同步位置（必须动）

1. **submodule pin**：`deepseek-harness/` 指向新 commit（与 npm 版本一致的 tag）。
2. **desktop 依赖**：`packages/host/desktop/package.json` 中 100+ 处
   `@deepseek-ai/dsh*` 精确版本 `0.1.1-rc.2` → `0.1.2-rc.1`（含 `@deepseek-ai/dsh-session*`
   等全部上游包；我们消费的上游包清单见 4.2）。
3. **patches 适配**（root `resolutions` patch-on-package）：
   | patch | 规模 | 上游 0.1.2 改动 |
   |---|---|---|
   | dsh-client-ui-brand-official@0.1.1-rc.2 | 20 行 | **0 提交，未动** → patch 大概率可直接沿用 |
   | dsh-client-ui-directory-picker-browse@0.1.1-rc.2 | 166 行 | host 侧 12 提交；client 侧 0 → 需核对 |
   | dsh-llm-deepseek@0.1.1-rc.2 | 9 行 | 37 提交 → **重新适配概率高** |
   | dsh-sandbox-windows-acl@0.1.1-rc.2 | 12 行 | 34 提交 → 需核对 |
   | app-builder-lib@26.15.3 | — | 与上游无关（打包器），不受影响 |
4. **yarn.lock**：重生成（注意 YARN_GLOBAL_FOLDER 沙箱重定向坑）。

### 4.2 我们直接消费的上游包（摘要）

- `@deepseek-ai/dsh-session`：**import 了 `surface` 与 `types` 子路径**，使用
  `AgentCancelCause`、`SessionHeader`、`SessionId`、`SessionEvent`、`JsonValue` 等类型
  （dsh-cron / dsh-connectors / loop-notify / skill-telemetry 等）。
- `@deepseek-ai/dsh-session-reference/remote`、`@deepseek-ai/dsh-session-projection/types`。
- 上游 0.1.1-rc.2..0.1.2-rc.1 中 session 相关目录（packages/session 等）**192 个提交**。
- 另经 client 插件（dsh-client-*）间接消费大量 UI/sidebar/slots 面（品牌、文件上传、附件等）。

### 4.3 风险排序

1. **P0：会话格式迁移**。0.1.2 迁移 v0→v1→v2 且 0.1.3-alpha.1 仍未收敛；我们直接 import
   dsh-session 的 surface/types 子路径类型，任何子路径/类型/语义变更都会破坏
   dsh-cron、dsh-connectors、loop-notify、skill-telemetry 的 typecheck 与运行行为。
   另外历史会话数据格式兼容（用户本地 `.dsh-home` 数据）由上游迁移逻辑接管，需真机验证。
2. **P1：patch 重适配**。llm-deepseek（37 提交）与 sandbox-windows-acl（34 提交）上游改动
   大，patch 冲突/失效概率高；这两处 patch 承载的是我们桌面端必要修复（如 LLM 配置、
   Windows ACL），失效会直接破坏 Windows 打包。
3. **P1：插件 API 漂移**。客户端插件体系（slots 注入、sidebar/settings 扩展点）在 0.1.2
   有大量 UI 重构（textarea、i18n 门槛、plugin list），`ctx.slots` 注册面可能变动。
4. **P2：行为回归面**。7633 文件的大版本，需全量门禁 + 真实 Electron E2E 验证
   （e2e:client 13 断言）+ 桌面交互冒烟。
5. **P2：0.1.3-alpha.1 不可作为 desktop 目标**（npm 无包），源码 pin 与 npm 依赖会脱节。

## 5. 升级路径（若执行）

按 AGENTS.md：**pin 更新与 desktop 行为变更分开提交**；不编辑 submodule 内文件。

1. 预检：submodule 内 `git diff 0.1.1-rc.2..0.1.2-rc.1` 对我们 patch 涉及的 4 个包做
   `patch --dry-run` 评估；对 dsh-session 子路径做 API 差异扫描。
2. 提交 A：仅 submodule pin → `0.1.2-rc.1`（gitlink commit）。
3. 提交 B：desktop package.json 版本号批量替换 + patches 重新生成 + yarn.lock 重生成。
4. 验证：`corepack yarn check`（build+typecheck+test）→ `e2e:client` →
   真实服务冒烟（登录/会话历史/图片上传/插件面板）。
5. 双环境部署按既有流程（v2.x 服务端与上游 dsh 无关，本项目自身版本号另评）。

## 6. 插件兼容性核对（v0.1.2-rc.1，2026-09-05 补充）

### 6.3 第三方/用户安装的插件：**不保证兼容，需逐插件检查**

- 上游官方在 rc.1 release notes 明示 0.1.2 为破坏性版本，并推荐[oh-my-dsh/dsh-plugin-upgrade-skill](https://github.com/oh-my-dsh/dsh-plugin-upgrade-skill)给插件作者适配。
- 判据（任一命中即大概率不兼容）：import 了 `dsh-client-runtime`、`dsh-host-apiproxy`、任何上游包的 `./invariant`；访问 `Session.events`/`ctx.sessions.get(...).events`；深度依赖 ui-conversation 内部模块（src 拆包）；peerDependencies 或 resolptions 锁定 `0.1.1-rc.2` 精确版本（npm 若该版本被 unpublish 则直接断供）。
- 我们的桌面 profile 未内置第三方插件，故"安装的插件"需按用户实际安装情况逐个体检。
