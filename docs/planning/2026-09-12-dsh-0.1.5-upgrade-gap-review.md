## 1. P0

### P0-1 非图片附件上传在打包版必然失败：CSP `script-src` 缺 `blob:`（**真机确认**，见 §7）

- 我们的 CSP：`packages/host/desktop/src/electron-runtime.ts:85-92`，`:87` 为
  `script-src 'self' 'unsafe-inline' 'unsafe-eval'`（无 `blob:`）；`:86` `default-src` 里的 `blob:` 永远轮不到——
  CSP3 的 `worker-src` 回退链是 `worker-src → child-src → script-src → default-src`，`script-src` 一旦声明就截断。
- 上游 0.1.5 新增的 `@deepseek-ai/dsh-client-file-upload` 在生产路径上只用 Blob-URL Worker：
  `packages/client/file-upload/src/client/runtime.ts:169-171`（无 `__DSH_FILE_UPLOAD__` hook → `workerTransport()`）、
  `:249-256`（`new Worker(URL.createObjectURL(new Blob([...])))`）、`:258`（失败即 `background upload worker failed`）。
  唯一设置该 hook 的 `dsh-experimental-webworker-runtime` **不在我们的依赖树里**，所以我们 100% 走 Worker。
- 调用方：`packages/client/ui-conversation/src/client/service.ts:366`（附件 `File`）、`:239-248`
  （未 ready 直接抛 `conversation.sendSession: one or more files have not finished uploading`）→ **卡住整条消息发送**。
  图片走 base64（`:260/:454/:575`）不受影响 ⇒ 症状是"图片能发、PDF/zip/txt 不能发"。
- 复现（打包用 Electron 43.4.0 + 我们的 CSP 原文，微实验）：
  `Creating a worker from 'blob:…' violates … "script-src 'self' 'unsafe-inline' 'unsafe-eval'". Note that 'worker-src' was not explicitly set, so 'script-src' is used as a fallback. The action has been blocked.`
- 同源根因（P1 级）：新右栏 PDF 预览 `dsh-client-ui-sidebar-documentpreview/lib/client.js:26433` 同样 `new Worker(blob:…)`；
  `:2215-2232` 把 HTML 预览的 `script[src]`/`link[href]` 重写成 `blob:` 后塞进 `sandbox="allow-scripts"` 的 blob iframe（`:2389`，继承父 CSP）→ 含相对外部资源的 HTML 预览被拦。
- 门禁为何绿：`e2e:client` 13 项从不创建会话、从不加附件；`tests/electron-runtime.spec.ts:1021-1053` 只把这条 `script-src` **字符串**钉死，从不做 Worker 能力验证——"收紧会被发现，本身致坏永远不会被发现"。
- 修法：CSP 增加显式 `worker-src 'self' blob:`（或 `child-src blob:`）；补一条"打包版附加 PDF 并发送"的真机断言。

- `packages/host/cron/src/client/panel-mount.tsx:21` 的挂载选择器**含** `dshDesktopConversationSurface`，

### P1-3 每次启动都会 spawn 第二个 Electron 进程（`openBrowser` 默认 true，被我们的 patch 吃掉）

- `packages/host/desktop/cordis.patch.yml:31-35` 对 `web-runtime` 行做**整段 config 替换**（只写 printUrl/surfaceContext/trustedHosts），
  丢掉了上游 rc2 行里的 `openBrowser: !!js ctx.webStartup.openBrowser`（`bundle/web-app/cordis.patch.yml:154-161`）；
  schema 默认 `true`（`bundle/web-app/src/index.ts:61`）→ `handoffBrowser`（`:229`）成立 → `:275` 调 `openBrowser`。
- `openBrowser` 用 `spawn(process.execPath, ['--input-type=module','--eval',…])`（`:174-180`）——在 Electron 宿主里就是 GUI 二进制。
- **实测**（打包产物 + Xvfb，捕获日志）：启动日志出现
  `dsh web: opening the default browser; pass --no-open to disable` 与
  `web-app: could not open the default browser because [FATAL: Running as root without --no-sandbox is not supported]; use the dsh web URL printed at startup`。
  普通用户机器上的表现＝第二个应用进程撞单实例锁后秒退（浏览器交接静默不发生），即每次启动多一个无用进程。
- 注：该 key 在 rc1 就存在，属**存量不一致**；但本次升级的 patch 语义检查正好该一并处置。
- 修法：`cordis.patch.yml` 的 `web-runtime` config 显式加 `openBrowser: false`（或 `!!js false`）。

## 3. 数据面（会话格式 v0→v3 / flock / 备份回滚）

### P0-4 备份口径写的是**已废弃**的投影缓存路径，照文档恢复会丢当前投影缓存
