# 递归自进化（SI）开发循环：把「大模型 RL 那一套」翻译成「我们自己的工具」

- 状态：**规划，未实施**（本文只定义结构与落地步骤，不改任何代码/CI/仓库设置）
- 起因：2026-09-25 讨论「能不能像大模型 RL 那样自我进化 —— 自己提需求 → 评审需求 → 代码落地 →
  项目实现 → 验证 → 用户视角评估 → 调研竞品 → 再提需求」
- 范围：**本仓（PicoAide Harness 桌面产品）的开发流程本身**，不是产品里的某个功能
- 相邻既有文档（先读它们，本文不重复其内容）：
  - `docs/playbooks/multi-agent-regression-audit.md` —— 多子代理对抗审计的话术与停止条件
  - `docs/decisions/2026-09-25-gate-definition-authority.md` —— 判据的「定义权」现状与未收口项
  - `docs/AUDIT-2026-09-23-FULL.md` —— R1–R16 各轮审计记录总账
  - `AGENTS.md` 铁律 0 —— 渠道/客户身份永不进本仓

## 0. 一句话结论

**RL 的「权重」在我们这里不存在，等价物是「仓库状态 × 判据集合 × 记忆」这三样一起。**
所以视角转换不是「把模型换成代理」，而是：

> 把「优化一个可微函数」换成「优化一组可执行的工件（代码 + 判据 + 记忆 + 结构），
> 而唯一的梯度来源是**带证据的提交**，唯一的奖励是**可被证伪的判据 + 人类的验收**」。

由此推出本次要补的三件事（现状里**没有**的环）：

1. **需求生成与评审**（RL 的「探索 + 任务分布」）：现在新需求只从人嘴里出现，没有池子、没有评分、没有取舍留痕。
2. **用户视角评估**（RL 的「held-out eval」）：现在只有技术断言（门禁/探针/E2E），没有「员工拿到手能不能用、愿不愿意用」的判据。
3. **固化环的机检**（RL 的「权重更新」）：现在守卫是**逐个手工加**的，没有「每条 P0/P1 修完必须变成判据、否则不许关闭」的强制。

## 1. 参照系：大模型 RL / 自进化的自动化方案由哪些部件组成

先把自己这边讲清楚，再谈映射（这是本次提问的第一半）。

| # | 部件 | 在 RL 里的作用 | 工程上的形态 |
|---|---|---|---|
| 1 | 策略 π | 产生动作分布 | 被训练的权重（推理时冻结） |
| 2 | 环境 / 任务分布 | 提供状态与反馈 | runner + 沙箱 + 任务集 |
| 3 | Rollout | 采样轨迹 | 推理服务批量生成 |
| 4 | 奖励 / 验证器 | 给轨迹打分 | RM 模型、规则验证器（RLVR）、单元测试 |
| 5 | 优势估计 / 信用分配 | 判断哪一步带来收益 | GAE、过程奖励模型 |
| 6 | 策略更新 | 改权重 | 训练器 + 梯度步 |
| 7 | KL / trust region | 防跑偏、防崩溃 | KL 惩罚、ratio 裁剪 |
| 8 | 经验回放 / 记忆 | 复用样本 | replay buffer |
| 9 | 课程学习 | 由易到难 | 任务难度调度 |
| 10 | 离线评测 / 基准 | 防过拟合与退化 | held-out eval set |
| 11 | 探索 | 发现新策略 | 温度、熵奖励、自博弈 |
| 12 | Reward hacking 防护 | 防钻空子 | 奖励审计、对抗验证器、留出人类抽检 |

**这套东西之所以能自动跑**，靠三个前提：梯度自动可微、奖励密集可算、**奖励函数在策略之外**
（策略改不动自己的裁判）。第 2/3 条在我们这里全都不成立 —— 这就是视角必须换的地方。

## 2. 视角转换：同一套部件在「我们自己的工具」里是什么

### 2.1 逐部件映射

|---|---|---|---|---|

| 2 | 环境 | 仓库 + CI（5 必需检查）+ 测试环境三栈 + 真机 + 用户 | `.github/workflows/ci.yml`、`temp/deploy-281/verify-stack.sh` | 强 |

### 2.2 四条结构性错位（照搬 RL 会直接坏掉的地方）

1. **可微 vs 不可微**：RL 的梯度自动、密集；我们的"梯度"是**别人写的补丁**，稀疏且单步昂贵。
   ⇒ 必须把信用分配**显式外化**（证据三件套 + 红绿矩阵），不能指望"跑多了自然学会"。
2. **奖励密集 vs 奖励延迟**：RL 每一步都有分；我们的真实奖励（员工愿不愿意用）**几周后才出现**。
   ⇒ 只能先用**代理奖励**（门禁绿、变异杀伤率、真机探针通过、部署后实拉一致），
   而代理奖励一定被优化 —— 所以第 4 条错位是它的必需品。
3. **裁判在策略之外 vs 裁判可被策略改写**：RL 里策略改不了奖励函数；我们这里
   **PR 可以改 workflow、可以改守卫本身**（`gate-definition-authority.md` §1 已逐字论证：
   `pull_request` 跑的是 PR merge commit 里的 workflow ⇒「判据的定义版本 = 被审版本」）。
   ⇒ SI 循环必须有**独立的判据定义权**，否则整个循环退化成"自己给自己发奖"。
4. **泛化在输入分布 vs 泛化在未来需求**：模型只需对输入分布泛化；工具还要对**尚未提出的需求**泛化。
   ⇒ 需要 `backlog`/`roadmap` 层与需求评审 gate（这是纯 RL 类比里没有的部件）。

### 2.3 转换三步法（回答「怎么从大模型视角变成我们自己工具的视角」）

1. **问"被优化的对象是什么"**：不是权重，是「代码 + 判据 + 记忆 + 结构」四件套。
   → 每次改动都要问：它改的是代码，还是改判据，还是改记忆？（三者的评审强度不同，见 §6.6）
2. **问"梯度从哪来"**：不是反向传播，是**证据**。没有「文件:行号 + 引入提交 + 可复跑命令」的
   变更不算梯度，只是噪声。
3. **问"谁定义奖励"**：不是固定的 RM，是**可以被修改的守卫集合**。所以每次"加/改判据"
   都必须走独立审批（人），这是 SI 循环的**唯一硬闸门**。

一句话：**RL 把经验压进权重，我们把经验压进判据。** 判据是这条链路里唯一不会随会话丢失的东西。

   └──────────┘             └──────────┘             └──────────┘

| 环 | 现在靠什么 | 缺口 |

## 4. 五环状态机（每环的输入 / 动作 / 产物 / 判据 / 闸门）

### ① 感知（Signals）—— 只读、可重复、零副作用

- **输入**：CI 失败历史、审计台账未闭环项、`memory` 的 key 待办、`dtodo` 到期项、
  依赖与上游 pin 巡检、真机/客户现场（会话包、截图、日志）、竞品与市场信息、用户原话。
- **动作**：归一化成 `signal` 条目（来源 / 时间 / 证据路径 / 影响面 / 是否可复现）。
- **产物**：`temp/si/<round>/signals.jsonl`（原始，gitignored）；进仓的只有**结论**。
- **判据**：每条 signal 必须有**可复跑的证据指针**（命令、提交、会话 id、文件路径）；
  没有证据的进 `unverified` 区，不得直接进需求池。
- **闸门**：只读。**禁止在这一环改任何被跟踪文件。**

### ② 判定（Judgement）—— 需求池 + 评审

- **输入**：`signals.jsonl` + 既有 backlog 未决项。
- **动作**：
  1. 去重（同一根因合并，保留最强证据）；
  2. 打分（六维，见 §6.2）；
  3. 写**验收判据草案**（这一条最容易被跳过，也是"需求能不能落地"的分水岭）；
  4. 人拍：`accept / defer / reject / needs-evidence`。
- **产物**：`docs/si/backlog.json`（单一真源）+ `docs/si/rounds/<date>.md`（评审记录）。
- **判据**：`accepted` 且 `priority ∈ {P0,P1}` 的条目**必须**有非空 `acceptance[]`，
  且每条 acceptance 能被写成"某命令跑出某结果"（否则退回 `needs-evidence`）。
- **闸门**：**人**。代理可以打分、可以提议，但不能把条目改成 `accepted`。

### ③ 行动（Act）—— 落地

- **输入**：`accepted` 条目。
- **动作**：泳道切分（按包 × 职责，单分片 diff ≤1500 行）→ 实现 → 自测。
- **产物**：分支 + PR（草稿即可）+ `docs/decisions/*`（若有长期约束）。
- **判据**：`yarn check` 全绿 + 新增/改动的判据有**变异验证**（回退实现必须变红）。
- **闸门**：**禁止自合并**；PR 必须留人审；判据面（`.github/**`、`scripts/**`、`patches/**`、
  `yarn.lock`）应单独要求审批 —— `.github/CODEOWNERS` 已就位但**当前是占位团队、平台侧不生效**，
  见 `gate-definition-authority.md` §4 与本文 D7。

### ④ 校验（Verify）—— 三层，缺一层都算没验

| 层 | 跑什么 | 判据 |
|---|---|---|
| L1 单测/门禁 | `yarn check`、包级 `check`、Go `go test ./... -count=1 -p 2 -timeout 1800s` | 全绿 + 变异红 |
| L2 真机/产物 | `e2e:client`、`probe:*`、`package-dir.mjs` 后跑 afterPack 清单、部署后**从域名实拉**（AppImage sha256 对 manifest、`app.asar` 的 `build/channel.json` 核对 `home_dir`） | 逐字一致 |
| L3 **用户视角** | 见 §5-B2（本环新增） | 任务完成率 / 无阻断 / 文案可懂 |

- **闸门**：L3 未过时，需求状态只能到 `verified-technical`，不能到 `done`。

### ⑤ 固化（Consolidate）—— SI 循环与"审计循环"的唯一区别

- **动作**（每条 P0/P1 关闭时**逐条**执行）：
  1. **判据**：把根因写成一条守卫或回归用例（能被打坏才算）；
  2. **记忆**：`memory` 的 `key`（长期约定）+ `daily/project`（本轮进展）；
  3. **结构**：`normify` 结构库同步（改了模块形状时）；
  4. **文档**：`docs/decisions`（长期约束）或 `playbooks`（可复用话术）；
  5. **豁免登记**：确实无法落判据的（如一次性运维动作），写进 `waivers[]` 并给出理由。
- **产物**：`docs/si/rounds/<date>.md` 的「固化清单」段 + 上表的四类落点。
- **判据**：`node scripts/si/check-consolidation.mjs --round <id>` —— 本轮 `closed` 的 P0/P1
  逐条必须有 `{guard | test | waiver}`，缺一即 **EXIT=1**（这是把"记忆"变成"权重"的那一步）。
- **闸门**：无人值守可跑（只读校验）。

## 6. 实现方案

### 6.1 目录与"什么进仓、什么不进仓"

| 内容 | 位置 | 进仓？ | 理由 |
|---|---|---|---|
| 需求池（单一真源） | `docs/si/backlog.json` | ✅ | 评审要留痕，且要被机检 |
| 每轮评审/验收记录 | `docs/si/rounds/<date>-r<N>.md` | ✅ | 与 `docs/AUDIT-*` 同性质 |
| 度量与口径 | `docs/si/metrics.md` | ✅ | 数字必须可复核 |
| 校验脚本 | `scripts/si/*.mjs` | ✅ | 判据面，受 CODEOWNERS 保护 |
| 原始信号、探针、日志、竞品原文 | `temp/si/<round>/` | ❌（gitignored） | 公开仓纪律 + 体积 |
| 长期约束 | `docs/decisions/*` | ✅ | 既有惯例 |
| 长期事实 | `memory` 的 `key` 轨 | — | 跨会话不失忆 |

**注意**：`docs/si/**` **不在** `check-doc-claims.mjs` 的记录面豁免名单里
（豁免的是 `docs/planning|decisions|releases`、`docs/AUDIT-*`、带日期文件名）。
若要让数字型表述（如"保留 3 个版本"）不被误判，三选一：
把 SI 记录放 `docs/planning/`、给该目录加豁免登记、或**不写数字型 claim**。
建议先选第三种（SI 文档里不抄真源数字）。

### 6.2 需求条目的数据结构（草案）

```jsonc
{
  "id": "SI-2026-09-25-001",
  "title": "一句话（用户能懂，不写实现）",
  "provenance": {                    // 必填：没有来源的需求不得进池
    "kind": "user | audit | incident | competitive | dependency | eval",
    "evidence": ["<文件:行号>", "<提交 sha>", "<会话 id>", "<链接 + 抓取日期>"]
  },
  "problem": "现在会发生什么坏事（可观测）",
  "acceptance": ["可跑出红/绿的判据 1", "..."],   // accepted ∧ P0|P1 时非空
  "score": { "value": 1-5, "risk": 1-5, "cost": 1-5, "verifiability": 1-5,
             "reversibility": 1-5, "strategic": 1-5 },
  "priority": "P0 | P1 | P2 | P3",
  "state": "signal | needs-evidence | accepted | deferred | rejected | in-progress | verified-technical | done",
  "consolidation": { "guard": "scripts/check-*.mjs#rule", "test": "path.spec.ts",
                     "memory": "key:...", "waiver": null },
  "outcome": { "checked_at": null, "reverted": null, "in_use": null }
}
```

打分只用于**排序与取舍留痕**，不自动决定优先级（优先级由人拍）。

### 6.3 脚本与命令（新增四个，全部可 `--selftest`）

| 脚本 | 作用 | 判据 | 退出码 |
|---|---|---|---|
| `scripts/si/signals.mjs` | 只读聚合信号 | 有输出且每条带证据指针 | 0/2 |
| `scripts/si/check-backlog.mjs` | backlog 结构与状态机校验 | 3 个坏夹具必红 | 0/1/2 |
| `scripts/si/check-consolidation.mjs` | 固化率强制 | 缺 `guard` / `test` / `waiver` 任一即红 | 0/1 |
| `scripts/si/metrics.mjs` | 生成度量 | 口径可复算（与文件头声明一致） | 0/1 |

全部按本仓惯例：**通过行必须与覆盖面一致**（`check-doc-claims.mjs` 的教训）、
**不得用一条环境变量把红翻绿**（WASM 门禁 `BUDGET=999` 的教训）、
**豁免必须显式登记**（登记制，不是"没查到就算过"）。

### 6.4 调度与角色：用哪个 DSH 原语做哪一环

| 环 | 原语 | 说明 |
|---|---|---|
| ① 感知 | `cron` / GitHub `schedule` | 定时只读体检；产物落 `temp/` |
| ② 判定 | **人 + 普通会话** | 评审不接受无人值守（这是唯一的价值闸门） |
| ③ 行动 | `subagent` / `workflow` | 扇出泳道；单分片 ≤1500 行 diff |
| ④ 校验 | `subagent`（**新代理**）+ 脚本 | 对抗复核必须换代理（playbook §3） |
| ⑤ 固化 | `goal`（同会话多轮）/ 手动 | 收口动作有明确完成条件 |
| 整轮迭代 | `ralph` | 仅当人明确要求"fresh-agent 迭代"时使用 |

**不要**用 `ralph` 或 `goal` 去跑"感知→判定"——判定必须有人；也**不要**让同一个代理
既实现又验收（本仓已有"修复引入新回归"的实例：R7 抓到 R6 修复的副作用）。

### 6.5 预算与停止条件（防止无限自嗨）

- 单轮预算：子代理 ≤8；墙钟 ≤1 个工作日；改动面 ≤1500 行 diff/分片；不改判据面的 PR 不超过 1 个。
- 停止条件（三条同时满足才算收敛）：
  1. 一整轮 **0 个 P2 及以上**（沿用 playbook 的收敛口径）；
  2. **固化率 100%**（本轮 P0/P1 全部有 `guard|test|waiver`）；
  3. backlog 里 `accepted` 的 P0 清零，或剩余项被显式 `deferred` 并写明原因。
- 反指标（出现即暂停循环）：waiver 占比 >20%、代理奖励（绿灯率）上升但 L3 用户视角通过率下降、
  同一根因连续两轮复发。

### 6.6 防"假绿"/防 reward hacking（本仓已登记 8 类假绿形态：恒真断言、只钉字符串不钉能力、
各钉自己的字面量、存在性断言、白名单滥用、mock 掩盖契约、判据未绑 HEAD、文档内漂移 ——
清单在 `temp/wasm-client-only/AUDIT-CHARTER.md`，SI 必须继承）

1. **变异验证是硬通货**：新增/改动判据必须能被打坏，打不坏的一律记 P3 缺口。
2. **对拍上一版只允许收紧**：`UNEXPLAINED` 必须为 0；任何"上一版拒绝、当前接受"逐条列出。
3. **判据定义权独立**（未收口，见 `gate-definition-authority.md` §3）：SI 循环**自己不能改裁判**。
4. **不许用 env 翻绿**：上限类判据只能收紧，非法取值 fail-loud。
5. **存在性断言不算判据**：要断言行为/归属/可见性（本仓两次因此漏 P0）。
6. **公开仓纪律（铁律 0）**：SI 产出的任何文件与**提交信息**都要过
   `node scripts/check-no-real-domains.mjs`；竞品/客户名只进 `temp/`，进仓用占位符与角色化表述。
7. **不自合并、不自打 tag、不自动部署生产**：这三件事永远是人。

### 6.7 与现有资产的关系（尽量复用，不另起炉灶）

- **不重造审计循环**：③④两环直接用 `docs/playbooks/multi-agent-regression-audit.md` 的话术与参数。
- **不重造部署验证**：L2 直接用 `temp/deploy-281/{fetch-channel.sh,verify-stack.sh,verify-mac-notarized.sh}`。
- **不重造结构记忆**：⑤固化直接写 `normify` 结构库与 `memory` key 轨。
- **不重造门禁**：新脚本进 `scripts/check-workspaces.mjs` 的既有编排（含 `--changed` 快速通道）。

## 7. 度量（先基线，后目标）

| 指标 | 定义 | 现状（待 A5 量化） | 目标 |
|---|---|---|---|
| 固化率 | 有 `guard\|test\|waiver` 的关闭项 / 关闭的 P0+P1 | 未知（R16 回填可知） | ≥95% |
| 假绿率 | 变异杀不死的断言 / 新增断言 | playbook 实测抓到 5 次 | ≤5% |
| 复发率 | 同根因再次出现的发现数 / 总发现数 | 未知 | 逐季下降 |
| 探索供给率 | 来自 `competitive/incident/eval` 的新需求 / 总新需求 | 接近 0 | ≥30% |
| 需求命中率 | `done` 后 30 天未被回退且仍在使用 | 未测 | ≥80% |
| 周期 | 从 `accepted` 到 `done` 的中位天数 | 未测 | 逐季下降 |

**警告**：前两行是**代理奖励**（可被优化），必须与最后两行（真实奖励）一起看。

## 10. 本文不做什么（边界）

- 不改任何 CI/仓库设置（D7 需人工执行）；
- 不新建并行流程与台账（复用 `docs/AUDIT-*`、`playbook`、`normify`、`memory`）；
- 不承诺"全自动自我进化"：②判定与发布永远是人的；
- 不把 SI 循环本身当成产品功能（这是**开发流程**，不是客户端能力）。
