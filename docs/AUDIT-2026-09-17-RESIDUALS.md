| 代理部署下出站目标由代理解析（R6） | 全部出站共有的环境属性，不是本端点特有；本地已做连接期 IP 复检（`netguard`），代理侧无法约束。 |

| 口令擦除只覆盖字面变体 | `redactCredential` 按已知口令的原样/大小写/base64/URL 编码擦除；目录服务把口令做引号包裹、转义、分段或 UTF-16 等变换后回显时仍可能落明文。改成"对端错误文本一律不进日志"会牺牲排障能力，属产品取舍（已记在 §四）。 |
| 基线既有、本次区间未引入的同类问题 | 按"基线锚定"原则不修，避免把审计区间无限扩大（台账 `pre-existing` 行）。 |

## 四、CodeQL 处置口径

v2.7.5 前仓库面板有 10 条未关闭告警，现在**面板 0 条未关闭**：

- **关掉 6 条**：`js/identity-replacement`（探针里的恒等替换）、`js/incomplete-multi-character-sanitization` ×2
  与 `js/incomplete-url-substring-sanitization`（测试里的字符串剥离/子串断言，改成逐段扫描与
  结构化断言）、`go/clear-text-logging`（日志不再打印错误对象本身，且对端回显的口令被擦除）、
  `go/request-forgery`（OIDC 探针改为复用运行期同一出站 client：≤5 跳、逐跳连接期地址复检）。
- **按"仅用于测试"关闭 2 条**：`js/request-forgery`（connectors 并发用例里转发到本机假上游）、
  `js/unvalidated-dynamic-method-call`（真机探针 harness 的静态页分发，调用前有类型守卫）。
  两者都不进产物。
- **按误报关闭 2 条**：`js/bad-code-sanitization`（`eval-policy.ts` / `runtime.ts`）——命中点的
  唯一插值是模块常量经 `JSON.stringify` 编码；且"内置浏览器执行 AI 编写的脚本"是**产品既定
  能力**（2026-09-08 定案，不当作安全边界）。同规则同形态的既有告警早已按误报关闭。

两条要认账的边界（独立复核指出，均已记录在案、不作为"已消除"）：

1. **`go/request-forgery` 这一类是"接受风险"而非"消灭了形态"**：独立复核用本地 CodeQL CLI
   （2.26.2）在同一棵树上复跑，仍会在 OIDC 探针这一行命中（GitHub 侧用 2.27.0 且已判 fixed）。
   命中项的本质是"管理端可以指定任意 https 目标"这一既有设计：admin-only 接口 +
   `validateIssuerURL` 先校验 + 出站逐跳连接期复检 + 私网按企业自建 IdP 需要放行。
   与已关闭的 #64 同一口径；若后续分析再次报出，按本条处置。
2. **`go/clear-text-logging` 的"不再命中"含数据流模型成分**：真实保障是"不打印错误对象 +
   擦除已知口令形态"这一层语义；擦除按口令的**字面变体**（原样/大小写/base64/URL 编码）进行，
   对端若把口令做引号包裹、转义、分段或 UTF-16 等变换后回显，日志仍可能落明文。更彻底的口径
   （对端错误文本一律不进日志，只记结构化错误码与长度）会牺牲排障能力，本轮未采用——
   见"明确接受不修的残留"。

另外，为消除"改写正则"带来的隐性判别力退化，两个测试助手（`stripTagBlock` /
`stripHtmlComments` / `stripBlock`）已把"未闭合标记"的语义从"其后全部视为块内"改成
**直接抛错**：畸形输入会让断言响亮失败，而不是安静地少扫一段。
