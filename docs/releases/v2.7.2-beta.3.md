# v2.7.2-beta.3（2026-09-12）

> 一句话：修 **beta.2 之后仍存在的三处工具面故障**（文件搜索 `glob`/`grep`、网页抓取
> `web_fetch`、AI 浏览器点击与截图），并带上服务端安全审计修复。**测试环境必须升级；
> 客户端必须重装本版**。

## 一、`glob` / `grep` 在**打包版客户端**上 100% 失败（全平台）

- **现象**：桌面端做文件搜索一律失败，报
  `… subprocess failed before reporting an outcome (ripgrep provider failure)`
  （beta.2 已修掉同一句话背后的另一条链——命令执行的 runner 环境——但文件搜索是**另一个独立缺陷**）。
- **影响**：Windows / Linux / macOS 的打包版都受影响，只在开发态（非打包）不出现。
- **根因**：搜索用的 ripgrep 二进制路径由依赖包 `require.resolve` 给出，打包后该路径落在
  `resources/app.asar` **内部**；asar 是一个文件不是目录，原生二进制无法从里面启动。
  同一个二进制在 `app.asar.unpacked/` 下是一份真实文件（打包配置已解包），因此只要把路径指过去即可。
- **修复**：新增补丁在路径解析出口把归档内部路径重写到 `.asar.unpacked` 兄弟路径（仅当它存在）。
  非打包环境原样返回，行为不变。守卫单测在打包产物布局上做端到端核对。

## 二、`web_fetch` 对**任何**网址都失败（本机代理 fake-IP 环境）

- **现象**：`web_fetch` 全部返回
  `URL hostname "…" resolves to a non-public IP address`。实测 `github.com`、`baidu.com`、
  服务端 API 域名全部被拒。
- **影响**：开了本地代理 **fake-IP** 模式（常见代理客户端默认开启）的机器上，网页抓取工具
  完全不可用；不开 fake-IP 的机器不受影响。
- **根因**：客户端抓取器带一层"解析地址后校验是否公网"的防护，而 fake-IP 会把所有域名解析到
  `198.18.0.0/15`（RFC 2544 保留段）。保留段被判为非公网 → 一律拒绝。
- **修复**：按产品决策，**客户端 `web_fetch` 不再拦截目标地址**——请求由本机用户与 AI 在本机
  发起，地址护栏在桌面场景没有收益，却使代理用户完全不可用。代理路由与出网链路本身未改动。

## 三、AI 浏览器：点击"假成功"、截图不可用

- **现象**：`browser_click` 返回成功但**零效果**（链接不跳转、提交按钮不提交、勾选框不动），
  `browser_screenshot` 报 `Current display surface not available for capture`；
  而 `fill_form` / `select` / `upload_file` 正常。
- **根因**：AI 浏览器窗口按设计**创建后保持隐藏**（AI 在后台操作，不弹窗打扰）。隐藏窗口没有
  渲染表面：合成输入事件协议层接受但页面收不到（于是"假成功"），逐帧截图也拿不到画面。
  表单类工具走页面对象路径，所以一直是真的生效。
- **修复**：
  - 点击：窗口能接收输入时用真实合成输入（原行为）；接收不到时在页面对象层完成完整事件序列
    （含链接跳转、勾选、表单提交的激活行为），并把实际走的那条路径写进操作日志；点击位置没有
    元素时报"未找到"并记为失败，**不再假成功**。
  - 截图：逐帧截图不可用时改用渲染器侧合成帧，并按原有上限等比缩放；两条路都失败时把两条原因
    都报出来（保留原有诊断判据）。
  - 产品行为不变：AI 仍然不会把浏览器窗口弹到前台。

## 四、服务端与管理面

- 管理面分页在超大页码时整数回绕导致 500（审计日志 / 余额流水 / 用户 / 用量四个端点）。
- 访问日志只记录 URL 路径：单点登录回调的授权码与状态参数不再落入容器日志。
- 单点登录的服务发现（discovery）出网改用安全传输层：拦截链路本地地址与 DNS 重绑定，
  企业自建身份服务仍可正常使用。
- 网关在"必须改密"状态下强制返回 403 的回归测试补齐；`golang.org/x/crypto` 升级清除模块告警。
- 管理后台与客户端品牌面：品牌名槽补归属标记、图标与站点清单改为桌面端自有产物；
  cron 面板在会话区让位（此前分屏下会挤占中列）；上游 0.1.5 升级审查的 P0/P1 一并修复。

## 五、升级与回滚

- **服务端**：取本版镜像 → 按 `docs/deploy/AI-DEPLOY.md` 升级（**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`）。本版**无数据库迁移**，与 beta.2 数据面完全兼容。
- **客户端**：随服务端镜像分发，员工从自己登录的服务器取包（服务端会下发
  `client.version = 2.7.2-beta.3`）。**必须重装本版客户端**才能拿到本文三条修复。
- **回滚**：保留上一版镜像 tag，改回即可；客户端回滚需重装上一版安装包。

## 六、请复验这三条

1. 让 AI 做一次文件搜索（`glob` 或 `grep`）——应返回结果而非 provider failure；
2. 让 AI 抓一次网页（`web_fetch`）——在开了代理 fake-IP 的机器上应正常返回正文；
3. 让 AI 操作内置浏览器：点击一个链接或提交按钮应真的生效，截图应能拿到画面。

## 附件与校验

- `picoaide-server-2.7.2-beta.3-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。

## 已知边界

- 内置浏览器的点击在本版有两条路径：窗口可见时是真实合成输入；窗口隐藏时是页面对象层激活。
  后者不模拟"用户激活"语义，极少数依赖该语义的站点（部分支付、剪贴板、全屏）以及画布绘制、
  拖拽、悬停才出现的菜单，仍需要把浏览器窗口打开后再操作。
- `web_fetch` 的地址护栏是**有意去掉**的：若将来需要恢复，请连同代理环境一起评估，不要直接回退。
- 文件搜索与网页抓取两处都是**补丁**而非上游修复：升级 DSH 版本时需要重新切补丁，
  仓库守卫单测会在补丁丢失时立刻红灯。
