# PicoAide Harness v2.6.2（2026-09）

本版本修复能力中心上传的**归属权**问题：技能/智能体一旦有人上传（即使仍在待审核），该名称即归属上传者——其他人抢传同名将被明确拒绝；管理员可以修改归属（负责人），只有归属人可以继续更新，且版本号只能递增。

---

## 一、归属权（技能与智能体同一套策略）

### 1. 自动注册归属人 📌

员工 A 上传技能/智能体 X 的**那一刻**（无需等到审核通过），X 即注册归属人 = A（取自登录态，不可伪造）。A 的提交被拒绝、被删除后，名称与归属依然保留（与"版本号一经使用永久占位"同一防抢占精神）。

### 2. 他人不允许再动 🚫

- 员工 B 上传同名 X → **409**「名称已被占用，无法上传：请更换名称或联系管理员」（明确告知占用关系，不再返回 404）；
- 客户端能力中心上传前本地预检：同名且非本人 → 直接提示「名称已被占用」，不发请求；
- 历史回填的空归属行同样禁止员工"接管"；
- 被锁定（管理员占名）的名称 → 403 + 回显理由。

### 3. 归属转移（管理员可修改负责人）🔧

webadmin 能力中心审批页新增「归属」列与「转移归属」操作：把维护权交给其他账号后，旧负责人不能再上传、新负责人获得续传权；每次转移写审计 `app_owner_transfer`（含新旧值）。

### 4. 只有归属人可更新，版本只能递增 📈

- 本人升版本号（`x.y.z` 严格大于历史最高版本）可正常提交；同版本号**永不可复用**（含被拒/软删历史版本）；非首个版本必须写 changelog；
- 管理后台（如上架/代发）不受归属约束，仍可发布任意名称。

## 二、接口变更

| 端点 | 说明 |
|---|---|
| `PUT /api/server/admin/apps/:kind/:app_id/owner` | 归属转移（kind = skill/agent；RBAC `capability:write`；目标须为存在用户；同归属幂等） |
| `GET /api/client/v2/capabilities` | 条目新增 `is_owner`（当前用户是否为该能力归属人，供客户端预检） |
| `POST /api/client/v2/shared-skills`、`POST /api/client/v2/agent-presets` | 归属保护返回 **409 NAME_TAKEN** + 明确文案（此前 404） |

新增审计动作：`app_owner_transfer`。

## 四、升级注意

无需数据库迁移；服务端、桌面客户端（能力中心）、webadmin 同步升级即可。客户端预检依赖服务端下发的 `is_owner` 字段——旧服务端 + 新客户端时预检降级为服务端兜底（409 提示），不影响正确性。
