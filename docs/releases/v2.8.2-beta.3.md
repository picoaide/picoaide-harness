# v2.8.2-beta.3（2026-09-30）

> **谁必须升级**：要验证语音输入的测试环境；以及准备评估下一版交付件体积的运维。
> 本版有两件**运维必须先知道**的事：① 客户端新增**语音输入（默认开启）**；
> ② 语音模型**随客户端分发**，因此**三平台安装包各增大约 230MiB**，服务端镜像 zip 同幅增大。
> **不升级的后果**：留在 beta.2 拿不到语音输入（其余功能无变化）。
> 本版**没有任何数据库迁移**，回滚仍然是"换回上一版镜像 tag"。

## 一、语音输入（默认开启，模型随包）

- **现象**：会话输入框右侧出现麦克风按钮；点它开始录音，说话内容变成输入框里的**草稿文字**（可以改完再发）。
- **在哪儿识别**：客户端**本机**的子进程（SenseVoiceSmall + Silero VAD），**录音不出机器**，
  没有云端识别、也没有云端回退 —— 断网可用。中/英/日/韩/粤自动识别；单次最长 120 秒、上限 4MiB。
- **模型从哪来**：**随客户端分发**。构建时把权重打进产物（按上游清单校验大小与 sha256），
  客户端装配期把上游的官方配置项指到客户端目录里的那份 ⇒ **装上即可用：零下载、零网络**。
- **权限**：首次录音时向系统申请麦克风；客户端只放行**本应用主窗口**的纯音频请求
  （内嵌浏览器与应用窗口各走自己的权限面，不受影响）。
  **macOS 必须安装本版或更新的已签名包**（含麦克风用途说明与音频输入 entitlement）才会弹系统授权框。
- **自证**：打包版真机探针 —— 全新数据根下麦克风直接进入「开始录音」，且
  `$DSH_HOME/speech-to-text/` 为空（既没下载也没复制）；门禁侧有三组判据：
  上游 Remote 的**真实 Cordis 拓扑**解析、载荷→**上游官方配置项**的注入、以及
  "构建声明随包 ⇒ 产物必须真的带"。

## 二、交付件体积：压缩收益被随包模型抵消（**运维必读**）

- 本版含打包压缩优化（`compression=maximum`）：相对 beta.2，**Linux AppImage −43.2MB、macOS DMG −18.0MB**。
- 同时**三平台安装包各 +约 230MiB**（随包语音模型），所以**净变化是变大**：
  单个安装包约为"上一版 − 压缩收益 + 230MiB"，即**净增约 190MiB 量级**。具体字节以 tag 产物为准。
- **服务端镜像 zip 内含三平台客户端安装包**，因此 zip 会随之增大约 690MiB
  （beta.2 约 537MB → 本版约 1.2GB 量级）：取包、`docker load`、上传/下载时间都会变长，请预留时间与磁盘。
- **不想带模型的渠道**：在渠道包 `channels/<id>/channel.json` 写
  `"desktop": { "speech_bundle_model": false }`（缺省为 **true**）。关掉后客户端回到
  "首次使用时下载模型"，适合能直连公网或已配内网镜像的部署。
- 另外三个**可选**部署字段（都只影响本地获取模型的方式）：
  `desktop.speech_model_dir` + `desktop.speech_vad_path`（本机预置文件，零下载）、
  `desktop.speech_model_origin`（内网镜像源，模型路径与文件名不变）。
- 构建期行为：拉取不到权重会**直接让打包失败**（不产出"以为带了其实没带"的包）；重复打包幂等。

## 三、其他

- 客户端其余功能（会话、连接器、定时任务、内置浏览器、五轨记忆、更新检查）本版**无行为变化**；
- 上游固定点未变（仍 `0.1.7-rc.2`），会话格式未变（`v4`）；
- 服务端：**零代码改动、无数据库迁移**。

## 四、已知限制（本版认账，未修）

- **录音与识别只在有麦克风的真机可验**：无音卡的 CI / 无头环境里点录制会得到明确的
  "未找到设备"（预期行为，不是权限被拒）。
- **macOS 的系统授权弹窗**只在真机、且安装**已签名且公证**的包时出现（CI 只验打包与结构）。
- **预置/镜像来源的模型文件**由上游只查"文件存在"、**不校验哈希**（显式来源的既定语义）：
  版本匹配由部署方负责；配错的表现是准备阶段明确报 `Speech model verification failed`，
  不会静默降级成"看着正常但识别不出"。
- 语音转写只作为草稿插入输入框（不写入会话、不自动发送）；本版不做"语音指令"。

## 五、升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
- **回滚**：本版**属于"只加列/只建表"之外的最简一类 —— 无迁移**。
  保留上一版镜像 tag，改回并 `docker compose up -d server` 即可。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
  **macOS 用户必须更新到本版客户端**才会拿到麦克风权限。
- 会话格式与上游 pin 都没变 ⇒ 客户端可以单独回退，不需要恢复数据根。

## 附件与校验

- `picoaide-server-2.8.2-beta.3-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
