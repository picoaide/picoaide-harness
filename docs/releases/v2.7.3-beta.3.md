# v2.7.3-beta.3（2026-09-14）

> 一句话：连接器（第三方系统接入）的一轮修复版 —— **6 个真实缺陷**，其中"令牌续期不生效"
> 与"重连后工具消失"会直接影响日常使用。**建议客户端升级**；服务端无功能改动，可随镜像一起更新。

## 一、连接器令牌续期：不再"续不上"

- **现象**：连接器用着用着开始报"令牌无效"，或界面显示"已连接"但工具调用全部失败；
  更早的版本里点「连接」重新授权也救不回来。
- **原因（两处）**：①续期请求里带上了配置的权限范围，被授权服务器判定为"超出原授权范围"而拒绝，
  于是不断重试、不断失败；②"令牌变化后重新建立连接"的顺序写反了（先建新的、再拆旧的），
  第二次连接必然报"服务名已被占用"。
- **本版怎么修**：续期请求按规范只带必要参数（沿用原授权范围）；重新建立连接时先拆旧的再建新的，
  重连/换令牌都不会再撞名。刷新后的新令牌会立即用于后续请求，不需要重启客户端。
- **自证**：对**真实的授权服务器与真实的 MCP 服务器**跑通了完整流程（发现授权服务器 → 动态注册 →
  PKCE 授权 → 回调 → 带令牌调用工具），并覆盖"会话中途令牌失效 → 自动续期 → 继续调用成功"与
  "续期轮换后的令牌仍可继续续期"；连接器包内 278 项自动化用例全绿。

## 二、重连失败不再"弄丢"可用的连接器

- **现象**：点「连接」（例如想重新授权）后如果在授权页取消、或服务端临时不可达，
  原本还能用的连接器工具会整片消失，只能重启客户端。
- **修复**：只有授权**成功**之后才替换旧的连接；失败时保留原有的可用连接。

## 三、界面状态不再自相矛盾

- 断开连接后不再显示「令牌有效期至 …」；切换账号后不会残留上一个账号的有效期。
- 首次连接一个需要授权的服务时，如果凭据已被服务端拒绝，提示改为
  「需要先完成授权（点击「连接」重新授权）」，不再抛出原始技术错误。
- 需要额外凭据的连接器在凭据缺失时会明确要求填写，**不再出现"显示已连接但工具全废"的状态**。

> 说明：以上修复集中在连接器中心。服务端本次只随版本号出包，无功能改动、无数据库迁移。

## 升级与回滚

- **服务端**：从更新服务器取 `<渠道>/releases/2.7.3-beta.3/picoaide-server-v2.7.3-beta.3-amd64.zip`
  （内含 `image.tar`）或 GitHub Release 附件，按 `docs/deploy/AI-DEPLOY.md` 升级。
  **升级前必须备份**；不要使用 `latest` 标签，不要执行 `down -v`。本版无数据库迁移。
- **客户端**：随服务端镜像分发 —— 服务端升级后，员工从自己登录的服务器门户下载安装包即可；
  已装旧版客户端的机器会收到更新提示。
- **回滚**：保留上一版镜像 tag，把部署配置里的镜像标签改回并重启服务端即可。

## 附件与校验

- `picoaide-server-v2.7.3-beta.3-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压。
