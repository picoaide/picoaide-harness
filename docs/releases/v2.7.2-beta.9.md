## 一、Windows 客户端：MCP 连接器全部连接失败（本版修复）

- **现象**：在 Windows 客户端里连接**任何** MCP 连接器（服务端下发的、或自己填的
  `streamable-http` 地址都一样）立即报「连接失败：… 出站重定向栅栏不可用，拒绝连接」，
  面板状态停在“连接失败”。服务端与网络都正常。
- **影响**：仅 v2.7.2-beta.8 的 **Windows** 客户端。该版本给 MCP 连接通道加了
  「不跟随重定向」的加固自检，自检里判断安装路径时把路径分隔符写死了：Windows 上
  拿到的路径是 `C:\…\app.asar\node_modules\…`（反斜杠），而判断用的模板是
  `node_modules/…`（正斜杠），于是**任何** Windows 安装都被判成“加固对象不对”，
  直接拒绝注册连接器 —— 连接器本身完全正常。
- **修复**：判断前先统一路径写法（分隔符、`\\?\` 扩展长度前缀、Windows 大小写），并且只有在
  「两侧都能读到、且确实是两个不同文件」时才拒绝；读不到时不再当成“不同文件”，
  改由随后的实际行为校验决定。真正会放错加固对象的构建（例如 SDK 被打包内联、
  或存在第二份副本）仍然拒绝注册，**本次没有放松安全边界**。
- **自证**：回归用例直接钉住现场那两条路径（Windows 反斜杠写法）必须判为“同一文件”，
  并覆盖正/反斜杠、扩展长度前缀、大小写、两个可读的不同文件、一侧读不到五种情形；
  连接器包 203 项测试与全仓门禁绿。

## 二、其余客户端

- macOS / Linux 客户端本版**行为不变**（同一条自检在正斜杠路径下本来就通过），
  随版本一起重发只为统一版本号。
- 服务端镜像内代码与 v2.7.2-beta.8 相同，升级只为把修好的客户端安装包一并分发。

## 升级与回滚

- **服务端**：按 `docs/deploy/AI-DEPLOY.md` 执行 —— 从更新服务器取本渠道镜像包
  （`<渠道>/releases/v2.7.2-beta.9/picoaide-server-v2.7.2-beta.9-amd64.zip` +
  `SHA256SUMS`）→ `docker load` → 切换 `SERVER_IMAGE` → `docker compose up -d server`
  → 健康检查。本版无数据库迁移。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包更新；
  也可从门户下载安装包手动重装。
- **回滚**：把 `SERVER_IMAGE` 改回上一版本标签并重启 server 容器即可；本版无迁移，
  无需回滚数据库。仅回滚服务端**不会**把已升级的 Windows 客户端降级 —— 若要回退
  客户端，重装 v2.7.2-beta.7 或更早的安装包。

## 附件与校验

- 更新服务器：`<渠道>/releases/v2.7.2-beta.9/`（镜像包 + `SHA256SUMS`；同目录
  `latest.json` 指向本版）。
- 公开渠道另见 GitHub Release `v2.7.2-beta.9` 的附件
  `picoaide-server-v2.7.2-beta.9-amd64.zip` 与 `SHA256SUMS`。
- 校验：下载后 `sha256sum -c SHA256SUMS`（或与 Release 附件中的哈希逐字比对）再解压升级。
