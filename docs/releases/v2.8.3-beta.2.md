# v2.8.3-beta.2（2026-10-18）

> 一句话：服务端把 DeepSeek 的 **web_search 按次费用**纳入计量与账单，管理端可配置单价；
> 同时包含 macOS 客户端**原地自更新**、WASM 应用控制台修复、渠道交付平台声明、发布链收敛
> 与官网/Wiki 重构。**不升级的后果**：搜索按次费用仍然只按 token 计费，11 月 1 日起
> 这部分上游成本会静默漏计；macOS 用户继续走「打开磁盘映像、自己拖进应用程序」的旧更新路径。

## 一、web_search 按次计费（服务端 + 管理端）

- **背景**：DeepSeek 官方自 **2026-11-01 00:00（北京时间）** 起，对 DeepSeek Harness /
  Claude Code / Codex 经**服务端工具调用**访问 Search / Fetch 的请求，按 **5 元 / 千次成功请求**
  计费。网关在 `/v1/messages` 的 Anthropic 兼容代理链路上只能看到模型 token 用量，
  看不到这笔按次费用 —— 不单独计量就会整段漏计。
- **本版怎么修**：
  - 网关统计响应里**成功带回网页结果**的 `web_search_tool_result`（错误块、空结果块不计；
    上游在 `usage.server_tool_use.web_search_requests` 自报时取二者较大值，不重复相加）；
  - 新增 `usage.search_requests`（0085，只加列）记录每次请求的搜索次数，费用 =
    token 费用 + 次数 × `usage.search_price_per_1k` / 1000；
  - **按次费用不参与峰谷折扣** —— 官方 Search 是无时段差异的独立价目；
  - 流式请求在收尾结算里回填；搜索结果晚于最后一条 usage 时补一次差额回填（幂等，不重复扣）；
  - 0-token 清理**排除**已计费的搜索行，避免「余额已扣、明细消失」。
- **管理端**：「网关 → 计费」新增「Search 按次计费(元/千次)」，取值 0~1000，
  **缺省 0 = 不计费**（升级本身不改变既有账单）。要跟随官方计费，请在该页填 **5**。
  用量明细接口同步返回 `search_requests`，可按次对账。
- **顺带修正**：模型编辑页的缓存命中价提示语此前写「仅作定价展示；命中 token 仍按输入价计费」，
  与后端实际按 `cache_input_price_per_1m` 计费相反。本版改为正确说明并给出官方参考比例
  （V4 缓存命中价约为输入价的 2%~3.3%）；历史费用不受影响（cost 记录时固化）。

## 二、macOS 客户端原地自更新

- **现象**（升级前）：macOS 的「安装更新」只打开已下载的磁盘映像，然后要求用户自己把应用
  拖进「应用程序」；对非技术用户这一步经常半途而废，或留下新旧两份应用。
- **本版**：与 Windows 同口径 —— 确认后宿主退出，一个 detached 的 `/bin/sh` 帮手把影像里的
  应用复制到目标同目录、`codesign --verify --strict` 校验通过后，以「旧包改名成备份 +
  暂存件原子 rename」的方式落位，再重新打开应用；新版本在启动路径上写标记，帮手等到它才删
  备份，等不到就回滚并重开旧版本。
- **判据都在动用户文件之前**：影像里必须是同一个 BundleID、清单声明的版本、同一个签名 Team；
  做不到原地替换的环境（开发态、App Translocation、目标不可写、空间不够、非管理员账号等）
  逐字回落到**改造前**的「打开磁盘映像让用户自己拖」。
- **合并前审计的修复同版交付**：启动标记改为整行定串并绑定 bundle（防版本号前缀误判）、
  新增启动失败的负向标记、撤回「目标路径下有进程即成功」的 `pgrep` 判据、
  备份删除收敛到宿主侧唯一一处、失败状态撤销 ready 以便重新检查更新，并把 macOS 集成判据
  接进 CI 真跑（此前 `describe.skipIf(≠darwin)` 在 CI 上从未执行）。
- Windows / Linux 客户端更新路径不变。

## 三、WASM 应用控制台修复

- **现象**：管理端「应用中心 → 平台限制」把时间预算（如编译超时）改成某个值后点保存，
  页面上什么都没发生。
- **两处根因**：① 控制台下发的区间是基础区间（编译超时 1–300 秒），而服务端实际校验上界是
  60 秒 —— 页面把管理员引到一个必然被拒的值；② 保存失败的反馈原先渲染在字段区上方，
  而保存按钮在长表单底部，点保存时错误块在视口外。
- **本版**：区间改由与服务端校验**同一批序关系**推导（区间内每个值都有合法组合、区间外
  每个值都不可达）；反馈紧贴动作按钮，并按 `details.field` 定位到被拒的那一格
  （格子标红 + 格内错误全文 + 滚动/聚焦）。不放宽任何执行期闸门，无数据库迁移。

## 四、渠道可声明交付平台

- 渠道配置新增 `desktop.platforms`（取值 `win` / `mac` / `linux`，**缺省 = 三端全交付**，
  既有渠道行为逐字节不变）。声明后**四处一起收窄**：镜像装配（非声明平台的安装包不进镜像）、
  更新服务器中转（只传/只校验声明平台）、门户下载区（未声明平台整块不渲染）、
  客户端更新清单（少该键，客户端自然收不到该平台更新）。
- 新增「官方渠道 = 新增渠道的模板」完整性判据：官方渠道的渠道配置必须**逐键显式**声明
  （slug / app_id / 产品名 / home 目录 / 深链 scheme / 交付平台等），不再依赖代码兜底值。
  复制模板新建渠道时缺键会在 CI 当场红，而不是带着看不见的继承行为上线。
- **运维提示**：只交付 Windows + macOS 的渠道将不再产出 Linux 安装包（每版约 350 MiB），
  门户也不再显示 Linux 下载块。

## 五、发布与分发链收敛

- 更新服务器每个渠道的版本保留策略由 **3 版收紧为 2 版**（最新版 + 上一个版本）。
  单个渠道包实测约 1.25 GB，4 渠道 × 3 版会超出存储额度；更老的版本以 GitHub Release
  作为长期存档。**回滚深度因此只有一格**：R2 上只保留上一个版本，再往前请用 Release 存档。
- 新增中转孤儿前缀清扫：发布中途失败/被取消时销毁步骤不会执行，历史遗留对象是客户安装包而
  桶是公开读的。现在按对象年龄（缺省 24 小时）清扫中转前缀，只删整个都超龄的一级前缀，
  **永不碰本次运行的前缀**；删除目标只由运行 id + HMAC token 构成并做形状校验
  （经品牌脱敏的列表输出不能回传当删除目标 —— 文件名会变成 `***`，删除会静默落空）。

## 已知限制（本版认账，未修）

- **搜索计量只覆盖网关 `/v1/messages` 的服务端搜索**：客户端直连的 `web_fetch`、
  以及 OpenAI 兼容 `/v1/chat/completions` / `/v1/responses` 里的搜索工具不在统计面内
  （本平台当前链路不使用后者）；若将来改走服务端 Fetch，需要另加计量。
- 上游既不返回搜索结果块、也不自报 `usage.server_tool_use.web_search_requests` 时，
  按次费用**无法计量**（不会凭空加收），只能按 token 计费。
- 搜索单价缺省 0：不配置就仍按 token 计费；11 月 1 日之后需要管理员显式设为 5。
- macOS 原地更新在开发态、App Translocation、目标不可写、空间不足、非管理员账号等环境
  回落为「打开磁盘映像」；回滚不回滚用户数据；用户自己的实例占着锁时更新会被回滚。
  逐条认账见 `docs/decisions/2026-10-09-macos-in-place-update.md`。
- 渠道平台收窄只认 `win` / `mac` / `linux` 三值；真实渠道仓的模板完整性由 CI 的
  `--require-template` 判据保证（合成夹具不带该旗标）。
- 更新服务器只保留最近 2 个版本，跨两版以上的回滚需要使用 GitHub Release 存档。

## 升级与回滚

- **升级前必须备份**：`picoaide-data`（含 `master.key`）与 `pg_dump`，确认备份非空。
- **服务端**：本版包含迁移 **0085**（`ADD COLUMN IF NOT EXISTS usage.search_requests`，
  只加列、可重放，不重写历史行）。按 `docs/deploy/AI-DEPLOY.md` 取镜像并升级；
  升级后到「网关 → 计费」确认 Search 单价（跟随官方计费填 5，不启用则保持 0）。
- **客户端**：随服务端镜像分发，员工从自己登录的服务器取包；服务端升级后客户端会提示升级。
  macOS 本版起原地替换应用包；WASM 应用仍要求服务端与客户端同版本使用。
- **回滚不能只换镜像**：beta.1 的二进制不认识 0085，会以「schema 与二进制不同代」拒绝启动。
  正确步骤：① 确认只加列的 0085 与旧二进制兼容后，删除 `schema_migrations` 里的 85 行
  （`search_requests` 列可以保留，旧代码忽略它）；② 把服务端镜像改回 `v2.8.3-beta.1` 并重启；
  ③ 如需恢复数据，用升级前的应用数据与数据库备份。客户端可继续使用已升级版本
  （macOS 原地更新不迁移用户数据）；服务端回滚后更新清单会回到旧版。
- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：`0085_usage_search_billing.sql`

## 附件与校验

- `picoaide-server-2.8.3-beta.2-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），
  内含该渠道的客户端安装包；渠道声明了 `desktop.platforms` 时只含声明的平台。
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
- 客户端安装包在镜像内（`/opt/picoaide/client/`），员工也可从自己服务器的更新页面下载。
  品牌渠道的镜像与客户端只在该渠道自己的更新目录里，不随公开 Release 发布。
