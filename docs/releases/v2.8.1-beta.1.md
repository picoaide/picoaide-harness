# v2.8.1-beta.1（2026-09-22）

> 一句话：本版**没有任何新的用户功能**，交付两件内部改动 —— 桌面客户端的引擎升到
> Electron 44.4.3（Chromium 152），以及**发布包不再夹带客户端自身的源代码与 sourcemap**
> （安装包内 asar 内容 −18.7 MiB）；同时发布版关闭调试工具。
> **注意：本版不以缩小安装包为目的** —— 新引擎的运行时更大，三平台安装包的下载体积
> 比上一版**略增**（约 +2 ~ +10 MB）。
> beta 测试环境建议升级，用于验证新引擎与新的打包管线。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 预发布（beta 渠道） |
| 升级建议 | beta 测试环境建议升级（验证新引擎 + 新打包管线） |
| 影响面 | **桌面客户端**（Linux / Windows / macOS）；服务端镜像随包同版本，无服务端行为变化 |
| 产品代码变化 | 有（客户端打包管线与窗口策略；无面向用户的功能变化） |
| 数据库迁移 | **本版无新增**（沿用现有 schema） |

## 一、发布包不再夹带自有源码（asar 内容 −18.7 MiB）

- **现象**：上一版（2.8.0）的安装包内，asar 归档共 14 385 个条目 / 148.05 MiB；本版为
  12 334 个条目 / **129.38 MiB**（**−18.7 MiB，−12.6%**）。减少的部分是客户端自身的
  `src/`、`tests/`、`scripts/`、各插件源码目录、**内嵌原始 TypeScript 源码的 sourcemap**，
  以及依赖包中仅供构建期使用的 `.ts` / `.d.ts`（包内 `.ts/.tsx` 条目 1 975 → **0**）。
- **这不是体积优化**：安装包会把内容重新压缩，源码类文本在压缩包里占的份额很小，而新引擎
  的运行时更大，因此**三平台安装包的下载体积反而略增**。下表是同一渠道、由服务端门户分发的
  实际交付文件（不是本地构建产物）：

  | 交付产物 | 2.8.0（上一版） | 本版 | 变化 |
  | --- | --- | --- | --- |
  | Linux（AppImage, x64） | 157.91 MB | 159.93 MB | +2.02 MB |
  | macOS（DMG, Apple 芯片） | 159.23 MB | 163.21 MB | +3.97 MB |
  | Windows（NSIS 安装程序, x64） | 179.57 MB | 189.37 MB | +9.80 MB |

- **影响**：修复的是**实现细节暴露面**（见第二节），不是下载耗时；需要"更小的安装包"的
  场景不适用本版。
- **修复**：打包输入改为「运行期白名单」——只有真正随包运行的产物进入安装包，其余在进包前
  就被排除。构建期新增正反两侧断言：安装包内不得出现自有源码 / sourcemap / 开发期产物
  （命中即拒包），同时必须保留随包运行期资源（内置技能等），两个方向都由门禁钉住。
- **自证**：与上一版**实际交付件**同口径清点（自有源码与 sourcemap 条目 **471 → 0**，
  `.ts/.tsx` 条目 **1 975 → 0**），上表数字取自部署机上的真实交付文件。

## 二、发布包不再可以读出实现源码（安全面）

- **现象**：此前发布的正式版与预发包里，安装包内含客户端自身的源代码目录与
  sourcemap（sourcemap 里**内嵌原始 TypeScript 源码**）；同时客户端**从未关闭调试工具**，
  在客户机上打开调试工具即可读到这些内容。
- **影响**：属于实现细节的暴露面，不影响业务数据与登录凭据。任何拿到安装包的人都能看到。
- **修复**：①源码与 sourcemap 不再进包（sourcemap 在进包前丢弃，而非打包后删除）；
  ②**发布版关闭调试工具**，开发态（`yarn dev`）保持可用。自动化测试与诊断链路走的是
  独立的调试端口协议，不受影响（本版已跑通完整客户端自动化）。
- **认账范围**：第三方依赖包自带的源码与类型声明**仍在包内**（那是上游 npm 包的公开内容，
  不属于我方源码）。若需要进一步瘦身，需要逐个依赖包判定，属独立课题。

## 三、桌面引擎升到 Electron 44.4.3（Chromium 150 → 152）

- **现象**：桌面客户端的浏览器引擎随之更新（Chromium 152、V8 15.2），包含上游的安全修复。
- **影响**：**不升级不受益**；本版客户端与服务端无需同时升级（无跨端协议变化）。
- **核对**：Electron 44 的几条破坏性变更逐条核对均不影响我们 —— 移除 32 位与 Unity
  不在交付范围内；剪贴板 API 调整不影响（渲染侧走标准 `navigator.clipboard` + 权限策略）；
  网络请求头的新限制不影响（应用出站只发普通接口请求，不做文档导航）。
- **体积说明**：引擎升级本身**会让包变大**，不是瘦身手段 —— 实测同配置下
  43.4.0 为 153.3 MB、44.4.3 为 160.0 MB（+6.7 MB）；第一节的打包修复在同一口径下
  约省 4.6 MB，两者相抵后 Linux 安装包净增约 2 MB。

## 已知限制（本版认账，未修）

- **Windows 与 macOS 安装包未在本机复核**：本次在 Linux 上完成了真实打包与完整客户端
  自动化（41 项断言全过），Windows NSIS 与 macOS DMG 由 CI 三平台 job 构建，需要在对应
  平台做一次冒烟确认后再对外铺开。**请 beta 渠道的 Windows / macOS 用户升级后反馈启动与登录**。
- **本次升级的客户端需手动更新**：客户端自动更新按版本号递增触发，已装旧版（2.8.0）的机器
  会收到提示；beta 与正式版**共用同一数据目录**（登录态与历史会话延续），因此从 2.8.0
  升级不需重新登录。
- **调试工具在发布版不可用**：这是本版**有意**的行为变化（见第二节）。需要现场排查时，
  使用客户端自带的「导出诊断包」入口，而不是调试工具。
- 本版**无新的用户功能**，因此不涉及功能回退；若只关心功能变化，本版可以跳过。

## 访问模型变更（升级必读）

**本版无访问模型变更。** 客户端仍在桌面客户端内使用，浏览器入口、登录方式、数据目录
与服务端接口均与上一版一致。

## 升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
- **回滚**：本版**无数据库迁移、无服务端行为变化**，回滚只需保留上一版镜像 tag、
  改回 `.env` 的 `SERVER_IMAGE` 后 `docker compose up -d server` 即可，不需要恢复数据库。
  客户端回滚需要重装上一版安装包（**注意**：本版关闭了发布版调试工具，回退到旧版会恢复该能力）。

## 附件与校验

- `picoaide-server-2.8.1-beta.1-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），
  内含该渠道的三平台客户端安装包；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
