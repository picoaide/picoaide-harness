# v2.7.3（2026-09-14）

> 一句话：本版是一轮**安全审计修复 + 连接器可用性**的合集 —— 修掉一批「可能外泄 / 可能越权 /
> 可能少收钱」的缺陷，并让连接器（第三方系统接入）的访问令牌**自动续期**，不再需要重启客户端。
> **服务端与客户端都建议升级**；从 v2.7.2 升上来有 4 条数据库迁移（启动时自动应用，见第五节）。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 正式版 |
| 升级建议 | **建议所有部署升级**（含 1 个登录链路 P0、多项凭据保护与计费口径修复） |
| 影响面 | 服务端镜像、Windows · macOS · Linux 客户端、管理后台、网页门户 |
| 产品代码变化 | 有（相对 v2.7.2：自 v2.7.3-beta.1 起累计三轮修复 + 门户改版） |
| 数据库迁移 | 有 4 条：0064 `users.last_totp_step`、0065 `usage.provider_id`、0066 `admin_sessions.secret_hash`、0067 `users.external_identity` |

## 一、登录链路：链接里的服务器地址不再被信任（P0）

- **现象**：员工点开一个指向**真实公司服务器**的登录链接并在公司统一登录页完成登录后，
  登录凭证可能被发送到链接里指定的**另一台服务器**。攻击者不需要伪造登录页、不需要密码，
  用统一登录（SSO）或双因素（MFA）的同事同样会中招；被拿走的凭证有效期 90 天，等同于
  该员工在公司服务器上的全部权限。
- **本版怎么修**：服务端只接受来自"服务端自己配置的地址"的登录回跳（不再信任请求里带的主机名）；
  客户端把"是否更换服务器"的判断提前到**发出任何网络请求之前**，没有正在等待的登录目标时一律拒绝。
  密码登录与正常单点登录流程都不受影响。

## 二、客户端凭据保护（多项）

- **注入的凭据不再从错误提示里漏出**：此前机器人操作失败时，错误文案里可能逐字带上刚才注入的
  密码（当页面把密码当作元素 id 时）。现在所有对外文本（页面快照、错误提示、页面正文、执行结果）
  统一先脱敏再截断。
- **同一网站的另一个标签页不再能读回密码**：此前凭据保护只认"当前标签页"，在同网站新开一个
  标签页即可通过读取网页存储拿回刚注入的密码。现在保护跟随**网站**（并加 5 分钟上限与数量上限，
  避免长期占用）。
- **截图不再抢在保护生效前拍到密码**：此前的检查在排队之前做，若前面的操作（如等待页面）正占着
  执行权，截图会排在注入之后执行并拍到已填好的密码。现在检查与执行在同一临界区内。
- **能力代价（有意保留）**：口令被页面**变形**渲染（base64、逐字符分隔、画成图片）时，值级擦除
  覆盖不到；这类变形仍可能进入模型上下文。若需要更严（例如注入过凭据的标签终身禁用脚本与截图），
  请提出，我们按下一轮决策处理。

## 三、连接器（第三方系统接入）：令牌自动续期 + 六个真实缺陷

- **令牌续期：不再"续不上"**。此前客户端开着一两天之后，连接器（招聘、CRM 等第三方系统）的
  工具调用开始持续报"令牌无效"，界面却仍显示"已连接"，唯一的恢复办法是重启客户端或重新走一遍
  授权。本版把续期交给 MCP 官方授权规范实现，并补齐三处触发时机：**调用时**（服务端报令牌过期
  就自动换新并重试，用户无感）、**后台心跳**（每分钟检查一次，临近过期提前续期；本机子进程型连接器
  会在续期后自动重启该子进程）、**手动**（连接器卡片新增「刷新令牌」按钮，不会重新打开授权页）。
  卡片同时显示「令牌有效期至 …」与「上次刷新 …」；确实失效时明确显示「需要重新授权」，
  网络或服务端临时故障则保留原凭据、稍后自动重试。
- **重连失败不再"弄丢"可用的连接器**：点「连接」（例如想重新授权）后如果在授权页取消、
  或服务端临时不可达，原本还能用的连接器工具会整片消失，只能重启客户端。现在只有授权**成功**
  之后才替换旧的连接。
- **界面状态不再自相矛盾**：断开后不再显示「令牌有效期至 …」；切换账号后不残留上一个账号的有效期；
  需要额外凭据的连接器在凭据缺失时明确要求填写，不再出现"显示已连接但工具全废"的状态。

## 四、计费、管理台与共享内容

**服务端计费（该收的钱不再漏收）**
- **流式对话在余额不足时不再"送完整回答却不扣费"**：此前余额判定发生在回答全部发完之后，
  扣费失败会连带把这一次的用量记录一起回滚 —— 表现是员工拿到完整回答、账单上是 0，
  而且可以无限重复。现在这类欠款如实入账（欠款会拦住后续请求），非流式请求仍在**未交付**时拒绝。
- **客户端无法再关掉自己的计量**：此前请求体里一个 `include_usage:false` 就能让上游不回报用量，
  输入侧因此永久按 0 计费（实测一次 16 元的调用只记 0.52 元）。现在计量开关由服务端持有。
- **按实际命中的上游计价**（迁移 0065）：同名模型配置了多个上游时，不再可能命中 0 价。
- 补齐输入侧兜底估算，并收口"估算把图片按字节当 token"（会把一次调用算成 300 倍价钱）与
  "文本伪装成图片把费用压低"（最低可压到三百分之一）两个方向；上游错误响应体只透传必要字段，
  不再原样回传可能含密钥的全文；单用户并发请求有上限。

**管理台与共享内容**
- **渠道素材脚本执行**：带脚本的渠道 logo 被直接打开时会在服务端域上执行，并可读走管理台的
  会话令牌。现在素材下发统一带沙箱策略并在下发前做脚本特征检查，管理台自身也补齐了安全响应头。
- **管理员会话令牌只存哈希**（迁移 0066）：升级后**现有管理会话全部失效，管理员需重新登录一次**。
- **双因素（TOTP）** 校验加入重放保护；第二步校验与登录失败共享限流，不可无限爆破；未认证请求
  无法再靠大量密码校验耗尽内存；外部身份（统一登录 / LDAP）与身份提供方主体绑定，
  同名不同主体一律拒绝，避免接管同名账号。
- 审计员角色不再看到注定失败的写操作按钮；共享库与市场内容不再互相串（下架的智能体不再出现在
  共享库/审批队列/能力中心，授权替换不再连带删掉用户级授权）。
- **技能与智能体上架**：智能体的行为编排文件此前从未被审核界面读取（超过预览上限时静默变成空白），
  审核员看到空内容、员工装到的却是真实编排 —— 现在编排必须可读且可解析才能上架；归档完整性校验
  覆盖全部条目，解包闸门加固（YAML 别名/合并炸弹、同名文件、文件与目录同名、符号链接条目等）。

**网页门户**
- 门户首屏改为**下载优先**：第一眼就是「下载客户端 → 安装 → 登录」，管理后台入口从首屏移除
  （管理员直接访问 `/admin/`）。下载按钮改为图标 + 文字，深色主题自动换用暗色版标识；
  窄屏下单列排版。

**本机接口与其它**
- 定时任务与桌面更新的本地接口补上持有性证明 —— 此前本机任意程序伪造请求头即可写入并立即执行
  定时任务、或触发更新安装。
- 记忆插件的全部写入落点统一加符号链接断言（此前目录级符号链接可让写入落到仓库之外）。
- 桌面更新协调器的定时器不再被并发操作互相取消（此前"检查更新"可能永久变成静默无操作）；
  诊断包权限收紧到 0600，渠道构建导出的诊断包不再指向官方数据目录。

## 五、升级、迁移与回滚

- **服务端**：从更新服务器取本渠道镜像包
  （`<渠道>/releases/v2.7.3/picoaide-server-v2.7.3-amd64.zip` + `SHA256SUMS`）→ 校验 →
  `docker load` → 切换 `SERVER_IMAGE` → `docker compose up -d server` → 健康检查。
  启动时自动应用迁移 **0064 / 0065 / 0066 / 0067**（新增列，在线 DDL）。
  **升级前必须备份**（`.env` + `pg_dump -Fc` + `picoaide-data`），详见 `docs/deploy/AI-DEPLOY.md`。
- **升级后请知悉两点行为变化**：①**管理员需重新登录一次**（迁移 0066 使存量管理会话失效）；
  ②客户端请求里带 `include_usage:false` 不再被"尊重"（计量由服务端持有），这是计费正确性所必需。
  另：新保存的 LDAP 配置若为非回环明文 `ldap://` 默认拒绝（存量配置不受影响，
  需要时设 `PICOAI_LDAP_ALLOW_PLAINTEXT=1`）。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器门户取包更新；
  已装旧版的机器会收到更新提示。数据根与 v2.7.2 一致，无需重新登录。
- **回滚**：把 `SERVER_IMAGE` 改回上一版标签并重启 server 容器即可。本版迁移为新增表/列，
  回滚镜像不会破坏数据；仅回滚服务端**不会**把已升级的客户端降级 —— 若要回退客户端，
  请重装上一版安装包。

## 附件与校验

- 更新服务器：`<渠道>/releases/v2.7.3/`（镜像包 + `SHA256SUMS`；同目录 `latest.json` 指向本版）。
- 公开渠道另见 GitHub Release `v2.7.3` 的附件 `picoaide-server-v2.7.3-amd64.zip` 与 `SHA256SUMS`。
- 校验：下载后 `sha256sum -c SHA256SUMS`（或与 Release 附件中的哈希逐字比对）再解压升级。
