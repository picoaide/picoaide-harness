# v2.8.2-beta.7（2026-10-06）

> 预发版，只修一件事：内置浏览器的「AI 控制蒙版」在 `v2.8.2-beta.2` ~ `v2.8.2-beta.6` 的客户端上**整层不显示**。
> 与 `v2.8.2-beta.6` 相比**只有客户端程序改动、没有任何数据库迁移**：服务端换镜像即可、客户端随镜像分发；
> 回滚同样是换回旧镜像。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 预发布（beta） |
| 升级建议 | 建议升级；**使用内置浏览器的同事必须升级客户端** |

## 一、内置浏览器：AI 控制蒙版整层不显示（用户报告）

**现象**：用「AI 操作浏览器」打开网页后，窗口里**看不到任何 AI 控制界面** —— 既没有"AI 正在操作 /
我来操作"的蒙版，也没有右下角的"交给 AI"胶囊；网页与工具栏照常显示，但**整窗点击都没反应**：
点不到「我来操作」接管，也点不到「交给 AI」交还。把浏览器窗口关掉再打开**不会恢复**
（关窗只是隐藏窗口，那层视图还活着），要重启客户端才会重建。

**影响**：`v2.8.2-beta.2` ~ `v2.8.2-beta.6` 的客户端上，内置浏览器的人工接管/交还入口不可用：
AI 把控制权交给用户（例如引导登录）之后，用户既无法交还、也无法确认状态，只能重启客户端。

**根因**：`v2.8.2-beta.2` 起客户端随包的引擎（Electron `45.0.0-alpha.7`）在「透明覆盖层叠在网页之上」
这条能力上出现回归 —— 覆盖层不再正确合成到网页之上：在软件合成的机器上表现为**整窗被一块灰白板盖住**，
在有硬件合成的机器上表现为**覆盖层什么都没画、却照样吃掉全部点击**。真机像素对拍（同一个探针只换引擎）：
`44.0.0` / `44.4.3` / `43.x` 上蒙版之下的网页颜色正常透出，`45.0.0-alpha.7` 上**一个像素都透不出来**。

**本版怎么修**：

- 客户端引擎回到 **Electron `44.0.0`**（稳定版，且仍在上游包解析原生插件支持的运行时列表里）；
- 该引擎在 **`app.asar` 归档路径**上取文件元数据时会退化成「数字版」统计信息（会导致**文件系统技能
  整片消失**：预设自带技能、项目 `.dsh/skills`、`$DSH_HOME/skills`、`~/.agents/skills`）——
  本版用自己的补丁把这条补齐（`patches/dsh-fs-local@0.2.0-rc.2.patch`：权限位与纳秒时间戳按形状取值）；
- 打包门禁随之改成**能力判据**：不再要求"引擎必须返回某种统计形态"，而是要求打包后的客户端**真的能
  在归档里 stat / 列举 / 读取预设技能**（列举结果与产物反推的期望逐元素相等），引擎形态只打印到构建日志。

**自证**：真机像素 A/B 探针（同一脚本、同一台机器，44.0.0 通过 / 45-alpha 失败）；
`yarn package:dir` 的 afterPack 门禁在真 `app.asar` 上通过（日志形如
`packaged ASAR filesystem smoke OK … ASAR-BIGINT-SMOKE-ENGINE bigint=false …`，即"引擎仍是数字形态、
而技能真的列得出来"，正是本版要表达的语义）；打包版图形 E2E 43/43；桌面与浏览器包测试全绿。

## 二、这一版的连带说明（引擎回退的影响面）

- **不变**：服务端代码、数据库结构、会话格式、业务功能——本版不影响服务端；
  客户端的数据根与登录态不变，升级后无需重新登录、历史会话照常可见。
- **内置浏览器**：蒙版、胶囊、活动面板与「我来操作 / 交给 AI」入口恢复正常。
- **文件系统技能**（预设/项目/家目录）：打包版上正常，由上面那条补丁保证。
- **麦克风**：本版引擎的权限回调形状与上一版不同（会带 `mediaType`，且一次请求会依次询问
  音频与视频两类），闸门方向**更严**（多了"视频一律拒"的一道）；用过语音输入的同事若遇到
  异常，请把现象反馈给我们。

## 访问模型变更（升级必读）

本版无。

## 已知限制（本版认账，未修）

- **控制权提示最长 5 秒延迟**（继承自上一版）：侧边栏的"控制权在你手里"提示走 5 秒轮询，未接长连接。
- **"蒙版画不出来"这一类故障仍缺自动兜底**：本版修的是根因（引擎），但"看不见的蒙版不允许占着整窗
  吃点击"这条自我保护还没做，计划中。若日后再次遇到"整窗点不动且看不到任何控制入口"，请**重启客户端**
  并在会话里反馈。
- 其余继承自 `v2.8.2-beta.6` 的已知限制不变（见该版「已知限制」一节）。

## 升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
  **只用旧版客户端拿不到本修复**。
- **回滚**：本版**没有任何数据库迁移**，也不含数据改写 ⇒ 保留上一版镜像 tag，把 `SERVER_IMAGE`
  改回去、`docker compose up -d server` 即可；客户端回装上一版安装包（回装后内置浏览器的蒙版问题
  会随旧引擎一起回来）。
- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无

## 附件与校验

- `picoaide-server-2.8.2-beta.7-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
- 客户端安装包在镜像内（`/opt/picoaide/client/`），员工也可从自己服务器的更新页面下载。
