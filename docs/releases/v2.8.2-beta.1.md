# v2.8.2-beta.1

> **谁必须升级**：所有在用 2.8.1 及更早版本的环境。本版是一次**全仓审计（五轮）后的修复版**，
> 以**修 bug 与补判据**为主，无新功能；其中包含一条**发布面不可用的生产级缺陷**（见下）。
> **不升级的后果**：WASM 应用平台在编译缓存超上限后会**永久拒绝发布/校验**且不自愈；
> 商店技能可能被"更新"静默覆盖掉本地改动；随包技能被卸载后下次开机会自己装回来。

## 一、这一版修了什么（按"用户会怎么碰到"排序）

**1) 发布面与可用性（含一条生产现场 P0）**
- **WASM 编译缓存自锁**：磁盘编译缓存超过上限后，发布/校验闸门会一直 503，而回收只在编译作业之后跑 ⇒ 永不恢复。现在有周期回收 + 闸门命中"缓存超上限"时先同步回收再判，并新增"每个阻塞理由都必须登记自愈路径"的常设判据。
- **发布链守卫**：CI 触发器与"被钉住的步骤"现在不可被静默摘除（`if: false` / `continue-on-error` / 删 `push:` 之类会直接红）。
- **补丁实效**：`patches/` 若一处都没生效，门禁现在必然失败（旧行为只打一行 warning，且判据见证依赖 yarn 缓存）。

**2) 能力中心 / 技能库**
- 商店技能被本地修改后，"更新"不再静默整树覆盖用户改动；内置技能的"卸载"会持久生效（不再下次开机被装回）。
- 随包技能换入的临时目录挪到第二层私有目录（修掉窗口期内可能索引到"幽灵目录"的问题）；随包技能升版后溯源版本号不再停留在旧值。
- 版本先后语义收敛为一份算法 + 一份仓内共享语料（修掉"把降级当升级"的双端分叉）。

**3) 客户端宿主**
- 连接器对"永久拒绝"类 OAuth 错误不再无限重发；cron 在"应用关闭期间错过触发点"时现在可观测（不改触发时刻、不补跑）。
- 浏览器工具的预算不再被内部等待/排队吃掉（返回可读的具体错误）；深链打开应用与面板打开走**同一个**打开闸门。
- 回收器/账本/锁/临时文件若干处一致性与失败清理。

**4) 服务端与计费**
- 文件回收在"复检 → 上游删除"之间不再误删他人对象（引入世代号）。
- 模型取参、账本与明细切分、审计批写失败、余额对账读失败等若干处改为**确定序 / 如实报错**。
- 管理面路由守卫从"前缀字面量"改为命名空间级；审计保留策略现在有周期执行者。

**5) 工程与门禁（不直接影响用户，但决定以后能不能少踩坑）**
- 五轮审计共发现并在本版修复：6 P0（含一条生产现场 P0）+ 108 P1（逐轮：66/15/19/8/15，其中部分为门禁自身的判别力缺陷），以及数量更多的 P2/P3；每条修复都带回归用例与变异验证，且由**另一名子代理独立复审**。
- 对"假绿"（扫不到就当通过、只钉文本不钉能力、可空转的注入接缝、检测与计票共用一条通道）做了系统性收口；发布链新增三类"静默零发布"判据（tag 缺 `v` 前缀、tag 打在旁支、预发缺发布说明）。

## 二、升级须知

- **数据库**：本版只有一条**只加列**的迁移（`gateway_files` 的世代号字段），不回填、不改写既有数据；回滚只需换回旧镜像（列留着无害）。
- **客户端**：与服务端版本需保持同代（0.1.6 线）。预发布 tag 只构建 beta 渠道；品牌渠道要等正式 tag。
- **运维**：如果你的环境里有"定期删编译缓存文件"的临时脚本，**升级后请停用** —— 新版本由进程内回收统一负责（直接删文件会与编译写并发）。人工清空请走 `/readyz` 指引或进程内回收入口。
- **已知未修（本版仍然存在，均已登记）**：cron 在同进程换代时会把在跑的 run 记为 cancelled（与既有"封笔世代拒绝迟到结算"断言冲突，需产品拍板）；编译缓存上限仍是编译期常量（后台暂不可配，本版已让回收/水位不再依赖编译子系统）；`/readyz` 仍未鉴权（本版已把驱动错误原文从对外响应移出，只留分类与可 grep 的服务端日志）；Windows/macOS 打包与真机图形 E2E 未在本轮验证（本机 Linux）。
