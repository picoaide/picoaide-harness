# PicoAide Harness v2.6.9-beta.4（2026-09）

预发布补丁：修掉 v2.6.9-beta.3 在测试环境暴露的**侧边栏品牌名折行**（左上角大号
品牌字变成两行，侧边栏头部从 24px 撑到 48px）。功能面与 beta.3 相同。

---

## 一、侧边栏品牌名折行（两个原因叠加）

用户现场截图：左上角是两行 "PicoAide / Harness"。实测数据：`rowText` 是
`"PicoAide Harnessv2.6.9-beta.3"`、行高 **48px**、`/api/pico/channel` 载荷的 `client`
里**没有 `short_name`**。

1. **显示的是显示名而不是短名**：`client.short_name` 是**随包品牌独有**的字段 ——
   服务端 `channel.Response` 里没有它，而 `/api/pico/channel` 在"有会话"这条路径上把
   服务端载荷**原样透传**，短名于是整条丢失，`resolveClientShortName` 回落到显示名
   "PicoAide Harness"。同一个端点在没有会话时返回的随包品牌里明明带着短名（注释也
   写着"服务端不下发这一项，所以由随包品牌补上"）—— 缺的就是叠加那一步。渠道化重构
   之前是硬编码 `name === 'PicoAide Harness' ? 'PicoAide' : name`，重构后改靠 short_name，
   于是**最常见的"服务端可达"路径**丢了短名。
   修：出口改为 `mergeChannel(builtInChannel(brand), 绝对化后的服务端载荷)`，与
   `channel-sync` 同一口径；服务端有值的字段仍然胜出。
2. **定高行里没有截断**：上游 `ui-sidebar` 的 `.brandName` 是 18px 字号 / **24px 定高**
   的行，名字元素此前只是 `inline-flex`，长了就折行。
   修：名字固定单行 + `text-overflow: ellipsis`（父级 `min-width: 0` 让 flex 项肯收缩），
   版本徽章 `flex: none` 不被压掉，全名挂 `title` 供悬停查看。

顺带修掉两处同源漂移（都由这轮新增的测试照出来）：

- `auth-gate` 里另有一份"随包品牌 → 渠道内容"映射（`resolveBrand` + `builtInChannel`），
  与 `channel-content.ts` 的 `brandChannel()` 在"渠道只配了 `login.short_name`"时给出
  **不同短名**。端点现在直接用 `brandChannel()`（单一实现），登录页那份的 client 短名
  也补上 login 回落，两者同序。
- `client/Channel.tsx` 自己有一份**不 trim** 的 `nonEmpty`：`short_name: "   "` 会被当成
  有效值 → 侧边栏渲染成空白。改为复用 `channel-content.ts` 的 `nonEmpty`。

## 二、文档

`docs/planning/2026-09-10-channel-package-reference.md` 新增 **§4.3 服务端不下发的字段
（`short_name`）与侧边栏品牌名**：哪些出口必须叠加随包品牌、映射只能有一份实现
（`brandChannel()`）、上游侧边栏那一行是 24px 定高（长了必须截断而不是折行）、判空
口径只有一份（`nonEmpty` 带 trim）。
