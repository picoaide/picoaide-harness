# v2.8.1-beta.2

> 预发布版本（beta 渠道）。本版**只有服务端与客户端网关链路的变化**，无数据库破坏性改动、无客户端界面改版。

## 谁必须升级

- **所有经网关调用模型的客户端**（桌面客户端 / 第三方 OpenAI·Anthropic 兼容客户端）：
  本版修掉了一个会被用户直接看到的问题 —— 大请求体在慢链路上被服务端误判成 `400 请求体格式错误`（且客户端按"不可重试"处理）。
- **使用图片 / Files API 的部署**：本版补上了 Files API 直通与**文件归属隔离**。
- **服务端管理员**：本版新增「网关文件」页与三个可在后台调整的网关数值。

## 修了什么

### 1. 请求体读超时不再误报 400（本版起因）

现场现象：会话日志里出现 `请求体格式错误`，且同一张图/同一段长上下文反复失败。

根因：服务端全局 `http.Server.ReadTimeout=60s` 同时罩住了"读请求头 + 读请求体"，长上下文、多工具 schema 或带图片的请求体在慢链路上读满 60 秒被截断，网关只看到"读失败"就回了 `400 VALIDATION` —— 而客户端把 400 归类为**不可重试**。

现在：

- 读请求体的时间预算按路由放宽到 **1 小时**（与 slowloris 防护解耦）；
- 读超时返回 **`503` + `code=SERVER`**（客户端按可重试处理），只有真正读失败才 400。

### 2. 容量与限流对齐官方口径

- 请求体上限：chat / FIM / messages / responses 各 **64 MiB**（原 16 MiB），embeddings 4 MiB；文件上传 64 MiB。
- 网关限流缺省改为 **0 = 不限制**（官方只限账号级并发、不设请求速率上限）；并发仍由每用户 in-flight 闸门兜底。
  ⚠️ **升级注意**：老库里已保存的 `gateway.rate_limit=60` **不会被代码缺省覆盖**，要按官方口径放开需在「网关」页把它显式改成 0。

### 3. Files API 直通 + 文件归属隔离

- 新增 `/v1/files`（含无 `/v1` 变体）：上传 / 列表 / 取元数据 / 删除，直通官方上游。
- 上游按 **API key** 划分文件，而全组织共用一把 key ⇒ 网关自己记归属：**列表只回自己的文件**，他人的 id 一律按"不存在"处理，**聊天里引用他人 `file_id` 直接 404**（不泄露存在性）。

### 4. 文件保留上限与自动回收

- 新设置 `gateway.file_expiry_days`（缺省 **7 天**，1~30 可配）：上传时网关**重写 `expires_after`**（没带就补、超过上限就收敛），台账侧再收敛一次；超期由**回收器**每 5 分钟在上游删除（上游配额是每 key 25 GiB / 10000 文件，全组织共享）。
- 回收采用**标记认领**：进程中断也不会留下"永无凭据"的上游对象。

### 5. 后台新增「网关文件」页

按员工看占用（文件数 / 字节 / 其中已过期 / 最早过期），支持按员工过滤、`file_id` 搜索、排序与分页；单条删除 + 按条件批量清理（危险范围要求输入确认词，全部动作写审计）。

### 6. 出站请求体的安全与稳定性

- 按员工注入官方用户标识（chat `user_id` / responses `user` / Anthropic `metadata.user_id`），覆盖客户端自带值；
- 请求体不是合法 JSON 对象 ⇒ 本地 400（不再"解析失败就原样转发"）；
- 新增进程级**在飞请求体字节**闸门（缺省 128 MiB，可配），打满返回 `503` 可重试；单请求 `file_id` 引用上限缺省 **600**（对齐官方"单请求最多 600 张图"，可配）。

## 升级步骤

1. 取镜像包：`https://release.picoaide.com/beta/releases/2.8.1-beta.2/picoaide-server-2.8.1-beta.2-amd64.zip`
   同目录 `SHA256SUMS` 可比对哈希；GitHub Release 亦附 `SHA256SUMS`。
2. `docker load` 后**按运行容器的 image id 重打渠道 tag** 并写回该栈 `.env`（同机多栈必须这样，归档内 tag 恒为版本号）。
3. `docker compose up -d server`，健康检查 `/healthz` 返回 200。
4. 本版**无新增数据库迁移**（schema 仍为 0079；若从更早版本升级，迁移会自动应用）。
5. 客户端不做强制升级：本版客户端与上一版行为一致，服务端改动对旧客户端透明。

## 回滚

改回 `.env` 里的 `SERVER_IMAGE`（上一版 `beta-2.8.1-beta.1` / `beta-2.8.0`）+ `docker compose up -d server`。
本版无迁移、无数据格式变化，回滚不需要恢复数据库。

## 已知残留（不影响使用，已在文档记录）

- 上游删除对象与台账收尾之间存在一个极短窗口：若恰好发生并发重新上传，客户端会按既有路径回落到内联图片重传；
- `chunked` 上传无法在读取前预判体量，内存闸门只能在读完后计费（带 `Content-Length` 的上传在读取前即被拒绝）；
- 调小保留上限不会追溯已落库的文件（管理员可在「网关文件」页按员工清理）。
