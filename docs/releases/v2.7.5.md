## 一、内置浏览器：交给用户操作之后，AI 不再整轮超时

- **现象**：AI 把浏览器控制权交给用户去登录（`browser_takeover`）后，用户登录完在聊天里说
  "我已经登录"，但没点浏览器窗口里的「交给 AI」；此后 AI 的每一次浏览器操作都**卡满 30 秒**
  然后报一句"工具调用超时"，连续十几次、耗时几十分钟。用户与助手都以为"页面卡死了"。
- **影响**：任何需要用户手动登录一次的任务（网银、内部系统、需要短信验证码的站点）都会
  烂尾；助手的重试还会持续消耗时间与配额。
- **修复**（三条一起做，缺任一条都会再次出现同样的现象）：
  1. **预算序关系**：闸门等待预算从 300 秒收到 10 秒，且"闸门 + 余量 < 工具总预算"成为
     硬约束——此前闸门预算比工具预算长，工具内部再清楚的错误也会被整体超时覆盖掉；
  2. **控制权状态三面可见**：拒绝理由统一为"用户正在操作浏览器，请在浏览器窗口点『交给 AI』
     后重试"；`browser_list_tabs` 输出控制权状态；侧边栏浏览器入口着色并提示"AI 正在等你
     交还浏览器控制权"——用户回到聊天窗口时原本没有任何提示；
  3. **关窗/切会话即复位**：关闭浏览器、切换会话或清理数据时同步交还控制权，不再残留"AI
     以为用户还拿着"的状态。
- **自证**：回归用例覆盖预算不变量与三个可见面；把闸门预算改回 300 秒、去掉提示或去掉状态
  记录，对应用例即失败。

## 二、内置浏览器窗口不再自己弹到前台

- **现象**：AI 在后台操作浏览器时，用户切到别的窗口，浏览器窗口过一会儿又自己弹回来；
  最小化后也会自动弹回，像被强制置顶。
- **根因**：两条"抢焦点"路径——蒙版夺键盘的动作**无条件**执行（而蒙版是默认状态，AI 每次
  操作、接管与窗口重排都会触发它），以及窗口重排时用"移除再添加"的方式把视图抬到最上层
  （系统在激活视图时会顺带激活它的顶层窗口，Windows 上还会把最小化窗口恢复）。
- **修复**：所有夺键盘的动作先判断"窗口真的在前台"（可见、未最小化、有焦点）；用户自己
  把窗口带回前台时补做键盘上锁（AI 忙时挡住用户误操作的设计不退化）；窗口重排不再重排
  已挂载的视图，层序只保留两条不变量（新挂载的视图在最上、蒙版永远在最上）。
- **自证**：真机实测（真实适配器 + 真实运行时）切标签/关标签/改变窗口大小/会话重排触发的
  原生"抬到最上"调用从各 2 次降到 **0 次**；后台状态下蒙版抢焦点 0 次且窗口保持非前台。
  回归用例 12 条，去掉任一闸门都会失败。

## 三、macOS：记忆写不进去、菜单栏只剩一个方块

- **记忆写不进去**：macOS 客户端上记忆模块完全无法写入（路径与权限处理缺陷），且一个损坏的
  状态文件会让**整个客户端起不来**。本版修掉写入路径，并把记忆模块的失败降级为"该模块不可
  用"，不再阻塞启动。
- **菜单栏图标**：macOS 菜单栏此前只显示一个实心方块（浅色菜单栏是黑方块、深色是白方块），
  看不出品牌 mark。原因是模板图把"品牌底板 + mark"整张图直接缩放：系统对模板图只取透明
  通道当遮罩，底板不透明 ⇒ 遮罩就是整块方块，mark 在数学上不可能显示。本版为 macOS 改用
  **只有 mark、背景透明**的模板图；Windows / Linux 的彩色托盘图标逐字节未变。
  渠道素材若"方块之外没有 mark"会在构建期直接失败，不再产出一个看不见的图标。

## 四、客户端错误监控：从此真的收得到

- **现象**：界面里真实发生的报错从未被采集，而链路正常时管理后台同样一片空白——问题可以
  无声无息地存在很久。
- **修复**：错误采集在客户端真实生效（含渲染进程的未捕获错误），管理后台可以看到客户端
  上报状态；`error_reporting_enabled` 关掉即不再上报。端到端自动化里补了两条"真实激活"
  断言：摄取端必须收到登录后的新增事件、且必须收到一条带渲染进程标记的、本次一次性标记
  的真实未捕获错误——监听装错执行上下文时用例失败。

## 五、客户端多语言补齐

- **现象**：中文之外的界面语言下，弹窗、面板、预认证页面、内置浏览器窗口仍有大量中文。
- **修复**：补齐客户端侧约 550 条硬编码文案（记忆模块 / 内置浏览器 / 登录与恢复页 /
  连接器 / 定时任务 / 桌面与品牌），并确立宿主侧语言来源的唯一入口（用户应用内选择 →
  请求语言 → 产品默认），按请求解析、不冻结在模块加载期。中文文案逐字保留（与改前
  diff 为空的部分经逐行核对），并新增字典卫生守卫防止再退化。

## 六、连接器：令牌刷新后不再被"授权已失效"打死

- **现象**：连接器在后台刷新过一次令牌之后，下一次请求报错并降级为"需要重新授权"。
- **影响**：任何实现了刷新令牌**轮换 + 复用检测**（RFC 6749 推荐行为）的授权服务器上，
  一次后台刷新之后的 401 就会打死该连接器。本仓 CI 也正是以约一半概率被这条竞态打红。
- **修复**：带外刷新完成后把新凭据**回灌到活着的传输**（此前只写磁盘，传输仍持已被消费的
  旧令牌），并补"注册期间落盘的刷新"追赶路径；一个连接器有多个 HTTP 端点时逐个回灌，
  句柄只在传输真正加载成功后安装。回归用例是确定性的（不靠赢得竞态），删掉回灌调用即失败。

## 七、内置工具自检报告的三项修复

- **截图卡住时说得清卡在哪一步**：两条抓帧路径现在受同一条预算约束（原生抓帧 + 渲染器
  兜底 + 余量 < 工具总预算），任一路径卡住返回自带原因的失败，而不是笼统超时。
- **定时任务可以真正删除**：助手新增删除能力（与界面同一删除动作、同一权限口径）；
  看不见的任务按不存在处理；**正在执行的任务拒绝删除**。
- **Windows 沙箱无法授权时给出原因与出路**：某些工作区（非本账户创建、网络驱动器、
  目录联接/符号链接、云同步占位、非 NTFS、被安全软件保护）拿不到写权限，此前只有一行
  `SetNamedSecurityInfoW failed (Win32 5)`。现在补上成因与两条出路（换本地 NTFS 目录，
  或该会话使用完全权限预设）。**没有做静默降级**：拿不到写权限就不放行写入。

## 八、回归审计：数十条确认缺陷

相对 v2.7.4 的改动做了一轮多代理的对抗式回归审计（每轮"审计 → 独立复核 → 修复 →
新代理再证伪"，直到一轮零新发现），确认并修复的缺陷按面归类：

- **安全**：登录页占位符二次展开（渠道配置含占位符时可在未认证页面注入属性与脚本）；
  凭据注入的拒绝文案不再回显被观测站点的地址（原文与脱敏投影都可能漏出口令）；
  错误上报自检端点的失败详情不再回显目标响应片段与内网地址（该端点此前可被当作内网
  端口扫描器），失败原因只进服务端日志，每次自检留审计记录；LDAP 目录绑定口令在落日志
  前先擦除，并补**连接期**地址复检（此前存在"检查后用域名再解析一次"的窗口）。
- **浏览器**：槽位等待预算取自统一预算表；站点闸门按原始地址比对（口令落在主机名时不再
  永久误拒）；截图后的接管检查点进入控制权状态（侧边栏因此能提示）。
- **记忆模块**：会话查询参数被语言前缀误伤、分支开关在三个界面失效、技能目录同步改为
  "旁边暂存 → 原子交换"（失败可回滚、崩溃残留会被回收）、角标计数不再每次重挂面板。
- **服务端与管理后台**：错误上报 DSN 的校验面与随包 SDK 的可解析面完全对齐（145 条共享
  语料、8101 条自造输入对拍零分歧）；网关页保存不再被历史空 DSN 永久挡死；错误上报状态
  清洗控制字符；能力中心下架的组织内容对管理员同样隐藏；定时任务扫描窗口按调度形态
  取值（此前的固定值把合法的复合表达式判成"几十年内不会触发"）。
- **判别力**：13 处"测试不可能失败"的断言缺口补齐；门禁前门在参数写错时会假绿的问题
  改为直接失败；新增两个静态守卫（守卫总数 9 个）。

## 九、管理后台：写面闸门与"数据到达前"的显示

- **余额发放策略卡**在数据到达前就渲染出可写控件，此时点保存会把**空额度当成 0 提交**，
  等于一次误清空——现在加载未完成时输入与按钮全部禁用，失败也不再有"静默成功"的假象。
- **客户端上报状态**计数块此前无条件渲染 `0 台`，数据到达前先闪一遍"一切正常"的误导性
  数字；现在加载期间只显示"加载中"。
- **网关「全局设置」**与**错误监控配置**：读取失败时页面此前仍会解锁写面，此时点保存会把
  **空初值当成新配置**提交——网关页会清空默认模型与峰谷计费窗口，错误监控页会**关掉错误
  上报并抹掉已配的 DSN**。现在两者的解锁条件是"配置真的读到了"（只有成功才解锁），失败时
  写面整体锁定并说明原因。
- **共享授权对话框**：授权列表还没读到时页面会显示"未授权（所有用户均不可见）"且可以保存，
  一次点击就把该资源的**全部部门授权清空**；现在列表未落地时不给这个假状态、并锁住保存按钮
  （商城页原先另有一份同样的实现，已合并为同一个组件）。此外，连续查看两个资源时不会再出现
  "展示着上一个资源的授权、却把撤销发给当前资源"的窗口——切换资源即刻清空上一份授权。
- **能力中心**行内操作在途时不置灰、点击被静默吞掉（"点了没反应"）已修。
- **用户/部门列表**在加载期间不再渲染空表与"共 0 人"；**审计日志**不再在首帧说"暂无审计记录"，
  保留策略落地前也不允许编辑（此前管理员刚输入的天数会被落地值覆盖）。
- **错误上报自检**的失败分类补齐三种情形：被出站护栏拦下（含运行期解析到内网地址的情形）、
  上报服务要求重定向、自检请求被中断——不再一律显示为"未知故障"。

## 十、升级与回滚

- **服务端**：从更新服务器取本渠道镜像包
  `https://release.picoaide.com/<channel>/releases/2.7.5/picoaide-server-2.7.5-amd64.zip`
  （`<channel>/latest.json` 是更新清单），按 `docs/deploy/AI-DEPLOY.md` 升级：
  **升级前必须备份**数据库与数据目录；使用明确版本号，不要使用 `latest`，不要 `down -v`。
- **客户端**：随服务端镜像分发。服务端升级后，员工从自己登录的服务器门户（`/` 或
  `/portal`）下载安装包，或由应用内更新提示升级，无需访问外网。
- **回滚**：保留上一版镜像标签，改回并重启 `server` 即可。本版新增的迁移是**加表**（客户端
  错误上报状态），旧版本二进制不会读写它，因此回滚到 v2.7.4 不需要回退数据库；若确实要
  回退，请按 `docs/deploy/AI-DEPLOY.md` 的备份恢复流程整库恢复。
- **从预发布版升级**：本版相对 beta.5 另有若干修复（见上表），升级方式与常规一致。

## 附件与校验

- `picoaide-server-2.7.5-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS`，再解压载入。

## 已知边界（本版未改）

- 截图在"渲染器完全不产帧"的极端环境下仍可能失败——本版保证它说清卡在哪一段并给出
  可操作建议，而不是给一句笼统超时。
- Windows 上某个工作区为何被拒绝授权，取决于该目录的归属与形态，需要现场用 `icacls` /
  `fsutil` 确认；本版不改变"授权失败即拒绝启动沙箱"的判定。
- 需要在浏览器里手工登录的任务，仍然要求用户在浏览器窗口点「交给 AI」把控制权交回；
  本版做的是让这件事在聊天窗口里可见、可理解，并让失败立刻说清原因。
