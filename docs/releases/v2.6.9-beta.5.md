## 一、员工余额（0061，新功能）

余额是**存量金额**（元），与原有 `quota_money` 的「月度流量上限」正交：

- **管理员手动调整**：用户管理列表「余额」按钮 → 增加 / 扣减 / 设为，可填备注（写审计
  `balance_adjust`）；扣减不能超过当前余额。金额输入支持数字键盘、快捷金额（±10/50/100/500）、
  实时「调整后余额」预览、超额红字并禁用提交。
- **每月自动发放**：服务端调度器每小时检查，每个北京月只执行一次（`balance_grants.month`
  主键幂等，跨实例/重启/重入不重复加钱），停机跨月后启动补发；范围 = 启用中的普通员工。
  发放方式可配：
  - **增加**：当前余额 + 月额度；
  - **覆盖**：余额重置为月额度。
- **保存即补发**：开启闸门并保存「额度 > 0」时，若本月尚未发放会立即自动补发一次，
  消除「保存设置 → 下一个调度 tick」之间全员 0 余额被拦的窗口；本月已发不重复。
- **网关闸门**：开关默认关闭（避免存量部署升级瞬间被拦）。开启后余额 ≤ 0 的员工调用 AI
  返回 429；消费与 `usage` 写入**同事务原子扣减**（微元精度，流式回填只扣差额）。
- **员工端**：`/api/client/v2/auth/usage` 下发 `balance_money/balance_enabled` 等字段，
  客户端账户卡在开启闸门时以余额为主数字展示。

管理入口：**用户管理 → 月度余额发放**（闸门开关 / 增加-覆盖 / 每人每月额度 / 立即发放本月 /
本月与最近发放记录 / 全员余额合计）。

## 二、审计修复（F1–F21）

按严重度摘录：

**P1**
1. **CSRF 与会话同寿命**：token 改为会话绑定 HMAC，CSRF 失败返回独立错误码，webadmin
   自动续期并重试一次——不再出现"挂机 2 小时后所有保存 403"。
2. **认证配置热更新**：启用/禁用 LDAP、OIDC 路由动态解析，保存即生效，无需重启（此前
   启用不生效、禁用后仍可登录）。
3. **组织树缓存与环检测**：部门/组/成员写路径主动失效缓存；树遍历全部加环保护——修复
   "30s 窗口内可造环 → 网关配额热路径死循环"的组合缺陷。
4. **流式断连计费**：客户端断开后继续 drain 上游直至拿到 usage chunk，否则按已转发内容
   估算回填——不再"中途断开免费"。
5. **本地文件服务越权面收敛**：`/sidebar/file` 的 html/svg 强制下载或 sandbox；cwd 覆盖
   只对已挂载会话生效；memory-evolve 技能管理 API 增加 loopback+Host+Origin 栅栏
   （并支持 `webRuntime.trustedHosts` 局域网权威）。
6. **配额口径**：余额作为硬预算；月度 token/金额/部门预算仍是软上限（页面已标注）。

**P2/P3 精选**：用户名字大小写全链路 nocase（含授权比较）；provider `base_url` 的
SSRF/metadata 防护（保存校验 + 全部出站 client 的 Dial 复检）；usage 分区清理的孤儿表
识别与错误上抛；deep link 会话切换拒绝；TOFU 证书接线（系统 CA 放行 + `PICOAI_TLS_PINS`）；
审计哈希链批量写入；LDAP 停用对账分页；登录限流跨入口共享并按 DB 隔离；创建用户原子化；
`preOrderNodes` 森林修复；go.mod 依赖标记修正。详见
`docs/decisions/2026-09-11-balance-and-audit-fixes.md`。
