# PicoAide Harness v2.5.8（2026-09-01）

本版本是一次**全项目质量审计修复发布**。我们沿着用户反馈（技能卡描述截断、安装失败）对四个领域做了系统性排查——客户端交互层、宿主 TS 层、Go 服务端与 webadmin 管理端、跨系统配合——共发现并修复 **44 项缺陷**（原始审计 33 项 + 依据问题模式深挖的同类问题 11 项），其中高危 4 项、中危 21 项、低危 19 项。所有修复均通过完整回归验证（详见「验证」）。

---

## 一、用户可见的高危修复（最值得关注）

### 1. 能力中心「我的」分区上传按钮永久卡死 🔴
- **问题**：任何一次装/卸/传动作后，`action` 状态停留在终态从不复位，`upload()` 的并发守卫会把「我的」分区的上传/重新上传按钮**永久锁死**——被拒后想重传必须重启应用。
- **修复**：守卫只拦截进行中的动作（与安装/卸载一致），终态不再阻断后续操作。

### 2. 管理后台统一审批「授权」弹窗 404 🔴
- **问题**：审批队列下发的 `base_path` 含版本段（`/shared-skills/:name/:version`），而授权是**资源级**路由（仅 `/shared-skills/:name/grants`）——前端把版本化路径直接拼给授权端点，段数不匹配 → 全部授权操作（列表/保存部门/单用户授权）404 不可用。
- **修复**：服务端审批行新增 **`grants_base`**（name-only 授权基路径），前端授权弹窗改用该字段；approve/reject/delete/preview 仍走原有版本化 `base_path`。两端补了断言测试。

### 3. 浏览器接管机制死锁（AI 无法恢复操作） 🔴
- **问题**：`ControlMutex.take()` 非幂等——遮罩接管后 1 秒内再点 shell「接管」会覆盖 release 承诺，**停泊的 agent 操作永不唤醒**，其后所有浏览器工具调用排队在一个不会结束的 Promise 后面（整面功能死锁，且 UI 显示已释放）。
- **修复**：`take()` 幂等（已接管时保留现有承诺）；`closeAll(user)` 保存并还原接管前状态（清除/切号不再静默解除用户接管）。

### 4. 深链登录会话劫持与日志注入面 🔴
- **问题**：`picoaide://auth` 深链的 token 被**无条件**写入会话（注释声称"bootstrap 时验证"，但攻击者可控网关可返回合法 bootstrap）；用户名/服务器串未消毒进日志；server 尾斜杠未归一会在模板拼接处产生 `//api` 404。
- **修复**：接受前先以该 token 调 `/auth/me` 预验证（失败即拒绝）；日志 `JSON.stringify` 消毒；serverURL 去尾斜杠并与 `fetchJSON` 归一行为对齐（5 处模板拼接统一 `normalizeServerURL`）。

## 二、用户可见的常规修复

### 能力中心 / 技能市场
- **卡片标题恢复中文显示名**：host 代理下发 `display_name`（snake）而客户端读驼峰 `displayName`，导致所有卡片标题恒等于英文技能名、搜索按标题不命中、跨源归并失效——出口统一映射修复
- 「我的」分区**错误态失效**（`loadSection('mine')` 写入与渲染读取的 key 不一致）：加载失败曾静默显示空列表且无重试，现已能看到错误+重试按钮
- 描述「点击展开全文」支持**键盘访问**（角色/焦点/Enter 触发，此前纯鼠标）
- 30 秒后台轮询刷新成功后自动退出错误态（此前错误提示会遮住已刷新的数据）

### 登录与深链
- **OIDC/OpenID 浏览器授权**：返回 Step1 或授权超时（5 分钟）后按钮复位、轮询停止，不再只能重启应用
- 登录页品牌 logo URL **属性转义**（XSS 面修复）
- `auth/state` 快照单次读取（消除并发登出时 `loggedIn:true` 但用户名为空的不一致）

### 定时任务
- 编辑已有任务**不再静默重新启用**已停用任务（旧逻辑 `if(!enabled) enable()` 会悄悄反转用户意图）
- 编辑对话框的执行内容字段（提示词/工作区/预设/权限）**只读展示 + 「不可编辑」提示**——此前字段可编辑但保存被静默丢弃（假象丢弃）
- 执行提示词改为**行内展开**（替换阻断式 `window.alert`）；编辑按钮补 aria-label

### 连接器
- 面板 2 秒轮询失败**保留旧数据 + 错误提示**（此前瞬时抖动即把已连接卡片清成空态）
- 卡片描述悬浮显示全文
- 模态对话框加 **Tab 焦点陷阱**（与能力中心一致）
- OAuth 失败路径清理 timer/监听（5 分钟残留）；多流程竞态按身份删除（取消/停止恢复可用）

### 账号卡
- 进度条 `aria-valuenow` 钳制到 0–100（超配额时不再报非法值）
- 「无限额度」语义区分：管理员「管理员」、普通用户「无配额限制」

### 其它
- 侧边栏与设置页的更新提示**合并为单一份订阅**（消除 30s + 5s 双份轮询同一端点）
- 浏览器标签页的权限/下载守卫 **disposer 随 tab 释放**（多次开关后不再一次下载弹 N 个保存框）
- 品牌配置在插件热重载（HMR）后仍能收到服务端变更推送
- webadmin：审批 tab 徽章计数改为独立全量数据（此前其它状态徽章恒为 0）；商城卡片描述悬浮全文

## 三、服务端 / 契约 / 安全

### 归档与安装（延续上一版本 zip 化的同类补漏）
- **商城 git 构建上限对齐 16MB**（此前 100MB 产物服务端正常下发、客户端任何版本都装不上）
- **zip 解压读取加 `LimitReader`**（防"小声明 + 高压缩比"的 zip 炸弹在管理端预览时 OOM）
- **绝对路径校验补齐 Windows 形式**（`\etc`、`C:\x` 此前被归一成相对路径放行）：TS zip/tar 分支 pre-normalize 检查 + Go `NormalizePath` 对称收紧，并保留 `./` 根目录条目放行
- TS/Go 归档**条目数上限对齐**（10000）

### 数据一致性
- 共享技能 / 共享智能体**重提改为单条原子 UPDATE**（metadata+checksum+archive+status 一条语句）——消除此前"行已置 pending 但归档仍旧"的两步脏窗口

### 日志安全
- 6 处 LLM 网关日志对用户可控模型名**脱敏**（截断 40 字符 + 长度标注，原先 `%q` 只防换行注行）

### 会话持久化
- `loadPersisted` **跨 safeStorage 后端双格式回退**（有 keyring ↔ basic_text 切换不再丢会话被迫重登），并删除了引用不存在函数 `loadLegacyEncrypted` 的误导注释

### 测试与 e2e
- e2e mock gateway **删除 3 个服务端无声明的死路由**（`/models`、`/config/models`、`/auth/session`）+ 职责注释（防未来客户端改调这些路径时 e2e 全绿但生产 404）
- `verify-profile-boot` 冒烟断言**同步 `ui-settings-plugins` 禁用**（此前该行回归冒烟仍绿）
- 4 处登录 e2e 断言硬编码旧品牌名 "DeepSeek Harness" → 改为 `includes('PicoAide')`

## 五、部署与升级

- **客户端**（三平台）：mac DMG / win x64 Setup / linux AppImage，附 SHA256SUMS 校验；客户端内升级源指向本版本
- **服务端镜像**：`ghcr.io/picoaide/picoaide-harness-server`（`v2.5.8` / `latest`）
- **注意**：本版本含服务端与 webadmin 的契约变更（审批行新增 `grants_base` 字段），**授权功能需要 webadmin 与服务端同步升级**；旧客户端的其余功能不受影响，但管理端「统一审批 → 授权」入口在任意一端为旧版本时不可用（404），建议一步到位同时升级服务端镜像与 webadmin
