# v2.7.4（2026-09-15）

> 一句话：修好两个最影响日常使用的问题 —— 桌面客户端的「复制」按钮全线恢复可用、
> 内置浏览器的「我来操作」（人工接管）全面可用；并修掉连接器、定时任务与企业账号的一批缺陷。
> **所有客户端建议升级**；服务端仅版本号随镜像更新，**无数据库迁移**。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 正式版 |
| 升级建议 | **必须升级**（v2.7.3 及更早版本：复制按钮不工作、内置浏览器人工接管在多数启动路径下不工作） |
| 影响面 | Windows · macOS · Linux 客户端；管理后台界面与对外接口无破坏性变更 |
| 产品代码变化 | 有（相对 v2.7.3：桌面壳、内置浏览器、连接器、定时任务、企业插件） |
| 数据库迁移 | 无 |

## 一、「复制」按钮恢复可用

- **现象**：鼠标移到任意一条消息、代码块、diff、终端输出或 JSON 视图上点复制图标，
  没有任何反应 —— 图标不会变成"已复制"，粘贴出来也是空的。
- **影响**：客户端里**所有复制入口**都失效，只能手工拖选文字。使用 v2.7.3 及更早版本的
  Windows / macOS / Linux 客户端都会遇到。
- **原因**：客户端窗口统一安装了"默认拒绝一切浏览器权限"的安全策略，这套策略把
  **剪贴板**一起拒掉了；而桌面运行时对"用户真的按在按钮上"与"脚本触发"这两种情况
  报的是两个不同的权限名，只放行其中一个时会出现"自动化测试通过、真人点击仍被拒"。
- **本版怎么修**：两个权限名都放行，且**只对本客户端自己的界面文档、只在顶层文档、
  只放行剪贴板这一个权限**。摄像头、麦克风、定位、屏幕共享等其余权限，以及内置浏览器里
  打开的第三方网页，全部维持原来的拒绝策略。
- **自证**：在打包客户端上用真实登录 + **真实鼠标点击**跑端到端：点击复制按钮后读回
  剪贴板内容与目标消息一致；三条约束（权限名 / 来源 / 框架层级）与反向对照（只放行一个
  权限名时用例必红）都写成了自动化用例。

## 二、内置浏览器的「我来操作」全面可用

- **现象**：内置浏览器里点右下角胶囊上的「我来操作」没有任何反应 —— 页面仍停在锁定状态，
  既不能自己点页面、也不能用地址栏，只能继续让 AI 操作。换会话或重启客户端有时又正常。
- **影响**：内置浏览器的人工接管在**多数启动路径**下整轮失效；同时"接管"本身也没有真正
  暂停 AI 已经在跑的操作，用户和 AI 可能同时操作同一个页面。
- **原因**：这是三个独立缺陷叠加 —— ①承载接管入口的那层控制界面在登录后没有跟着账号
  切换，它的操作请求被判"没有权限"而拒绝；②最常见的"开机即已登录"路径上，把操作凭证交给
  浏览器界面的那一步只在启动瞬间尝试一次，此后不再重试，于是凭证一次都没送达；
  ③人工接管只锁界面，没有中止 AI 已经启动的页面加载与写入。
- **本版怎么修**：控制界面跟随账号切换并在清理浏览器数据后重建；凭证交接改为"没就绪就
  按 1 秒→2 秒→…→30 秒退避重试，直到成功一次为止"；用户接管时中止 AI 已启动的页面加载，
  长操作在下一个协作检查点以"用户已接管"失败退出。
- **同批**：删除书签、删除下载、清除站点数据等会改状态的操作重新纳入同一把用户闸；
  接管按钮的请求增加超时，接口卡死时不会永久禁用按钮。
- **自证**：把三条路径在本地原样复现（含"反复启动、开机即登录"）并逐条对照修复前后行为；
  随后用真实服务器 + 真实账号 + 真实点击跑完整端到端（接管 → AI 操作确实暂停 → 交回 →
  AI 继续 → 复制可用），相关状态机与闸门均配自动化回归用例。

## 三、连接器（MCP 工具接入）

- **重启后恢复**：以 API Key 等"表单字段"为凭据的连接器，重启后不再被当成未连接；
  必填字段齐全即自动恢复工具。
- **先填设置再授权**：带"接入设置"表单的 OAuth 连接器，提交设置后会继续真正的浏览器授权，
  不再直接注册一个没有授权的连接；token 模式也不会跳过必填表单。
- **断开更可靠**：断开与后台注册的竞态已消除，断开后不会再有旧注册把工具"复活"。
- **目录更稳**：服务端下发的连接器目录会校验认证模式与凭据字段名，缺字段不再导致设置面板
  搜索崩溃；OAuth 发现支持带路径的签发方，目录拉取增加超时，表单默认值正确预填，
  畸形提交返回 4xx 而不是 5xx。

## 四、定时任务

- 权限预设下拉改为读取本机部署的权限名单，不再硬编码；选到不存在的名称不再得到无法理解的失败。
- 设备长时间休眠/关机后的补跑取**最近一次**错过的触发，而不是很早以前的一次。
- `*/n` 形式的工作日/日期语义与标准 cron 对齐（`0 0 */1 * 1` 表示每周一）。
- 登录态恢复型启动时，定时任务正确绑定当前账号。

## 五、企业与账号

- 重启后自动恢复的登录会话会正确同步模型网关配置，不再需要"再登录一次"才恢复。
- 退出登录失败时不再刷新页面假装已退出；失败会显示原因，登录状态保持不变。
- 账号卡与关于页的状态、货币格式跟随当前界面语言。

## 六、同批安全与健壮性加固

- 内置浏览器的控制权只由用户决定：模型工具不能再自己关掉用户闸，交接只能由用户点
  「交给 AI」完成；会话切换时不再残留"锁在用户手里"的状态。
- 浏览器快照、日志与审计行统一脱敏：URL 与页面文本里的凭据不再以明文落盘或回传模型，
  超长密钥先掩码后截断。
- 书签/历史等本地账本改为原子写：磁盘读失败不再被当成"首次运行"而覆盖既有数据，
  损坏文件改名保留并告警。
- 浏览器写操作失败不再静默：界面就地提示（未授权 / 无权限 / 服务不可用 / 网络错误分别给文案），
  不会出现"点了没反应但状态已变"。
- 安装包按实际解压体积做上限校验，降低恶意压缩包导致客户端内存耗尽的风险。

## 升级与回滚

- 服务端：从自己渠道的更新服务器取本版本镜像包（`<channel>/releases/2.7.4/`，
  同目录 `SHA256SUMS` 校验），按 `docs/deploy/AI-DEPLOY.md` 升级；**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`。
- 客户端：随服务端镜像分发 —— 服务端升级后，员工从自己登录的服务器门户（或
  `/updates/client/*`）取包，无需访问外网。
- 回滚：保留上一版镜像 tag，改回 `SERVER_IMAGE` 后 `docker compose up -d server` 即可
  （本版无数据库迁移，回滚不涉及数据格式变化）。

## 附件与校验

- `picoaide-server-2.7.4-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），
  内含本渠道的 Windows / macOS / Linux 客户端安装包；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压导入。
