# PicoAide Harness v2.6.9-beta.2（2026-09）

预发布补丁：把 v2.6.9-beta.1 在**真实部署**（测试环境从 systemd 迁到容器）中暴露出来的
问题修掉。功能面与 beta.1 相同，交付面有三处变化。

---

## 一、镜像与部署形态（实测修复）

- **镜像现在同时带 `v2.7.0` 与 `2.7.0` 两个 tag**：此前 CI 只打带 `v` 的形式，而部署文档
  §3/§6 的示例用不带 `v` 的形式 —— 照文档敲 `docker run picoaide-harness-server:<ver>`
  会去 docker.io 拉取，在隔离网/镜像代理下直接 403（实测踩到）。`docker load` 后两种写法都可用。
- **Linux 的 deb 不再进镜像**：deb 与 AppImage 是同一个应用的两种打包，员工装一个即可。
  每个渠道的镜像因此**小约 115MB**。CI 仍会构建 deb（`dist:linux` 的产物之一），只是不再
  进入任何交付面（既不进镜像，也不再作为构建产物上传）。
- **`docker-compose.yml` 透传 `PICOAI_PUBLIC_BASE_URL`**（并在 `.env.example` 里说明该配就配）：
  镜像内 compose 生成于该变量引入之前，实测在"宿主机已有共享反代"的机器上，服务端推不出
  https 地址，于是按设计**拒发**客户端下载链接（`client_unavailable`）——用户看到的表现是
  "检查更新永远说已是最新"。现补上透传，同时补 `PICOAI_LOGIN_MAX_ATTEMPTS`（测试环境便利项）。

## 二、文档

- `docs/deploy/AI-DEPLOY.md`：版本号以 `latest.json` 为准；双 tag 说明；跨境取包实测数据与
  并行取包姿势；`.env` 模板补 `PICOAI_PUBLIC_BASE_URL`；**新增附录 A：宿主机已有反向代理
  （80/443 被占用）**——含 compose override 模板、可信代理、从 systemd 迁移到容器的 6 步
  顺序与复验清单；执行清单补 3 条。
- `docs/planning/2026-09-10-r2-update-server-runbook.md` §11：跨境实测（单流 75–263 KB/s
  vs 8 路并行 ~2.2 MB/s）、可直接粘贴的并行取包脚本、两个坑（CDN 会忽略部分 Range 请求并
  返回整份响应；`pkill -f "curl.*…"` 会杀掉自己执行的脚本）。

## 三、CI 渠道信息泄露复查

- `ci-channels.sh`：构建期校验的错误信息此前会把**字段取值**拼进去（`desktop.slug(Acme-AI)`）
  —— 那正是客户品牌，而 `::add-mask::` 只掩码渠道 id。改为只报字段名与形状要求。
- `ci-build-channel-images.sh`：报错信息里的 `artifacts/<channel>` 改为只报序号（不再依赖掩码兜底）。
- "未知素材字段"告警只回显字段名形状的键（注解类键可能含品牌文案）。
- 新增回归门禁：字段取值不回显、镜像装配（无 deb + 双 tag + 清单 linux-x64 指向 AppImage）。
