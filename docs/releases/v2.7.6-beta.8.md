# v2.7.6-beta.8（2026-09-20）

> 一句话：**随包资源不再落盘** —— WASM 应用的页面/CSS/JS/图片改为运行期从内存直接响应，
> 宿主盘上不再出现"按版本抽取的资源目录"（只留各应用自己的 `app.db` 与平台编译缓存）。
> 这既是产品口径的简化，也**修掉了 beta.7 里"演示应用打不开（入口页 500）"那条阻塞级缺陷**
> —— 那正是"资源要落盘"这套机制必然带来的问题。
>
> **这是预发版（beta）**：先在测试环境验证，正式环境请等 v2.7.6 正式版。

## 一、演示应用打不开（beta.7 的阻塞级缺陷）

- **现象**：从应用中心打开内置演示应用，页面报
  「入口页读不到（包内缺 `index.html` / `index.htm`）：资源不存在：index.html」，HTTP 500。
- **影响**：三个内置演示（能力全集 / 内部小论坛 / 留言板）全部不可用。
  **员工自己发布的应用不受影响** —— 它们走的是发布链路。
- **根因**：随包资源（wasm 自定义段）原先必须"发布期抽到宿主磁盘"，而内置演示**不走发布链路**
  （服务端启动时直接播种）⇒ 它也得自己把自定义段抽出来，而它只写了应用配置，
  页面与静态资源从未落盘。这是"同一件事有两处实现"的必然结果，不是漏写一行。
- **修复**：把那件事整个删掉（见 §二）—— 于是**没有任何路径需要记得抽资源**。

## 二、随包资源改为内存直出（本版主变更）

- **变化**：wasm 的自定义段在运行期被解析成一份**内存资源集**；静态资源直出、应用
  `assets.read`、应用配置读取三条路径全部走它。宿主盘上不再有
  `<data_root>/apps/<app_id>/assets/<release_id>/` 这种目录。
- **为什么这么改（三条，都不是审美）**：
  1. **同一件事只能有一处实现**：抽段落盘原先既有发布链路一份、又有播种链路一份 —— 本次事故就是第二份漏了；
  2. **不能有两份权威**：应用配置曾在库内（`config_json`）与磁盘上各一份，得靠"一致性判据 + 半成品自愈"维持；现在库是唯一权威；
  3. **没有路径拼接就没有路径穿越**：原先要逐段拒符号链接、realpath 前缀比对、原子写防半写 —— 这些防御连同它们的判据一起消失。
- **行为不变的部分**：静态资源仍由宿主**直接返回**（不执行 wasm，带 ETag，`If-None-Match` 命中 304
  且连内容摘要都不重算）；入口页仍**由应用自己答**（先判名单再返回页面，这样不在名单里的人
  看到的是应用给的 403 页）；保留资源 `picoaide.app.json` 仍**永不直出**，只有应用自己读得到。
- **内存口径**：资源字节计入 `module_cache_mb`（该旋钮原先只算编译产物）—— 单版本资源上限
  4 MiB，与模块**同一条回收路径**（容量 LRU + 空闲回收 + 下架/冻结/删除立即释放）。
  管理端「应用中心 → 限制项」的字段名与说明已同步更新。
- **升级时的历史数据**：服务端启动时会清理历史遗留的资源目录（best-effort，逐条记日志）。
  **应用不需要重新发布**：资源本来就在库里的制品字节中，配置也在库里。
- **顺带修好**：同一个资源名在自定义段里出现两次（打包时两个源文件写了同一个目标路径）
  原先会**静默丢掉一份**，作者只会看到一个"内容不对"的页面；现在发布期直接拒
  （`ASSET_EXISTS`，错误里点名是哪几个资源），并给出改法。

## 三、内置技能口径订正（2.1.0）

- 应用构建技能里"资源在发布期被抽到宿主磁盘"的说法改为"随包资源 = wasm 自定义段，
  运行期由宿主解析后常驻内存"；`ASSET_EXISTS` 的含义与打包脚本文案同步。
- 差异**只在文档口径**，技能功能与示例代码不变；已安装该技能的员工会在客户端看到「可更新」。

## 已知限制（本版认账，未修）

- **历史资源目录清理只在启动时做一次**：清理失败只记日志、不影响启动（需要确认时看服务端日志里的
  `appserver: 已清理历史资源目录`）。
- 应用窗口内的外链落点未实现：应用里的外部链接当前一律拒绝打开（计划中）。
- 应用内 AI 的控制权交互与"按应用寻址"属下一批（计划中）；应用内 AI 的模型链路本身可用。
- **三平台只在 Linux 实测**：Windows / macOS 的窗口与静态资源行为待真机复核（计划中）。
- 运营看板趋势 UV 的长期（>90 天）保留需要新增迁移，本版未做（口径见 v2.7.6-beta.6 说明）。
- 仓库隐私守卫的覆盖面：判据覆盖**已跟踪文件与提交信息**；GitHub 的 **Release 正文**与
  **PR 标题/正文不是文件 ⇒ 不在判据内**（靠流程约束）。

## 升级与回滚

- **服务端**：取本版镜像压缩包 → 按 `docs/deploy/AI-DEPLOY.md` 升级（**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`）。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
  本版**不要求客户端与服务端同版本**（改动都在服务端一侧）。
- **回滚**（本版**无新增迁移**，属平级版本）：
  - 常规：把 `SERVER_IMAGE` 改回上一版 tag（`…:beta-2.7.6-beta.7`）+ `docker compose up -d server`。
  - ⚠️ **本版启动时会删掉历史资源目录，而 beta.7 及更早版本依赖那个目录**。因此回滚到 beta.7
    必须**同时恢复升级前的数据目录备份**（升级脚本自动生成的那份 `picoaide-data` 归档），
    否则应用会报"资源目录缺失"的 500；另一种补救是回滚后把各应用**重新发布**一次
    （旧版本的发布链路会重新把资源抽到磁盘上）。
