## 一、内存：更低的常驻、更快的释放

**谁需要关心**：把应用平台跑在小内存机器上、或者预期会有**几百个应用**的部署。

- **原来的问题**：应用编译后的产物会在服务端进程里长期缓存（缓存上限按磁盘口径给到
  512 MiB，且**只在容量超限时**才淘汰），并且释放后内存不会立刻还给系统。实测：一个
  3.45 MiB 的 Go 应用编译后常驻约 25 MB，**把模块全部关闭后 RSS 只回落约 20%** ——
  应用越多，"各用一次"就能把常驻内存顶到上限并长期占住。
- **现在**：
  - 编译模块缓存与**磁盘**缓存解耦（默认 128 MiB / 128 条，按部署可调）；
  - 新增**空闲淘汰**：超过 10 分钟没被访问就逐出，并**限频把内存归还操作系统**；
  - **事件驱动逐出**：应用下架 / 冻结 / 删除时立即释放它的模块与数据库句柄，不等超时；
  - 应用数据库句柄空闲回收从 10 分钟收紧到 3 分钟，每连接页缓存限 1 MiB。
- **小内存机器可以声明档位**：`PICOAI_WASM_MEMORY_PROFILE=small`
  （3 并发 × 64 MiB 实例 + 64 MiB 模块缓存，四笔账合计 630 MiB）。
  **不设置该变量的部署行为与之前完全一致**（默认档逐值相同）。
- **验证数据**（同一台机器，空闲 10 分钟后）：常驻从 185.9 MiB 降到 **12.8 MiB**；
  被淘汰后再次访问应用 **200**、约 270 ms（从磁盘编译缓存重建）、数据完好。

## 二、管理后台新增「应用平台」配置页

**谁需要关心**：平台管理员。位置：**运维 → 应用平台**。

- **可配置 11 项**：全局并发实例数、单应用并发、单应用队列、单用户跨应用并发、单用户
  单应用并发/排队、**单实例内存上限**、编译模块缓存上限、模块空闲回收、应用库空闲回收、
  SQLite 每连接页缓存。
- **即时生效与需重启分开标注**：除"单实例内存上限"（wazero 的运行期配置，改完需重启
  服务端）以外全部**保存即生效**；页面会明确提示哪些改动还需重启。
- **改之前能看到后果**：页面实时显示"内存四笔账"（并发 × 单实例上限 + 编译峰值 +
  上传峰值 + 模块缓存）与可用内存水位的对比；**超出水位直接拒绝保存**，不会"先跑起来
  再说"。页面还提供三档预设（默认 / 小内存 / 大内存）一键套用。
- **可回退**：一键"恢复默认/档位"即清空控制台设置，回到部署档位或编译期默认值。
- 优先级：**控制台设置 > 部署档位（环境变量）> 编译期默认**；若已保存的设置后来因机器
  变忙而超水位，服务端启动时会回落到档位并**大声告警**（而不是起不来）。

## 三、安装即带的演示应用（可删除）

**谁需要关心**：要给客户做演示的同事 —— 服务端安装完成后**无需任何上传**即可演示。

- 随镜像内置三个演示应用，覆盖三种准入模式：

  | 应用 | 准入模式 | 演示什么 |
  | --- | --- | --- |
  | 公开应用 | 匿名可达 | 不登录也能打开；未登录时不渲染任何账号信息 |
  | 登录可见 | 登录后全员可用 | 平台把身份注入请求帧（账号 / 用户 ID / 部门 / 是否发布者） |
  | 白名单可见 | 登录 + 名单 | 名单外的账号看到 403 页面**并显示本人账号**，不会误以为没登录 |

- 三个演示共用同一份程序，页面会如实显示"我现在处在哪种模式、平台给了我什么身份"，
  并在"共享留言墙"里演示应用数据库读写、在宿主能力清单里显示本次请求真实调用过的能力。
- **可以删除，删了不会回来**：管理员删除演示应用后，服务端重启不会重新播种（同一标识
  也不会被复用）。
- 不需要演示内容的部署：镜像里没有演示目录时自动跳过，不影响启动。

## 四、升级步骤

1. 取包并校验（附件 `picoaide-server-2.7.6-beta.4-amd64.zip` 与同目录 `SHA256SUMS`）：

   ```bash
   curl -LO https://release.picoaide.com/beta/releases/2.7.6-beta.4/picoaide-server-2.7.6-beta.4-amd64.zip
   curl -LO https://release.picoaide.com/beta/releases/2.7.6-beta.4/SHA256SUMS
   sha256sum -c SHA256SUMS          # 只需校验 zip 那一行
   ```

2. 按部署文档升级（备份 `.env`、数据库、数据目录 → `docker load` 镜像 → 切换
   `SERVER_IMAGE` → 重建 `server` 容器 → 健康检查）：见 `docs/deploy/AI-DEPLOY.md`。
3. **本版无数据库迁移**，升级不需要等迁移窗口。
4. 想让小内存机器启用应用子域：在 `.env` 里加 `PICOAI_WASM_MEMORY_PROFILE=small`
   （或部署后在管理后台「应用平台」页调低并发与缓存），再开启应用基域。

## 五、回滚

- 镜像回滚：把 `.env` 的 `SERVER_IMAGE` 写回上一版本（`...:v2.7.6-beta.3`）后
  `docker compose up -d server` 即可；本版**无迁移**，数据库无需回滚。
- 配置回滚：管理后台「应用平台」页点"恢复默认/档位"。

## 六、验证要点（升级后自查）

- `docker exec <server 容器> /app/picoaide-server --version` → `2.7.6-beta.4`。
- 管理后台 → **应用平台**：能看到当前值与四笔账预览，改一项并发保存后提示"已即时生效"。
- 客户端"应用中心"里能看到三个演示应用，分别按上表的准入模式访问一次（其中"白名单"
  演示默认把**首位管理员**加入名单，其他账号应看到 403 页面）。
- 服务端日志出现 `appseed: 已播种内置演示应用 …`（仅首次安装/升级后第一次启动）。
