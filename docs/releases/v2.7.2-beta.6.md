## 一、Windows 右上角：系统窗口按钮与右栏控件画在了一起

- **现象**：打开右侧栏后，窗口右上角出现两套图标叠在一起（一条横线、一个方框、一个叉，
  与分栏 / 全屏 / 收起右侧边栏的图标互相穿插），看起来像"图标糊成一团"；而右栏顶栏
  比会话顶栏高出 32 像素，两个窗格的头对不齐。
- **影响**：不只是观感。系统窗口按钮画在页面**之上**，所以那三个位置上的右栏控件
  **点不到** —— 点「收起右侧边栏」实际点在「关闭」上（有误关窗口的风险），
  「退出全屏」实际点在「最大化」上。
- **根因**：Windows 的原生窗口按钮由客户端外壳以**透明层**画在页面之上，占据窗口右上角
  一条固定区域；外壳只在主列与右列**预留**了这条区域（把内容压到它下方），而右侧栏面板的
  定位参照是**整个窗口**（普通形态）或**视口**（全屏形态），不是它自己所在的那一列 ——
  于是它绕过了预留，把自己顶栏连同控件送进了系统按钮的地盘。
- **修复**：普通形态按平台把面板顶部下移到预留区下方（Windows 32 像素 / macOS 20 像素）；
  全屏形态保持"覆盖整个窗口"的既有语义，改为把面板内容压到该区域下方。
  Linux 没有系统标题栏，行为完全不变。
- **怎么自证**：右栏自动化探针新增一条**几何**断言 —— 在 Linux 上翻转窗口的平台标识
  即可量出 Windows / macOS 的真实布局（预留区高度与面板偏移共用同一个标识），
  因此这类"只在某个平台才看得见"的缺陷现在能在常规流水线里被拦住，不需要 Windows 机器。
  打包产物实测：面板顶栏与控件顶边从 y=0/10（落在预留区内）变为 32/42，且与主列顶边对齐；
  探针 15 项全绿。

## 升级与回滚

- **服务端**：本版**服务端无代码变化**，只换客户端安装包；如按惯例升级，取本版镜像 →
  按 `docs/deploy/AI-DEPLOY.md` 操作（**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
  本版**无数据库迁移**，与 beta.5 数据面完全兼容。
- **客户端**：随服务端镜像分发，员工从自己登录的服务器取包（服务端会下发
  `client.version = 2.7.2-beta.6`）。**Windows 客户端需重装本版**才能拿到本文的修复。
- **回滚**：保留上一版镜像 tag，改回即可；客户端回滚需重装上一版安装包。

## 请复验这几条

1. **右上角不再重叠**：Windows 上打开右侧栏 —— 右上角应只剩系统的三个窗口按钮，
   右栏控件落在它们**下方**，两侧窗格顶栏对齐；
2. **按钮点得准**：点「收起右侧边栏」应是收起面板（**不是关闭窗口**），
   点「全屏」应是面板全屏（不是窗口最大化）；
3. **其余平台无回归**：macOS / Linux 上打开右侧栏，面板顶栏与会话顶栏对齐、控件照常可用；
4. 与前一版一并复验：右侧栏各标签页（含定时任务）、截图 / 输入 / 回车提交、文件搜索。

## 已知边界

- 预发布渠道（beta）自 beta.3 起使用**独立的数据目录**（与正式版分开），因此从更早的预发布版
  升级后会看到一份全新的本地配置与登录态，需要重新登录一次；这是为了避免两个世代的会话格式
  共用同一目录造成静默分叉。
