# v2.7.2（2026-09-13）

> 一句话：本版把「谁能花多少钱」从配额制换成**余额账本**，把内置浏览器收到**企业可用**的程度
> （凭据注入后进入活性窗口、出口统一脱敏），并修掉一批「可能外泄 / 可能越权 / 可能少收钱」的缺陷。
> **所有部署都应升级**；从 v2.7.1 升上来有 3 条数据库迁移（启动时自动应用，见第七节）。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 正式版 |
| 升级建议 | **建议所有部署升级**（含安全修复与计费口径修复） |
| 影响面 | 服务端镜像、Windows · macOS · Linux 客户端、管理后台 |
| 产品代码变化 | 有（相对 v2.7.1：89 个提交） |
| 数据库迁移 | 有 3 条：0061 `users.balance_money`、0062 余额账本、0063 `usage.estimated` |

## 一、余额账本取代配额与预算（管理后台变化最大）

- **是什么**：全局配额、部门预算、成员配额下线，改为**按人发放余额 + 余额账本**。每次调用先扣余额、
  写流水，余额不足直接失败（不再"先交付后记账"）。
- **管理后台**：新增「余额」页（逐人发放、流水查询、批量导入），原「配额与预算」页移除；
  「用量中心」保留，用于看用量与成本分布。
- **对员工**：账号卡只显示余额，不再显示配额进度。
- **不升级会怎样**：这一版之后的管理后台与客户端按新契约工作，混用旧服务端会出现页面与接口不匹配。

## 二、内置浏览器：企业可控

- **凭据活性窗口**：向页面注入口令后，该标签进入"活性窗口"——窗口内**禁止**脚本执行与截图
  （两者都可能把口令原样或变形后交回模型），完成一次跨文档导航后自动结束。
- **出口统一脱敏**：快照、正文、标题、地址、历史/书签、操作日志、下载名等所有出口都会把注入过的
  凭据值逐字擦除；跨源 iframe 有了正确帧索引，不再"点错帧"。
- **能力代价（有意保留）**：口令被页面**变形**渲染（base64、逐字符分隔、画成图片）时，值级擦除覆盖
  不到；这类变形仍可能进入模型上下文。若需要更严（例如注入过凭据的标签终身禁用脚本与截图），
  请提出，我们按下一轮决策处理。

## 三、Windows 客户端：MCP 连接器修回可用

- **现象**：v2.7.2 的预发布版本里，Windows 客户端连接**任何** MCP 连接器都报"出站重定向栅栏不可用"。
- **原因**：连接通道的加固自检在 Windows 上把路径分隔符判错，导致连接器被当成"加固对象不对"直接拒绝。
- **本版**：判断前统一路径写法，只有确证"加固对象是另一个文件"时才拒绝；读不到时交由实际行为校验决定。
  真正会放错加固对象的构建仍然拒绝注册（安全边界未放松）。

## 四、连接器与本地执行：服务端下发内容不再默认可信

- 连接器定义里的"凭证字段名"不能再绕过受保护的环境变量名单（此前的形态可把加载器参数注入本地命令
  **并真的执行**）；本地确认提示会列出全部将被注入的变量名。
- MCP 连接不再跟随重定向（含流式通道）：端点返回 3xx 一律按失败处理，授权码、PKCE 校验值与连接密钥
  不会因 307/303/308 被送到第二个主机。
- 回环地址口径在服务端与客户端统一；非 ASCII（IDN）主机名一律拒绝，请使用 ASCII 域名或直接 IP。

## 五、计费与结算：该收的钱不再漏收

- 兼容两种上游用量字段命名（含 Responses 类接口与嵌套 `response.usage`）；上游未报用量时按实际交付
  字节估算兜底，并写入 `usage.estimated` 标记以便对账。
- 余额不足 → `429 BALANCE_EXHAUSTED` 且不交付内容；其它结算错误 → `503 METERING_FAILED` 且不交付内容；
  可重试的瞬时错误先在事务内做有界退避重试。**任何结算失败都不再静默交付**。
- 上游返回 4xx 一律不扣费；修复单笔金额超过约 21.4 亿元时报错、巨额用量相加溢出被记成 0 等缺陷。

## 六、管理后台与审计

- 报表订阅：测试推送失败不再回显 webhook 地址与密钥；审计日志按查看者权限折叠历史条目中的地址，
  超级管理员仍可读原文用于追溯；新写入的条目只记订阅名称与 ID。
  **建议轮换 v2.7.1 及更早写入过订阅的机器人地址**（旧地址在历史审计行里仍是明文，只等保留期）。
- 登录会话变更缺少"会话持有性证明"能力时明确拒绝（此前的形态可被静默替换会话）。
- 用量中心的日期区间与图表口径一致、导航项不再因权限常量漂移对所有人隐藏、内网 HTTP 下连接器页
  不再白屏、峰谷时段配置在存量不可解析时可显式清空（二次确认）。

## 七、升级、迁移与回滚

- **服务端**：从更新服务器取本渠道镜像包
  （`<渠道>/releases/v2.7.2/picoaide-server-v2.7.2-amd64.zip` + `SHA256SUMS`）→ 校验 →
  `docker load` → 切换 `SERVER_IMAGE` → `docker compose up -d server` → 健康检查。
  启动时自动应用迁移 **0061 / 0062 / 0063**（加列与建表，在线 DDL，对分区表递归生效）。
  **升级前必须备份**（`.env` + `pg_dump -Fc` + `picoaide-data`），详见 `docs/deploy/AI-DEPLOY.md`。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包更新；数据根与 v2.7.1 一致，
  无需重新登录。
- **回滚**：数据库层可回退（0061/0062 只新增列与表，旧二进制可正常运行）；但**余额模型是产品行为变化**，
  回滚到 v2.7.1 会回到配额制、且看不到本版写入的余额流水。只在必要时回滚，并先留好备份。
- 从 v2.7.2 的任何预发布版本升级：无需额外操作（数据根一致）。

## 附件与校验
