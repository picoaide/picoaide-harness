# v2.7.5-beta.5（2026-09-17）

> 一句话：一轮**内置工具自检**的修复版——把三处"用不了、说不清"的地方修掉：
> 内置浏览器**截图卡住时不再只给一句超时**、定时任务**可以真正删除**、
> Windows 上**无法开启沙箱的工作区会说明原因与出路**。
> **建议所有使用 beta 的部署升级**（含已经装了 beta.4 的机器）。

本版**包含 v2.7.5-beta.4 的全部内容**。相对 beta.4 的差异如下。

## 一、内置浏览器：截图卡住时会说清卡在哪一步

- **现象**：`browser_screenshot` 在个别机器上连续超时（每次 30 秒），而同一时段其它浏览器
  操作（读取页面、点击、输入、执行脚本）全部正常；助手与用户只看到一句"工具调用超时"，
  既不知道卡在哪一步，也不知道该做什么。
- **影响**：需要"看一眼页面"的任务完全用不了截图；错误信息没有任何指向性时，助手容易
  误判成页面卡死并反复重试，白白消耗时间。
- **修复**：截图的**两条抓帧路径现在都受同一条预算约束**（原生抓帧 8 秒 + 渲染器侧兜底
  5 秒 + 余量，合计仍小于工具总预算 30 秒）。任一路径卡住时返回的是**自带原因**的失败
  （哪一段没有返回，以及"窗口需要能渲染，必要时先打开浏览器窗口再重试"），不再被整体
  超时覆盖掉。已补回归用例：模拟渲染器永不返回，断言调用在预算内带着原因收口。

## 二、定时任务：助手现在可以删除任务

- **现象**：助手能创建定时任务、能启停、能立即触发，却**没有任何删除手段**——自检或
  试验留下的任务只能由用户到界面里逐个手动清理。
- **修复**：新增删除能力（与界面里**同一个**删除动作，权限口径一致）：看不见的任务
  （不存在、或属于其他账号）按"不存在"处理；**正在执行的任务拒绝删除**——删除不会取消
  已经在跑的会话，只会让它的执行记录凭空消失，所以宁可让助手先停用或等本次跑完。
- 助手的系统提示词与公开文档同步列出五个工具名。

## 三、Windows：无法开启沙箱的工作区会给出原因与两条出路

- **现象**：在默认的「工作区内修改」权限下，某些工作区连一条最简单的命令都跑不起来，
  报错只有一行 `SetNamedSecurityInfoW failed (Win32 5)` 加一个目录路径；每条命令都只能
  靠一次性提权（完全权限）通过。触发这类失败的目录形态包括：不是当前登录账户创建的
  目录、经网络驱动器或目录联接/符号链接到达的目录、云同步占位目录、非 NTFS 卷、
  以及被安全软件保护的文件权限。
- **影响**：用户看到的是"客户端坏了"，而实际上是该目录**不允许被授予写权限**（Windows
  要求写文件权限的前提是调用者拥有该目录）。原报错没有任何可行动信息。
- **修复**：这一种错误码的失败在原有信息（接口名、错误码、目录）之后补上**成因与两条
  出路**：把工作区换成本账户创建的本地 NTFS 目录，或让该会话使用完全权限预设。
  **没有做静默降级**：沙箱拿不到写权限时绝不放行写入，只把原因说清楚。
- **自查建议**（PowerShell，不需要管理员）：
  - `icacls <工作区目录>` —— 看 `Owner:` 是否是当前登录账户、有无 DENY 条目；
  - `fsutil fsinfo volumeinfo <盘符>` —— 确认该卷是 NTFS；
  - `fsutil reparsepoint query <工作区目录>` —— 确认它不是目录联接/符号链接。

## 四、附件与升级

- 镜像与客户端安装包从更新服务器获取：
  `https://release.picoaide.com/<channel>/releases/2.7.5-beta.5/picoaide-server-2.7.5-beta.5-amd64.zip`
  （同目录 `SHA256SUMS` 可直接比对哈希；`<channel>/latest.json` 是更新清单）。
- 升级步骤与回滚方式见 `docs/deploy/AI-DEPLOY.md`（标准流程：备份 → 载入新镜像 → 更新
  部署文件里的镜像标签 → 重启 server → 健康检查）。
- 客户端会通过应用内更新提示升级；手工安装包在服务端门户（`/` 或 `/portal`）下载。

## 五、已知边界（本版未改）

- 截图在"渲染器完全不产帧"的极端环境下仍可能失败——本版保证它**说清卡在哪一段并给出
  可操作建议**，而不是给一句笼统超时；是否要为此改变浏览器窗口的创建方式，属另一项决策。
- Windows 上某个工作区为什么被拒绝授权，取决于该目录的归属与形态，需要现场用上面的
  三条命令确认；本版不改变"授权失败即拒绝启动沙箱"的判定。
