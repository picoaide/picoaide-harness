# PicoAide Harness v2.6.4（2026-09）

本版本修复一个重大 bug：**使用 DeepSeek 官方视觉模型（如 `deepseek-v4-flash-vision-exp`）时，模型清单自动下发后上传图片被提示「当前模型不支持图片」**。根因是「图片支持的配置没有下发」——服务端模型配置缺少输入模态字段，客户端据此把所有网关模型都当成了纯文本模型。本次全链路补齐：**服务端配置 → bootstrap 下发 → 客户端映射**，并在管理后台提供配置入口。

---

## 一、模型「输入模态」配置（服务端 + 管理后台）⭐

- `models` 表新增 `input_modalities`（`text`/`image` 数组，默认 `["text"]`，迁移 0058 自动应用）；
- **webadmin → 网关 → 模型**：新增/编辑模型时可选「输入模态：仅文字 / 文字+图片」，模型列表对支持图片的模型显示「图片」徽章；
- 服务端校验：空数组 / 未知模态 / 重复项一律拒绝（400），编辑时不传该字段 = 保持现值；
- 审计增强：`model_create` / `model_update` 明细记录模态字段级变更（如 `modalities:text→text+image`）；
- 渠道模型重同步**不会覆盖**管理员配置的输入模态（删除重建型全量同步除外，与 `default_params` 同语义）。

## 二、bootstrap 下发 + 客户端映射 ⭐

- `GET /api/client/v2/config/bootstrap` 与 `/v1/models` 的 `models[]` 每项携带 `input_modalities` 数组；
- 桌面客户端把该字段映射进本地 `llm-deepseek` 模型目录（`inputModalities`），视觉模型恢复图片上传/图片输入准入；
- 防御性兜底：服务端字段缺失或非法时客户端回落**仅文字**（不会让坏配置搞挂整个模型配置段，与旧行为一致）。

## 四、升级注意

1. **服务端升级必做**：迁移 0058 自动应用（新增 `models.input_modalities` 列）；webadmin 随二进制升级；
2. **升级后需管理员操作一次**：到 webadmin 网关 → 模型，把视觉模型（如 `deepseek-v4-flash-vision-exp`）的输入模态设为「**文字 + 图片**」——默认仍是「仅文字」，未标记前旧模型仍会提示不支持图片（这正是本次新增的配置语义）；
3. **桌面客户端需升级**（bootstrap 映射修复在客户端侧；自动更新链生效）；
4. 无协议破坏性变更：旧客户端连新服务端 = 字段缺失回落仅文字（行为与 v2.6.3 相同），新客户端连旧服务端 = 同样回落仅文字。
