## 一、预发布客户端的数据根回到与正式版一致（**需要重新登录一次**）

- **背景**：`beta.3` 起预发布客户端的数据根被改成独立目录 `~/.picoaide-harness-beta`，
  与正式版分开。预发布版是正式版的前置验证 —— 登录态、设置与会话必须与正式版延续，
  分开会让"装过正式版的机器试预发布版"看不到自己的历史，也会让同一台机器上两代客户端
  各自写入、互不可见。
- **本版**：预发布客户端的数据根**改回** `~/.picoaide-harness`（与正式版一致）。
  构建期守卫同步收紧：预发布渠道写别的目录、品牌渠道写正式版目录，两个方向都会让发布中止。
- **你需要做的**：
  - 装过 **beta.1 / beta.2** 或正式版、中间没换过根：升级后一切照旧（回到原目录）。
  - 装过 **beta.3 ~ beta.6**：客户端会从空的 `~/.picoaide-harness` 起，**需要重新登录一次**，
    升级前那段预发布期的会话在 `~/.picoaide-harness-beta` 里（未删除）。如需保留，先备份
    两个目录再手工合并；不建议直接对调目录（会话格式世代不同，见下条）。
- **要认账的残留风险**：正式线当前仍固定在较早的会话格式世代，预发期新建的会话对正式版
  客户端不可见。**窗口期内请不要在同一台机器上交替使用正式版与预发布版客户端**；
  正式版转正后该窗口闭合。

## 二、更新检查与下载：网络抖动不再等于失败

- **现象**：以前升级检查或安装包下载只要遇到一次网络抖动就直接失败：检查失败没有任何提示
  （界面照旧显示"已是最新"），下载失败则要从 0 重新下几百 MB。
- **本版**：
  - 检查更新最多 3 次尝试、安装包下载最多 5 次尝试，间隔按 2s/8s/20s/30s 逐步退避并带抖动
    （避免所有客户端同一时刻重试）；只重试瞬时故障（连接中断、服务端 5xx、传输被截断），
    明确不可恢复的失败（找不到安装包、包格式不对）不浪费用户时间。
  - **断点续传**：中断时已下载的字节留在本地，下一次从断点继续（服务端 `/updates/client/*`
    本身支持按范围下载）；服务端换了内容或忽略范围请求时自动改回整份重下，绝不拼接来源
    不一致的数据。
  - **失败可见**：重试等待中界面显示"第 n/N 次、N 秒后重试"；重试用尽后按类别给出原因
    （网络不可达 / 安装包校验不一致 / 包格式不正确 / 服务端未配置对外地址 / 请先登录 /
    缺少安装包）。用户手动点的那一次不做自动重试，直接给结论。
- **怎么自证**：新增真实 HTTP 集成测试 —— 服务器写一半就断开连接，断言"失败可重试且留下
  可续传的残留"，第二次带范围请求续传并通过哈希与格式校验，第三次直接复用不再下载。

## 三、后台静默下载，下载完成才提示安装

- **本版**：发现新版本后客户端在后台**直接下载**（不再先弹"要不要下载"打断用户），
  下载与校验全部完成、确认安装包可用之后，才提示一次"新版本已下载，可以安装"。
  真正的安装始终由用户确认（设置-关于的「安装更新」按钮、托盘菜单、会话顶部的更新徽标），
  不会在用户不知情时重启应用。
- **重启不重下**：已下载并通过校验的安装包会被记录；客户端重启、切换服务端后重新检查到
  同一版本时直接进入"可安装"，**不再重复下载**。
- 组织如果希望关掉后台自动下载（仍然保留"发现新版本"提示），可在客户端组装配置里把
  `backgroundDownload` 设为 `false`。

## 四、侧边栏与「设置-关于」显示同一份状态

- **现象**：同一时刻左上角（侧边栏品牌行）与「设置-关于」可能显示不同的更新状态 ——
  三个展示面各自轮询、各自缓存，刷新时机不一致。
- **本版**：整个窗口只有**一份**更新状态、**一条**轮询，侧边栏、「设置-关于」与会话顶部
  徽标读同一份快照，任何一处触发动作（检查/安装）后三处立刻同步；同一状态不再重复通知。

## 升级与回滚

- 服务端：取镜像（更新服务器附件 `picoaide-server-2.7.2-beta.7-amd64.zip`）→ 按
  `docs/deploy/AI-DEPLOY.md` 升级（**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
  本版服务端 Go 代码与 v2.7.2-beta.6 相同，无数据库迁移。
- 客户端：随服务端镜像分发，员工从自己登录的服务器取包，无需访问外网。
  装过 beta.3 ~ beta.6 的机器升级后需重新登录一次（见第一节）。
- 回滚：保留上一版镜像 tag，改回即可；客户端回滚到 beta.3 ~ beta.6 会再次切到
  `~/.picoaide-harness-beta`（那期间的数据仍在原处）。

## 附件与校验

- `picoaide-server-2.7.2-beta.7-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），
  内含本渠道的客户端安装包；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
