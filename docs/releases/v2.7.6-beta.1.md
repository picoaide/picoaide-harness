## 一、员工自建应用：是什么、能做什么

- **是什么**：员工用 Go / Rust / Zig 写一个小工具，编译成 WASM 交给平台，平台就把它跑起来，
  并给它一个地址（`<应用名>.<应用基域>`）、一个只属于它的数据库、以及"按使用者身份调用 AI"的能力。
  应用也可以**完全由 AI 写**（见第二节）。
- **能做什么**：读写自己的数据、调用平台 AI（费用记在使用者账上）、读取自己随包发布的静态资源、
  写运行日志。
- **不能做什么**（平台按"能力不存在"实现，不是靠策略拦截）：读平台数据（用户/令牌/余额/审计/用量）、
  读别的应用的数据、拿任何可用于调平台的凭据、访问网络、读服务器文件系统、拖垮平台（CPU/内存/磁盘/
  队列/AI 额度都有上限，超限被拒而不是把平台拖慢）。
- **权限模型**：**谁发布谁负责** —— 第一个成功发布某个应用名的员工永久占有它，只有他能发新版、
  上架/下架、删除；平台管理员可兜底接管。AI 只是编辑器，发布记录里记的是**发起操作的那个员工**。
- **改配置就是发新版**：访问模式、白名单、用途声明都随版本走，运行期改不了。

## 二、让 AI 自己把应用编译并发布出来

- 客户端里新增三个工具能力，AI 可以直接用：列出应用（看名字是否被占用、当前版本号）、
  **预检**（静态校验 + 真编译 + 干跑，不占版本号、不进审计、失败可反复调）、**发布**。
- 发布走的是**当前登录员工**的身份，不需要把任何凭据交给 AI；AI 也走不了"绕过界面直接打接口"
  这条路（那条路需要浏览器持有性证明，脚本拿不到）。
- 大于 8 MiB 的产物自动分片上传，断线后重发只补缺失的分片（可续传）。
- **作者手册（内置技能）随服务端下发**：客户端「能力中心 → 平台内置技能」里点一次「安装」即可，
  不需要管理员、不自动安装；没装时 AI 的工具报错会直接提示"先装这个技能"。

## 三、应用权限收敛为三选一，旧配置**不用重发**

- 权限从"可见性 + 是否需要登录"两个勾选，收敛为一个三选一：
  - **公开**：谁都能打开，不需要登录；
  - **登录后使用**（默认全员）：登录即可用；
  - **白名单用户**：登录 + 名单内可用。
- **名单由应用自己判定**（平台只把登录身份和访问模式告诉应用），平台不校验名单里的账号是否存在
  —— 这是为了不把平台变成账号枚举接口。
- 白名单模式下名单为空会被**拒绝发布**（那种应用对所有人都不可用）；"登录后全员"配空名单是合法的，
  旧版本里"需要登录 + 空名单即拒"的规则已废止。
- **已发布的应用不用做任何事**：老配置里的"可见性""是否需要登录"平台仍能读懂并按规则映射，
  下次发新版时会自动写成新格式。

## 四、应用中心展示全部应用

- 应用中心不再按可见性过滤：**所有应用都列出来**（包括已下架的），条目里标出访问级别与是否下架，
  已下架的应用禁用打开按钮（它仍然存在、数据保留，恢复后地址不变）。
- 冻结（停止服务）的应用不列 —— 列出来只会给出一个打不开的链接。

## 五、部署须知

- **新增的数据库迁移会自动执行**，无需人工干预；升级前仍建议按惯例做 PG 备份与数据目录备份。
- **应用对外访问地址（子域）默认不开**：不配 `PICOAI_APPS_BASE_DOMAIN` 时，发布 / 预检 / 应用中心
  都可用，但应用没有对外地址。要开启需要同时满足三件事（缺一不可）：
  1. 企业自备该基域的**通配证书**（平台不做证书自动化）+ 通配 DNS 解析到本服务端；
  2. **显式**配置可信反代地址（`PICOAI_TRUSTED_PROXIES`）—— 没显式配就开启子域会**拒绝启动**
     （否则全部匿名流量会挤进同一个限流桶）；
  3. 在 Caddy 里为该基域加 `*.<应用基域>` 的站点块。
- **编译子进程的操作系统级隔离档**：`PICOAI_COMPILE_ISOLATION`（`require` / `auto`（默认）/
  `off`）。容器里 bubblewrap 需要非特权 user namespace；**不可用时 `auto` 会大声记日志并回落**，
  `require` 则拒绝启动。生产建议 `require` 并让容器具备所需条件。
- **本版起镜像里额外安装了 bubblewrap**（编译隔离用），并随镜像发布内置技能资产
  （`/opt/picoaide/skills`，由客户端按需安装）。
- **不需要改的东西**：现有 `.env` 一个新变量都不配也能升级成功；镜像 tag 与渠道的对应关系不变。

## 六、升级步骤与资产校验

1. 从更新服务器取包（beta 渠道）：`<channel>/releases/<版本>/picoaide-server-<版本>-amd64.zip`
   与同目录 `SHA256SUMS`，先比对 sha256；
2. 在目标主机上：备份 `.env` / 数据库 / 数据目录 → 导入镜像 → **按渠道重打镜像 tag 并写回
   `.env`**（同机多渠道德 load 会互相覆盖裸 tag）→ `docker compose up -d server`；
3. 复验：容器 `healthy`、`--version` 与目标版本一致、迁移号已推进（本版为 0071）、
   客户端更新清单可访问。

> 回滚：把 `.env` 的 `SERVER_IMAGE` 写回上一个渠道 tag 并重建即可（旧镜像留在本机）。
