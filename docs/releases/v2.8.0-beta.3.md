# v2.8.0-beta.3（2026-09-21）

> 一句话：修掉两个服务端超时缺陷（**长时间流式回复在 5 分钟处被掐断**、**慢链路下载客户端
> 安装包在 5 分钟处断开**），并把 Office 文件的预览提示改成正常的「暂无法预览」——
> 不再出现指向一个并不存在的开关的指引。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 预发布（beta 渠道） |
| 升级建议 | beta 测试环境建议升级（含两个服务端超时缺陷的修复） |
| 影响面 | **服务端镜像** + 桌面客户端（macOS / Windows / Linux） |
| 产品代码变化 | 有（服务端两处超时修复；客户端 Office 预览提示） |
| 数据库迁移 | **本版无新增**（schema 仍到 0076） |

## 一、长时间流式回复不再在 5 分钟处被掐断（服务端）

- **现象**：单次生成**持续活跃超过 5 分钟**的对话（长文、长思考、工具链较长的会话），
  客户端会在第 5 分钟整收到 `unexpected EOF`（HTTP/2 下为 `stream INTERNAL_ERROR`），
  服务端访问日志同时在 `5m0s` 处出现写超时。**空闲流不受影响**（上游 90 秒空闲看门狗照常工作），
  所以此前的观感是「偶尔断、重发又好了」。
- **影响**：只有「一直在出字、但单次超过 5 分钟」的请求会中；不升级则这类请求必然失败，
  且客户端无法自助绕过。
- **修复**：两条流式出口（`/v1/chat/completions` 与 `/v1/messages`）在**每次 flush 前**
  把本次响应的写截止时间续到 `now + 窗口`（窗口 = `max(2 × 空闲超时, 60s)`，缺省 180 秒），
  并做节流（窗口的 1/3）避免 HTTP/2 下打扰事件循环；**全局 5 分钟写超时不被放大**，
  对「完全不写」的响应仍然生效。

## 二、慢链路下载客户端安装包不再被截断（服务端）

- **现象**：从部署后的服务器下载 150–180 MB 的客户端安装包时，链路速率低于约
  525 KB/s（Linux 包；Windows/macOS 约 530–600 KB/s）会在**第 5 分钟整**断开，
  客户端报 `stream INTERNAL_ERROR` / 连接重置。
- **影响**：上行较慢的部署环境里，员工下载客户端安装包会稳定失败，且无法自助绕过
  （换浏览器、重试都一样）。
- **修复**：只对 `/updates/client/*` 这一条静态下载路由改写**本次响应**的写截止时间 ——
  保底速率 64 KiB/s（180 MiB 约 48 分钟）、下限**不倒退**（不低于全局 5 分钟）、
  上限 1 小时（**有界，不是取消超时**）。其余路由与全部流式语义不变。

## 三、Office 文件的预览提示不再指向一个不存在的开关（客户端）

- **现象**：在右栏文档预览里打开 `.doc/.docx/.xls/.xlsx/.ppt/.pptx` 时显示
  「读取失败：Office 预览不可用。请在运行 DeepSeek Harness 的主机上启用文档预览服务。」
  —— 桌面端**没有**这个开关，这句指引无法执行。
- **影响**：只影响观感与判断（用户会以为是自己环境没配好），不影响数据与其它预览。
- **修复**：桌面端不再注册 Office 渲染器，这些文件落入与 `zip / mp4 / odt` 相同的
  内置空态：只显示**「该格式文件暂时无法预览」**，**不读文件、不请求转换服务**。
  **PDF / Markdown / 代码 / 图片 / HTML / 文本预览不受影响。**
- **说明**：桌面端**暂无** Office 预览能力（本版不随包 LibreOffice 引擎，理由与实测数据见
  仓库决策记录 `docs/decisions/2026-09-21-office-preview-disabled.md`）。若后续需要真支持，
  两条候选路线（随包引擎 / 服务端转换）的成本已在其中记录。

## 四、代码扫描告警清零（内部质量，无对外行为变化）

- 代码扫描面板的 **19 条告警全部在代码侧消除**（ReDoS ×2、路径注入 ×15、分配尺寸 ×2），
  **无 dismiss、无抑制注释**；其中路径判据改用标准库形态校验，可观察行为逐字节不变，
  并补了线性复杂度与越界用例。

## 已知限制（本版认账，未修）

- **Office 文件在桌面端不能预览**：谁会遇到 → 在右栏打开 Office 文档的人；现象 → 只显示
  「该格式文件暂时无法预览」（与 `zip/mp4/odt` 同一句文案，该文案为所有不可预览的二进制
  格式共用）；现在怎么办 → 下载后用本地 Office 打开；计划中。
- 沿用上一版仍未修的项：渠道暗色 logo 在客户端不生效（服务端门户已按系统主题切换，两端不一致）；
  能力中心每 30 秒的市场刷新可能短暂回退刚完成的安装状态（≤30 秒自愈）；详情弹层内的
  「按版本安装」结果仍显示在弹层外；内置浏览器部分低频动作文案仍为英文。
- 沿用上一版仍未修的项：**应用窗口内的「我来操作 / 交给 AI」按钮尚未挂载** —— AI 可以驱动
  应用窗口，但人无法在该窗口内交还控制权，当前处置是关闭该应用窗口。

## 升级与回滚

- 服务端：取本渠道镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**；不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发；服务端升级后员工从自己登录的服务器取包，无需访问外网。
  **服务端与客户端必须同版本**：旧版客户端连到本版服务端会出现功能不可用，
  请先升级客户端再使用。
- 客户端版本号为 `2.8.0-beta.3`，数据根仍为 `.picoaide-harness`（与上一版一致，
  登录态与历史会话延续）。
- **回滚**：本版**无新增数据库迁移** —— 保留上一版镜像 tag，改回 `SERVER_IMAGE` 后
  `docker compose up -d server` 即可；客户端重装上一版。无需恢复数据库。
  注意：回滚后本版修复的两个超时问题与 Office 预览提示会随之回来。

## 附件与校验

- `picoaide-server-2.8.0-beta.3-amd64.zip`：服务端镜像压缩包（`docker load` 后使用，
  内含本渠道三平台客户端安装包）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
