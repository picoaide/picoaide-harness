## 一、麦克风：「找不到设备」不再是唯一答案

- **现象**：此前不管什么原因，语音识别失败只会显示 Chromium 的英文原文
  `语音识别失败：Requested device not found`。这句话把三种完全不同的情况混成一句：
  真的没有录音设备、系统授权被拒（macOS 的 TCC；**被拒之后系统不再弹窗**）、
  以及远程桌面/虚拟机没开音频重定向。
- **本版怎么做**：
  - 没有录音设备时给出可执行的中文提示（去系统声音设置看输入设备；虚拟机/远程桌面
    需要开启音频或麦克风重定向）；
  - 客户端「语音输入准备」面板新增**麦克风自检**：显示系统报告的录音设备数与系统授权状态
    （已拒绝时明确写"需到系统设置里打开"），并可直接**申请麦克风权限**——
    只有状态是"尚未询问"时才显示这个按钮（已拒之后系统不会再弹，死按钮比没有按钮更糟）。
- **顺带收口一处真实风险**：真机 Electron 45 的权限检查回调收到的详情里**没有**媒体类型字段，
  原实现要求它等于 `audio` 属于恒假，会在设备选择阶段把请求判成"没有麦克风"。
  现改为"只在明确是别的媒体类型（如视频）时拒绝"，身份/框架/来源三道闸不变。
- **运维要做什么**：macOS 上必须使用**本版或更新的已签名包**才能触发系统授权框；
  已拒绝过的机器需要到「系统设置 → 隐私与安全性 → 麦克风」里重新打开。

## 二、上游固定点升到 0.2.0-rc.2（**无需迁移数据**）

- **升级范围**：上游 DeepSeek Harness 从 `dsh-v0.1.7-rc.2` 升到 `dsh-v0.2.0-rc.2`，
  中间 448 个提交。
- **数据面**：会话格式版本**两版相同**，实测 v0 → 当前格式的副本式迁移全部通过
  ⇒ **没有数据迁移**。回滚只需要换回上一版镜像，不需要恢复数据库，也不需要动客户端数据根。
- **我们做了什么**：8 个自有补丁全部逐条复核（在仓库外对官方发布包做过 apply 验证，
  并逐条对照上游源码确认"还生效吗、还有必要吗"），**零个被上游吸收**；其中 1 个因上游
  打包产物文件名变化而重切，语义逐字不变。
- **用户可见的一处变化**（来自上游升级指南）：设置 → 通用 → **工作详情**的历史保存值
  `normal` 现在显示为 **Detailed**（不再是 Standard），桌面端的默认值仍是 standard。
  磁盘上的取值不会被改写；想回到从前的显示，在该设置里选 Standard 即可。
- **不受影响**：上游把「Schedule / 自动化任务」三行搬进了可选插件包。我们**从未**按 id
  打开过它（产品内的定时任务是自研功能），所以不存在"升级后提醒停止投递"的问题。

## 三、关闭三条上游遥测/分析行（**安全口径，建议逐条读完**）

本版在桌面组合里把三条上游行显式关闭。三条都在客户端侧，与"我们自己的错误上报"
（`error_reporting_enabled` + 客户自建的 GlitchTip 兼容端点）互不影响。

- **`product-analytics` + `desktop-product-telemetry`**（0.2.0 新增，默认对桌面开启）：
  采集桌面使用事件并上报到 OTLP 采集端，事件含设备标识、账号标识、系统版本与使用行为；
  上报端点的默认值是**上游厂商自建的收集器**。本产品是自托管 + 白标交付，
  客户端使用数据出境到模型厂商不在交付承诺内，因此两条一起关闭。
  （其中一条另有硬理由：它要求一个我们不提供的构建版本变量，开着会让整个客户端起不来。）
- **`session-telemetry-otel`**（**既有行，此前在生产实际是开着的**）：它在用户
  **显式提交反馈时**（点赞/点踩、编辑、撤回）把**截至该事件的完整会话前缀**
  ——消息正文、工具参数与结果、工作区路径——导出到 OTLP 采集端。此前唯一的关闭手段是一个
  只在 CI 与测试里设置的环境变量，运行期没有任何地方设置它，所以线上一直是挂载的。
  本版改为**静态关闭**，与我们早已关闭的"会话日志随请求上传"（`session-log-deepseek`）对齐。
- **对用户的可见影响**：点赞/点踩、评分与撤回**照常可用、照常记录在本机会话日志里**；
  变的只是"不再向上游采集端上传会话内容"。没有开关，也不需要运维配置。

## 四、随包语音模型的来源与许可已声明

- 安装包里的语音识别权重（约 230 MB）是第三方产物，此前只列了 npm 依赖的第三方声明，
  没有覆盖它。本版在 `THIRD_PARTY_NOTICES.md` 里补了一节，写清产物名、来源与许可：
  - **SenseVoiceSmall**（int8 ONNX，随 sherpa-onnx 导出分发）：**FunASR 模型开源协议 v1.1**
    （模型卡标的是 `license: other`，**不是**代码仓的 MIT），协议 §2.2 要求署名来源与作者
    并保留模型名；
  - **Silero VAD**：**MIT**。
- 两条许可**不同**，交付与合规评审时请按上表分别引用，不要笼统写成"开源"。

## 已知限制（本版认账，未修）

- **macOS 替换安装仍是手工的**：更新提示会打开 DMG，替换「应用程序」里的副本由用户完成，
  替换后客户端不做版本自校验。计划中。
- **上游遥测行的默认值可能再次变化**：本版关闭的是当前三条；上游后续版本若新增默认开启的
  采集行，需要在下一次升级时重新对照（我们已把这一条写进升级脚本的人工核对清单）。
- 继承自 beta.3 的限制不变（见 v2.8.2-beta.3 的「已知限制」一节）。

## 升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
- **回滚**：本版**没有任何数据库迁移**，也**不含数据改写** ⇒
  保留上一版镜像 tag，把 `SERVER_IMAGE` 改回去、`docker compose up -d server` 即可；
  客户端回装上一版安装包。新旧版本可以并存，不需要停写窗口。
- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无
