# v2.7.5-beta.4（2026-09-17）

> 一句话：一轮**回归审计**的收口版——把客户端多语言那一批改动里"改出来的新问题"逐条修掉：
> 内置浏览器的**凭据注入站点绑定**、连接器**令牌刷新**、定时任务的**夏令时边界**、
> 界面文案的语言跟随，以及服务端管理面在查询异常时的**误报**。
> **建议所有使用 beta 的部署升级**（含已经装了 beta.3 的机器）。

| 项目 | 说明 |

本版**包含 v2.7.5-beta.3 的全部内容**（客户端错误监控采集面）。相对 beta.3 的差异如下。

---

## 一、内置浏览器：凭据只会注入到它自己的站点

- **现象**：连接器凭据（用户名/口令）在浏览器里的注入有一个"站点绑定"闸门——只允许注入到
  该连接器自己的站点。审计发现这个闸门判断"站点"的方式过于宽松：当凭据记录里的**服务地址
  字段填得不够规范**时（例如把一串编号、占位词、带编码的主机名写进地址字段），闸门可能把
  **另一个主机**当成基准，进而拒绝在真站点注入，甚至在提示里把模型引向那个错误的主机。
- **修复**：绑定基准的推导按"显式地址优先、只认文字形态确实是主机名的值"重做，并补齐了
  同形字/编码/本地回环名/超长标签等边界；两个都被旧规则认可的地址之间的取舍与旧版**逐条一致**
  （穷举 600 万组比对），也不会让任何记录从"可绑定"变成"不可绑定"。
- **对运维的建议**：需要**明确指定**站点时，请在浏览器插件配置里显式声明连接器的站点地址
  （`credentialSites`），或在凭据里使用形如 `BASE_URL` / `SERVER_URL` 的字段填写完整地址
  （`https://…`）。这类写法优先级最高、不受上述推导影响。

## 二、连接器：令牌刷新不再"用过的凭据再用一次"

- **现象**：OAuth 类连接器的访问令牌到期后由多种路径刷新（后台定时、面板按钮、重开恢复，
  以及 MCP SDK 自身的 401 自愈）。审计发现当**带外刷新**先完成、而正在运行的连接仍持有
  **已被消费的旧令牌**时，下一次 401 自愈会拿旧令牌去换新令牌；按 OAuth 规范，这会触发
  "refresh token 已被使用"并被服务端吊销整个授权——表现为连接器**静默降级为"需要重新授权"**，
  用户只看到工具报错。
- **修复**：带外刷新完成后会把新凭据**同步给正在运行的连接**（含轮换后保留 refresh token），
  并让刷新写入具备"读取—校验—更新"语义，避免与交互式重新授权互相覆盖。CI 里那条
  "同一个提交一次红一次绿"的偶发失败也随之定案（正是这条竞态）。
- **同批**：连接失败的状态分类改用稳定错误码——网络抖动、上游返回异常正文这类**不是授权
  问题**的失败，不再提示用户"请重新授权"。

## 三、定时任务：夏令时与跨日界线的边界

- **现象**：审计了"夏令时回拨日、跨日界线跳日、世纪闰年"等边界，发现两个真实问题：
  回拨日的"最近一次应执行时间"可能取错（把第一遍当成最近），以及**极端的跨日界线跳日**
  （某些时区历史上整日不存在）会让内部日期游标原地打转——该计算跑在调度心跳里，
  一旦发生就会**卡住整个定时任务调度**。
- **修复**：回拨日按"全天候选取最近"计算；游标增加前进保证（既不卡死也不丢跳日之前的候选）。
  全时区（400+ 个时区、三年内全部偏移跳变）逐分钟与独立真值对拍 11 亿次采样，0 差异。

## 四、界面语言跟随（客户端与桌面）

- **现象**：多语言那一批改动里有几处"漏网"——记忆插件的调度页有 9 处文案会把
  `{count}`/`{value}` 这样的占位符**原样显示**（任何语言都错）；桌面端的更新/检查更新/
  插件恢复对话框与两条启动通知仍是写死的英文；语言在运行中切换后，**已经打开的内置浏览器
  窗口**（工具栏、活动面板、菜单）仍停在旧语言；浏览器部署模式下登录首屏与 `/login`
  可能给出不同语言。
- **修复**：以上全部收口；语言切换会通知已打开的浏览器窗口重新渲染（**不影响正在浏览的
  标签页**）；桌面原生对话框与通知的语言跟随应用内设置。

## 五、服务端管理面：查询异常不再"显示成事实"

- **现象**：能力中心与审批列表在读取"官方属性 / 上下架状态"失败时，会把错误**吞掉**并按空
  结果渲染——运营看到的是"所有内容都不是官方"这种**与事实相反**的界面。
- **修复**：这类查询失败一律返回明确的服务器错误，界面不再给出错误结论。

## 六、附件与升级

- 镜像与客户端安装包从更新服务器获取：
  `https://release.picoaide.com/<channel>/releases/2.7.5-beta.4/picoaide-server-2.7.5-beta.4-amd64.zip`
  （同目录 `SHA256SUMS` 可直接比对哈希；`<channel>/latest.json` 是更新清单）。
- 升级步骤与回滚方式见 `docs/deploy/AI-DEPLOY.md`（标准流程：备份 → 载入新镜像 → 更新
  部署文件里的镜像标签 → 重启 server → 健康检查）。
- 客户端会通过应用内更新提示升级；手工安装包在服务端门户（`/` 或 `/portal`）下载。

## 七、已知边界（本版未改）

- 连接器记录里若把**通用占位域名**（例如 `mycompany.com` 这类真实可解析的占位写法）填进
  服务地址字段，而同一记录里另有真正的站点地址，绑定可能落到占位域名上——这是"从运维
  填写的字段里推断站点"这一机制的固有边界，本版按审计建议冻结规则、不再扩大启发式；
  需要确定绑定时请用 `credentialSites` 显式声明。
- 浏览器的凭据注入闸门是"尽力而为"的防误注入边界，不是对抗恶意页面的安全边界；同标签页内
  凭据窗口期之外的页面衍生内容（编码、反转、截图）仍不在覆盖范围。
