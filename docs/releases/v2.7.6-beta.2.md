## 一、管理后台新增「应用中心」

- 侧边栏「运维 → 应用中心」：列出全部员工自建应用（标题、应用标识、访问级别、上架/冻结状态、
  负责人、当前版本、更新时间）。
- 平台级处置：**上架 / 下架**、**冻结 / 解冻**、**转移归属**（离职接管）、
  **更新审批开关**（组织级：开启后新版本进待审队列，线上仍旧版本）。
- 权限沿用能力中心的粗粒度权限点：查看要 `capability:read`，处置要 `capability:write`；
  只读账号看不到处置按钮，服务端同样会拒绝写请求。
- 状态判定顺序：已删除 > 已冻结 > 上架/已下架 —— 冻结会连带下架，只看"是否上架"会把平台冻结
  误读成员工自己下架。

## 二、应用泛域名可以在控制台配置

- 位置：应用中心页顶部的「应用域名（泛域名）」卡片。
- **语义**：填主域名（例如 `example.com`），应用访问地址 = `应用名.example.com`；
  行为与原来完全一致（平台自己拼应用名，不要填 `*.example.com`）。留空 = 关闭应用子域。
- **优先级**：控制台保存过（含显式清空）> 部署时的环境变量 `PICOAI_APPS_BASE_DOMAIN`。
  卡片上会标出当前值来自「控制台配置 / 部署环境变量 / 未配置」。
- **改完立即生效，不需要重启**：服务端的域名门控每请求读当前值。
- **启用前需要满足三件事（缺一不可，保存时会逐条校验并给出可照做的提示）**：
  1. 该域名的 `*.该域名` **通配证书**（平台不做证书自动化）；
  2. **通配 DNS** 把 `*.该域名` 解析到本服务端；
  3. 部署 `.env` 里**显式**配置可信反向代理（`PICOAI_TRUSTED_PROXIES`）—— 没显式配就启用会
     被拒绝（否则全组织的匿名流量会挤进同一个限流桶）。
- 保存失败时控制台显示服务端原话与建议，不会静默失败。

## 三、服务端相应变化（部署可见）

- 新增两个管理端点：`GET/PUT /api/server/admin/wasm-apps/domain`（读/写应用基域；
  写操作要求 `capability:write` 并写审计 `wasm_apps_base_domain_change`）。
- 新增管理端点：`POST /api/server/admin/wasm-apps/:app_id/publish`（管理员上架，
  与既有的 `…/unpublish` 对称；下架是处置动作，处置完必须能恢复）。
- 应用列表接口新增 `current_version` 字段（控制台显示"当前版本"用）。
- **行为不变**：未配置基域时一切主机名仍走主站；配置后 `<应用名>.<基域>` 进应用、
  多级子域一律 404、未知主机名不回落主站。

## 四、升级步骤与资产校验

1. 从更新服务器取包（beta 渠道）：`<channel>/releases/<版本>/picoaide-server-<版本>-amd64.zip`
   与同目录 `SHA256SUMS`，先比对 sha256；
2. 备份 `.env` / 数据库 / 数据目录 → 导入镜像 → **按渠道重打镜像 tag 并写回 `.env`** →
   `docker compose up -d server`；
3. 复验：容器 `healthy`、`--version` 与目标版本一致、`/admin/` 侧边栏出现「应用中心」、
   应用中心页顶部的「应用域名」卡片能读到当前基域配置。

> 回滚：把 `.env` 的 `SERVER_IMAGE` 写回上一个渠道 tag 并重建即可。
