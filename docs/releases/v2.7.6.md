# v2.7.6（2026-09-20）

> 一句话：**员工自建 WASM 应用平台正式发布** —— 员工用一句话让 AI 把内部小工具做出来、发布到应用中心，
> 应用**只在桌面客户端内打开**（浏览器访问链路整体删除）；同时四个功能面板统一改版、
> 内置三个演示应用、应用构建技能升级为「陪不懂技术的同事把设计做完」。
> **本版服务端与客户端必须一并升级**（应用打开链路的契约在两端）。
>
> 数据库有迁移（`0069`–`0076`，含两条不可逆操作），**升级前必须备份**，回滚口径见「升级与回滚」。

## 访问模型变更（升级必读）

- **变化**：员工自建应用**只在桌面客户端内打开**（应用在客户端里以独立 origin
  `<渠道 app 源 scheme>://<应用标识>` 运行，每个应用一个 origin）。**浏览器访问链路整体删除**：
  应用不再有域名、不再有对外地址、平台不再需要为应用配置泛域名或通配证书。
  - 旧模型（应用子域 `https://<应用标识>.<应用基域>/` + 一次性换票 + 应用会话 Cookie）的**全部代码与表**已删除。
  - 与之配套的「匿名可用（`public`）」访问级别**不再存在**：应用一律要求登录，
    写侧只接受 `login`（登录后全员可用）与 `whitelist`（仅名单内用户可用）两种。
    历史配置里的 `public` 在**读取侧**一律按 `login` 处理，并在升级迁移中就地改写（无需作者重发）。
- **必须同版本升级**：应用打开链路的请求签名契约（安装证明）在服务端与客户端两侧，
  **旧版客户端打不开新版服务端的应用**，反之亦然。一句话：
  **若你使用旧版客户端，请先升级到本版再使用应用功能。**
- **不再可用的路径**（不是配置问题、没有开关）：
  - `https://<应用标识>.<任意域名>/` 这类地址**不存在**；
  - 管理后台里「应用基域 / 应用子域开关 / 泛域名证书」相关设置项已**删除**（升级后界面上不再有）；
  - 可分享的形态只有深链 `<渠道 deep link scheme>://app/<应用标识>`（scheme 由客户端渠道配置决定）。
- **运维要做什么**：
  1. 升级前**必须**备份数据库（见「升级与回滚」）；
  2. 停掉旧实例再升级（迁移 `0073` 会 `DROP TABLE`，旧实例持连接会让升级卡住 ——
     迁移内已设 `lock_timeout`，宁可快速失败也不无声卡住）；
  3. **不需要**为应用准备域名与证书；已有的泛域名证书可以保留给别的用途，也可以不再续期。

## 一、员工自建应用：正式可用

- **形态**：一个应用 = 一份 wasm 后端（只回 JSON）＋ 一份随包静态前端（页面/CSS/JS，
  运行期由宿主按路径直出）。应用有自己的数据库（一个应用一个库）、自己的日志、自己的准入名单；
  **没有**网络、文件、子进程、线程、员工名录等能力（这是设计边界，不是待办）。
- **怎么产生**：员工在客户端里对 AI 说「帮我做个设备借用登记表」，内置技能
  **应用构建（WASM 应用）** 会分轮次访谈需求、出设计卡、多角色评审后追问缺口，
  再写代码、编译、打包、发布到应用中心（`wasm_app_validate` / `wasm_app_publish` 两个工具）。
  作者也可以手动发布；**发布动作本身由 AI/作者在客户端内完成**。
- **权限与治理**：
  - 准入两档：`login`（缺省，登录后全员可用）/ `whitelist`（仅名单内）；名单由**应用自己**读配置比对，
    不在名单里的人会看到应用给出的一页提示（含本人账号，方便作者发现拼错）；
  - 归属：应用归属**首个成功占名的发布者**，管理员可在后台转移归属；
  - 审核：开启审核后，新版本先待审，管理员在管理端「应用中心」批准或拒绝（拒绝必须写理由，
    理由会回到作者手上）；
  - 处置：下架（应用仍在目录里、带「已下架」标记、打开返回 410）、冻结（只读快照，打开返回
    「已被管理员停用」）、删除（软删，标识与版本号永久占位）。
- **应用内 AI**：应用页面可以调用**使用者本人**的模型链路（额度扣使用者自己的余额），
  平台统一注入固定系统提示、不注入记忆与其它会话；首次调用弹一次性授权卡，可在应用详情页撤销。
  应用维度的用量归因尚未接通（见「已知限制」）。
- **运行护栏**：每个应用的并发、队列、单实例内存、应用库连接数与页缓存都可在
  管理端「运维 → 应用平台」按需调整（也可用部署档位一键设定）；用量看板见
  「应用中心 → 打开趋势 / AI 用量」。

## 二、四个功能面板统一为整页（界面改版）

- **定时任务 / 能力中心 / 连接器 / 应用中心** 点侧边栏入口后统一**把中列换成整页**（页首「返回对话」），
  视觉与交互收敛到同一套语言（按钮、卡片、胶囊、分段控件、开关、空状态）。
  此前能力中心/连接器/应用中心是浮在会话上的模态浮层：遮住对话、两层浮层能叠着开、窄窗口下布局被压扁。
- **能力中心**：列表里的描述固定两行截断，全文进详情弹层（原先三行 + 就地展开会把卡片撑到十几行）；
  内置技能按动作分区（可安装的进市场、可更新的进「我的」）；去掉重复标记。
- **应用中心**：卡片网格排布，标题/作者/时间/访问模式成组，底部动作对齐、卡片高度不再参差。
- 面板打开时不显示会话 —— 这是本版确定的口径（点「返回对话」回到会话）。

## 四、随包资源改为内存直出（内部机制，用户可见的后果是"宿主盘更干净"）

- 应用的页面/CSS/JS/图片等随包资源改为**运行期从内存直接响应**，宿主盘上**不再**出现
  `<数据根>/apps/<应用>/assets/<版本>/` 这类目录（只留各应用自己的数据库与平台编译缓存）。
- 升级时服务端会**清理历史遗留的资源目录**（best-effort，逐条记日志），应用**不需要重新发布**。
- 顺带修好：同一个资源路径在包里出现两次原先会静默丢掉一份（作者只会看到"内容不对"的页面），
  现在发布期直接拒绝并点名是哪几个资源；资源总量/单文件上限在发布期就地校验。

## 五、其它改进

- **内置技能**：应用构建技能升级为 2.0（分轮次设计访谈 + 多角色评审 + 前后端分离示例工程 +
  一条命令链打包发布），并订正了"资源落点"等口径；能力中心里的内置技能不再置顶成横幅，改为普通卡片。
- **内存与稳定性**：应用常驻内存明显下降（空闲回收 + 立即释放），容器环境下内存护栏同样生效；
  修掉"应用收尾期间关闭实例导致服务端崩溃""同应用请求被无意义串行"等阻塞级缺陷。
- **应用打开链路**：修掉预发阶段实测的「应用打不开」「点了打开却没有窗口」两条阻塞级缺陷，
  应用窗口运行在**按用户分区**、导航/重定向一律限定在应用自身 origin（外链不在窗口内打开）。
- **管理端**：新增「应用中心」（审批、归属、下架/冻结/删除、看板）与「运维 → 应用平台」（限制项与内存档位）；
  修掉限制项误操作会静默清空、拒绝申请可以不给理由、被冻结的应用被当成"应用不存在"等问题。
- **服务端修复**（随本版一并交付）：登录限流的真实客户端 IP 口径、MFA 挑战原子占用、
  OIDC 回调限流与出站校验、同名模型计价、管理会话哈希、TOTP 防重放等（详见 `docs/AUDIT-2026-09-13-SERVER-SECURITY.md`）。

## 已知限制（本版认账，未修）

- **应用内 AI 的用量归因尚未接通**：管理端看板在窗口内没有归因数据时显示「统计尚未上线」——
  那不是"零调用"。应用 AI 本身可用，费用照常扣使用者余额。
- **应用窗口内的外链落点未实现**：应用里的外部链接当前一律拒绝打开（计划中）。
- **应用内 AI 的控制权交互**（用户接管 / 按应用寻址）属下一批（计划中）。
- **三平台只在 Linux 实测**：Windows / macOS 的应用窗口与静态资源行为待真机复核（计划中）。
- 演示应用是**样例**：数据落在各自的应用库里，属于演示数据，升级/清理时按普通应用对待。
- 历史资源目录清理只在启动时做一次；清理失败只记日志、不影响启动
  （排查看服务端日志里的 `appserver: 已清理历史资源目录`）。
- 运营看板趋势 UV 的长期（>90 天）保留需要新增迁移，本版未做（更早日期如实给 0）。

## 升级与回滚

- **升级前必须备份**：至少 `pg_dump -Fc` 一份数据库；建议同时归档部署目录下的数据根
  （应用库与平台数据都在其中）。**不要**使用 `latest` 标签，**不要** `down -v`。
- **服务端**：按 `docs/deploy/AI-DEPLOY.md` 升级（取本版镜像归档 → `docker load` → 切换 `.env` 的
  `SERVER_IMAGE` → `docker compose up -d server`）。**先停旧实例再升级**：
  迁移 `0073` 是 `DROP TABLE`，旧实例持有的连接会让它一直等待（迁移内已设 `lock_timeout`，
  会快速失败而不是无声卡住）。
- **客户端**：随服务端镜像分发，员工从自己登录的服务器取包，无需访问外网。
  **本版服务端与客户端请一并升级**（应用打开链路的契约在两端）。
- **回滚**（本版含 `DROP TABLE` 与配置改写，属**不可逆**迁移）：
  - **不能只回退镜像**：旧二进制面对已迁移的库会逐请求报错（缺表/列）。
  - 正确顺序：**停服 → 恢复升级前的 `pg_dump` → 把 `SERVER_IMAGE` 改回上一版 tag →
    `docker compose up -d server` → 客户端回退到上一版安装包**。
  - 另需注意：本版启动时清理了历史资源目录，因此**回滚到 v2.7.5 或更早版本时，
    应用会缺少它们依赖的资源目录**；恢复 `pg_dump` 不涉及文件，需要一并恢复升级前归档的**数据根**
    （或回滚后把各应用重新发布一次）。
