# PicoAide Harness v2.6.9-beta.3（2026-09）

预发布补丁：修掉 v2.6.9-beta.2 在测试环境暴露的**白标品牌图裂图**，并顺带根治一个
从 v2.6.4 起就潜伏的启动期会话同步竞态。功能面与 beta.2 相同，客户端渲染与启动
行为有三处实质变化。

---

## 一、渠道品牌图裂图（三个独立原因，缺一个都还是裂的）

现象：渠道 `beta` 的桌面客户端侧边栏与主页品牌图是一张裂图。**不是渠道缺图标** ——
服务端 `/api/client/v2/channel/logo` 返回 200 `image/svg+xml`（938 B），容器内渠道
目录 `logo.svg` / `logo-dark.svg` 齐全，`/api/client/v2/channel` 也正常下发。问题
全在客户端：

1. **相对路径打到本地 webServer**：服务端下发的是相对路径
   （`/api/client/v2/channel/logo`，命名空间真源在 `server/internal/router`），而
   `/api/pico/channel` 原样透传、客户端 store 播种时原样存下 → `<img src="/api/client/v2/channel/logo">`
   在渲染层解析到**本地** webServer（那里没有服务端命名空间的路由）→ 404。
   修：`absolutizeChannelAssets()` 成为唯一实现（`/api/pico/channel` 出口统一绝对化、
   `channel-sync` 复用它），没有服务端地址时**丢弃**相对 URL，让消费方回落到内置
   品牌图形而不是渲染一个必然 404 的地址；store 播种侧再加一道
   `stripRelativeAssetURLs`。
2. **窗口 CSP 拦截跨源 logo**：桌面窗口的 `img-src 'self' data: blob:` 把客户
   服务器上的 logo 直接拦掉（微实验逐字复现：`violates the following Content
   Security Policy directive: "img-src 'self' data: blob:"`，`naturalWidth=0`）。
   渠道服务器地址在打包期不可知，而同一策略的 `connect-src` 早已放行 `http:`/`https:`，
   放行图片不增加外泄面 → `img-src` 改为 `'self' data: blob: http: https:`。
3. **启动期会话同步竞态**（真正的老问题）：`restore()` 在 SessionService **构造期**
   启动，其 emit 可能早于插件 `apply`，裸 `ctx.on(SESSION_CHANGED_EVENT, …)` 会整个
   漏掉 —— 于是"重启后带着有效会话"这条最常见的启动路径上，服务端驱动的渠道内容
   （绝对化后的 logo、改过的名称/主题色）永远不到，直到重新登录。同一根因即
   2026-09-05 的"视觉模型缺 `inputModalities`、上传图片被拒，重登即恢复"。
   修：新增 `subscribeSession()`（用现成的 `isRestored()` 判定"那次 emit 是否已经
   过去"，两个方向都不重不漏），`channel-sync` / `bootstrap` 改用它；
   `error-reporting` 里为绕开这个根因加的 1s×60 轮询兜底随之删除。

顺带修掉的真 bug：`mergeChannel` 丢掉服务端下发的 `login.logo_url_dark`；客户端
`<img>` 缺 `onError` 回落（只有登录页有，服务端不可达时会留一个破图图标）；
`absolutizeChannelAssets` 初版"先展开后覆盖"的写法在素材**被丢弃**时会把原相对地址
spread 回来（新测试照出来的）。

## 二、文档

- `docs/planning/2026-09-10-channel-package-reference.md` 新增 **§4.2 渠道素材 URL 的
  客户端契约**：三个环节（出口绝对化 / store 播种丢弃 / 窗口 CSP 放行）各自的规则与
  位置、三条配套约束（相对路径在本地 origin 必然 404、加载失败必须回落、素材 URL
  一律"先删后写"），以及 `logo_url_dark` 暂无客户端消费面的提醒。

## 三、CI 脚本回归门禁的破坏性副作用

`scripts/verify-ci-scripts.mjs` 调 `ci-package-clients.sh` 时没传 `--dist`，脚本按
缺省值对**仓库里真实的** `packages/host/desktop/dist` 执行 `rm -rf` —— 跑一次
`yarn check` 就会删掉刚打好的包（实测：随后 `e2e:client` 报 `app binary not found`）。
现在产物目录落在临时目录，`yarn check` 不再动工作区的构建产物。
