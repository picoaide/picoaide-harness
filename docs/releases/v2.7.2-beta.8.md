# v2.7.2-beta.8（2026-09-13）

> 一句话：本版修掉一批「计量少收 / 凭据可能外泄 / 写入越界」类缺陷，并修回 v2.7.2-beta.7 引入的「余额不足仍交付结果」回归。**使用 beta 环境的部署与客户端都应升级。**

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 预发布（beta） |
| 升级建议 | **强烈建议升级**（已装 v2.7.2-beta.7 的客户端、已升级到该版本的服务端） |
| 影响面 | 服务端镜像（含随包客户端）；Windows · macOS · Linux 客户端 |
| 产品代码变化 | 有（相对 v2.7.2-beta.7） |
| 数据库迁移 | 无（升级只需换镜像） |

## 一、必须先看：v2.7.2-beta.7 有一处「余额不足仍返回结果」的回归

- **现象**：开启余额闸门后，余额耗尽的调用**仍然返回 200 与完整结果**，但既不扣费也不记账，可以无限重复。
  流式请求则全量交付后按转发字节估算，仅扣到极小金额。
- **影响**：只有 v2.7.2-beta.7 存在（该版本引入），更早的版本是"记账但透支"，本版之前的所有 beta 都不应继续用于有余额闸门的部署。
- **本版怎么修**：改为明确失败 —— 普通与向量接口返回 `429 BALANCE_EXHAUSTED` 且不交付内容；流式在事件流中发出错误并终止，不再返回完整结果。

## 二、计量口径：该收的钱不再漏收

- **兼容两种上游用量字段命名**（含 responses 类接口的 `input_tokens` / `output_tokens` 与缓存命中明细）。此前按该命名的上游上报会被记成 0 用量、0 费用。
- **流式响应上游未返回用量时按字节估算兜底**（与另一条流式路径同一套实现）。此前这类请求完全免费；客户端中途断开同样不再免费。
- **修复极端大数相加溢出**：超大用量相加曾回绕成负数并被归零，导致巨额调用记成 0 元。
- **任何结算失败都不再静默交付**：余额不足 → 429；其它结算错误 → 503 `METERING_FAILED`（不返回上游内容，流式发错误事件终止）；可重试的瞬时错误先在事务内做有界退避重试，避免数据库抖动被误判成"免费放行"。
- **修复单笔金额超过约 21.4 亿元时结算报错**（金额参数被数据库按 32 位整数推断）。

## 三、本地连接器：服务端下发内容的本地防线

- **声明式绕过已封堵**：连接器定义里声明的"凭证字段名"此前可以绕过受保护的环境变量名单（例如声明一个与运行时引导变量同名的字段，把加载器参数注入本地命令）。本版在**定义解析**与**实际注入**两处都拒绝，并且本地确认提示会列出**全部**将被注入的变量名（此前只列一部分）。
- **不再跟随重定向**：连接器端点返回 3xx 时按出站策略拒绝，授权码与 PKCE 校验值不会因 307/308 被送到第二个主机。
- **本地回环地址口径统一**：`localhost` / `*.localhost` 以及带根点的域名（`host.`）与客户端的"本地回环"判定对齐。此前管理员能在管理后台保存 `http://localhost:…` 的连接器，客户端却静默丢弃、永远连不上。
- **合法连接器未被收紧误伤**：本地 MCP 服务（含凭证注入、工具调用）端到端回归通过。

## 四、内置浏览器

- **凭据注入后不再回传**：快照、标签页列表、地址栏状态、下载文件名、历史/书签/操作日志、窗口标题等**所有**回给模型的出口统一脱敏（此前只有部分出口脱敏，同一个返回体里元素文本已打码而地址仍是明文）。
- **注入过凭据的标签页禁止外传**：eval 的网络写入面（fetch / XHR / sendBeacon / WebSocket / EventSource / Worker / 表单提交等）被拒绝（静态判定 + 页面内拦截），只读表达式不受影响。
- **短口令不再误伤页面文本**：此前 8 字符以下的口令会把页面里同形的正常文本擦成 `****`；现在按长度与"值形态"双重判定，正常文本逐字保留。
- **跨源 iframe 纳入帧索引**：支付/SSO 这类跨源子帧此前不在索引里，`frame:N` 会静默落到另一个帧；现在一一对应，无法对应时明确报错并给出真实帧数。

## 五、记忆同步与写入边界

- 仓库内出现**符号链接**时，同步的全部写回路径（三路合并、冲突侧车、元数据文件、归档、待办）一律**拒绝写入**并给出明确原因，而不是写到仓库外的目标文件。此前只有部分出口受保护，`runSync` 的合并写回仍可被 `logs -> 外部目录` 这类符号链接穿透。
- 正常仓库（无符号链接）的同步行为不变，回归测试覆盖。

## 六、管理后台与审计

- **报表订阅凭据**：测试推送失败的错误响应不再回显 webhook 地址与密钥；审计日志读接口按查看者权限对**历史条目**折叠地址（不具报表读取权限的只读审计账号看不到明文，超级管理员仍可读原文用于追溯）；新写入的审计条目只记订阅名称与 ID。
- **会话变更**：缺少"会话持有性证明"能力时，登录/登出等会话变更动作改为明确拒绝（此前会退回较弱的同源校验）；正常路径不受影响。
- **可用性修复**：用量中心的日期区间与图表口径一致、导航项不再因权限常量漂移对所有人隐藏、非安全源（内网 HTTP）下连接器页不再白屏、峰谷时段配置在存量不可解析时可以显式清空（二次确认）、能力中心对共享智能体显示"更新到 vX"、账号卡在令牌失效后不再展示过期余额。

## 七、已知限制（本版有意保留）

1. **历史审计行里的 webhook 地址仍是明文，只等保留期**：v2.7.2-beta.7 及更早版本写入的报表订阅条目，其"详情"栏仍包含完整 webhook 地址（哈希链审计，本版不改写历史行）。在 v2.7.2-beta.8 上只有同时具备 `audit:read` 与 `report:read` 的账号（超级管理员）能读到原文，只读审计账号看到的是折叠后的地址。建议**现在轮换受影响的机器人地址**（在企微/钉钉/飞书侧重建机器人并更新订阅），旧地址随即失效；也可临时调低审计保留期让旧条目自然清理。全新部署不受影响。
2. **凭据标签页的 eval 收敛边界**：本版关闭的是"注入凭据的标签页通过网络 API 把凭据送出去"这条常规通道（静态拒绝 + 页面内拦截）。若页面自身脚本**提前缓存**了这些 API 的引用，仍可能绕过页面内拦截。这属于产品口径选择（更严的选项是"该标签页完全禁用 eval"，会牺牲只读排查能力），如需更严请在下一轮拍板。
3. **短口令**：≤7 字符的口令在自由文本中出现时不再打码（换取不误伤正常文本）；凭据值本身在任何出口仍始终擦除。
4. **下载列表保留真实文件路径**：下载打开与文件操作需要真实路径，列表接口不做脱敏（与地址栏、历史的脱敏口径不同）。

## 升级与回滚

- **服务端**：按 `docs/deploy/AI-DEPLOY.md` 执行 —— 从更新服务器取本渠道镜像包（`<渠道>/releases/v2.7.2-beta.8/picoaide-server-v2.7.2-beta.8-amd64.zip` + `SHA256SUMS`）→ `docker load` → 切换 `SERVER_IMAGE` → `docker compose up -d server` → 健康检查。
- **客户端**：随服务端镜像分发，由门户与客户端内的更新检查提示升级；本版客户端与 beta.7 数据根一致，无需重新登录。
- **回滚**：把 `SERVER_IMAGE` 改回上一版本标签并重启 server 容器即可；本版**无数据库迁移**，回滚不涉及数据形态变化。

## 附件与校验

- 更新服务器：`<渠道>/releases/v2.7.2-beta.8/`（镜像包 + `SHA256SUMS`；同目录 `latest.json` 指向本版）。
- 公开渠道另见 GitHub Release `v2.7.2-beta.8` 的附件 `picoaide-server-v2.7.2-beta.8-amd64.zip` 与 `SHA256SUMS`。
- 校验：下载后 `sha256sum -c SHA256SUMS`（或与 Release 附件中的哈希逐字比对）再升级。
