# v2.7.2-beta.8（2026-09-13）

> 一句话：本版修掉一批「计量少收 / 凭据可能外泄 / 写入越界」类缺陷，并修回 v2.7.2-beta.7 引入的「余额不足仍交付结果」回归。**使用 beta 环境的部署与客户端都应升级。**

| 升级建议 | **强烈建议升级**（已装 v2.7.2-beta.7 的客户端、已升级到该版本的服务端） |

## 一、必须先看：v2.7.2-beta.7 有一处「余额不足仍返回结果」的回归

- **现象**：开启余额闸门后，余额耗尽的调用**仍然返回 200 与完整结果**，但既不扣费也不记账，可以无限重复；流式则全量交付后仅按转发字节估算扣极少金额。
- **影响**：只有 v2.7.2-beta.7 存在（该版本引入）；更早版本是"记账但透支"，同样不建议用于有余额闸门的部署。
- **本版怎么修**：改为明确失败 —— 普通与向量接口返回 `429 BALANCE_EXHAUSTED` 且不交付内容；流式在事件流中发出错误并终止，不再返回完整结果。

## 二、计量口径：该收的钱不再漏收

- **兼容两种上游用量字段命名**（含 responses 类接口的 `input_tokens` / `output_tokens` 与缓存命中明细、嵌套 `response.usage`）。此前按该命名的上游上报会被记成 0 用量、0 费用；`prompt_tokens` 与 `input_tokens` 同时出现且一真一假时也能取到真值。
- **流式 / 非流式在缺少用量时按交付字节估算兜底**（同一套实现，含客户端中途断开）。此前这类请求完全免费。
- **估算带上限与标记**：单请求估算不超过 65536 个输出 token（约 256 KiB 交付），并写入新列 `usage.estimated=true`，报表与对账可以把估算行与上游真实上报区分开。
- **任何结算失败都不再静默交付**：余额不足 → 429；其它结算错误 → 503 `METERING_FAILED`（不返回上游内容，流式发错误事件终止）；可重试的瞬时错误先在事务内做有界退避重试。
- **4xx 一律不扣费**（此前上游 4xx 错误体里带用量会被照扣）；**修复单笔金额超过约 21.4 亿元时结算报错**；**修复巨额用量相加溢出被记成 0**；`/v1/completions`、`/v1/responses` 的计费行不再混记为 `chat`（按端点可对账）。

## 三、本地连接器：服务端下发内容的本地防线

- **声明式绕过已封堵**：连接器定义里声明的"凭证字段名"此前可以绕过受保护的环境变量名单（含键名带 `=` 的形态，可把加载器参数注入本地命令并**真的执行**）。本版在**定义解析**与**实际注入**两处都拒绝，本地确认提示会列出全部将被注入的变量名。
- **MCP 连接不再跟随重定向**：包括流式（SSE）通道在内，配置的端点返回 3xx 一律按失败处理；授权码、PKCE 校验值与连接密钥不会因 307/303/308 被送到第二个主机。
- **本地回环地址口径统一**：`localhost` / `*.localhost`、带根点域名、以及 IPv6/保留网段的判定与客户端一致（此前存在"管理端能保存、客户端静默丢弃"）。
- **拒绝非 ASCII 主机名**（IDN）：服务端与客户端都不接受 IDN 形式的连接器地址，请使用 ASCII 域名或直接 IP（这是一处有意的严格化，避免两端判定不一致）。

## 四、内置浏览器

- **凭据注入后进入"凭据活性窗口"**：窗口内 `browser_eval` 与 `browser_screenshot` **被拒绝**（脚本执行与截图都可能把口令原样或变形后交回模型）；窗口在该标签页主帧完成一次跨文档导航后自动结束，两个工具随即恢复。
- **文本出口的值级擦除延长到标签页生命周期**：快照、正文、标签页标题与地址、历史/书签/操作日志、下载名、窗口标题等出口，除"键=值"规则外还会把注入过的凭据值逐字擦除（此前导航离开登录页后即可被页面留存副本重新读出）。
- **短口令不再误伤页面文本**：按长度与"值形态"双重判定，`Item (abc123) shipped` 这类散文逐字保留。
- **跨源 iframe 纳入帧索引**：支付/SSO 这类跨源子帧（含其内部子帧）此前不在索引里、`frame:N` 会静默落到另一个帧；现在一一对应，无法对应时明确报错并给出真实帧数。

## 五、记忆同步与写入边界

- 仓库内出现**符号链接**时，同步与记忆的全部读写路径（三路合并、冲突侧车、归档轨、元数据、待办、原子写的临时文件、锁文件）一律**拒绝**并给出明确原因，而不是写到仓库外的目标文件，也不再把仓库外内容读回模型。
- 记忆归档读取接口（`GET /memory-evolve/api/memory-files`）同样受该断言保护。
- 正常仓库（无符号链接）的同步、归档与写入行为不变，回归覆盖。

## 六、管理后台与审计

- **报表订阅凭据**：测试推送失败的错误响应不再回显 webhook 地址与密钥；审计日志读接口按查看者权限对**历史条目**折叠地址（不具报表读取权限的只读审计账号看不到明文，超级管理员仍可读原文用于追溯）；新写入的审计条目只记订阅名称与 ID。
- **会话变更**：缺少"会话持有性证明"能力时，登录/登出等会话变更动作改为明确拒绝；正常路径不受影响（真机登录已在真组合下复验）。
- **可用性修复**：用量中心的日期区间与图表口径一致、导航项不再因权限常量漂移对所有人隐藏、非安全源（内网 HTTP）下连接器页不再白屏、峰谷时段配置在存量不可解析时可以显式清空（二次确认）、能力中心对共享智能体显示"更新到 vX"、账号卡在令牌失效后不再展示过期余额。

## 七、已知限制（本版有意保留）

1. **历史审计行里的 webhook 地址仍是明文，只等保留期**：v2.7.2-beta.7 及更早版本写入的报表订阅条目，其"详情"栏仍包含完整 webhook 地址（哈希链审计，本版不改写历史行）。在 v2.7.2-beta.8 上只有同时具备 `audit:read` 与 `report:read` 的账号（超级管理员）能读到原文，只读审计账号看到的是折叠后的地址。**建议现在轮换受影响的机器人地址**（在企微/钉钉/飞书侧重建机器人并更新订阅），旧地址随即失效；也可临时调低审计保留期让旧条目自然清理。全新部署不受影响。
2. **凭据活性窗口的边界**：窗口内 `browser_eval` 与 `browser_screenshot` 不可用（提交表单或导航后恢复）；页面若把口令**变形**后渲染（base64、逐字符分隔、把口令画成图像等），值级擦除只能覆盖逐字出现——这类变形仍可能进入模型上下文；导航出窗后截图恢复，页面自行重渲染的副本也可被拍到。这是"不牺牲登录流程可用性"下的取舍，如需更严（例如注入过凭据的标签页终身禁用脚本与截图）请在下一轮拍板。
3. **下载列表的磁盘路径保留真实值**（下载打开与文件操作需要），模型侧展示名与 URL 已脱敏。
4. **短口令（≤7 字符）在自由文本中出现时不再打码**（换取不误伤正常文本）；`password=…` 这类"键=值"形态仍始终打码。
5. **上游少报用量仍会被采信**：估算只在"上游未报"时兜底；上游若显式少报（例如实际输出很多却上报 1 token），计费仍以上报值为准。这是"信任网关上游"的既定口径，如需改为强制估算需产品决策。
6. **`usage.estimated` 暂未在管理后台界面标注**（接口已返回该字段）。

## 升级与回滚

- **服务端**：按 `docs/deploy/AI-DEPLOY.md` 执行 —— 从更新服务器取本渠道镜像包（`<渠道>/releases/v2.7.2-beta.8/picoaide-server-v2.7.2-beta.8-amd64.zip` + `SHA256SUMS`）→ `docker load` → 切换 `SERVER_IMAGE` → `docker compose up -d server` → 健康检查。启动时自动应用迁移 **0063**（`usage.estimated`，对分区表递归生效，均为在线 DDL）。
- **客户端**：随服务端镜像分发，由门户与客户端内的更新检查提示升级；数据根与 beta.7 一致，无需重新登录。
- **回滚**：把 `SERVER_IMAGE` 改回上一版本标签并重启 server 容器即可。迁移 0063 只新增一列且带默认值，**旧版本二进制可正常运行**（旧版写入不带该列、默认 false）；若要彻底回退数据库形态可执行 `ALTER TABLE usage DROP COLUMN estimated;`（只丢失"该行为估算"的标记，token 与金额不受影响）。
