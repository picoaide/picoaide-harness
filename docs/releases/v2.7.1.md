# v2.7.1（2026-09-11）

> **macOS 客户端安装包的交付修复版**：官方与定制渠道的 DMG 现在一律经 Apple 公证，
> 客户 Mac 首次打开即可直接使用，不再被 Gatekeeper 拦下。
> 客户端与服务端**产品代码与 v2.7.0 完全相同**，本版只改了打包与分发链。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 正式版（补丁） |
| 升级建议 | **必须升级**——所有需要分发 macOS 客户端的部署（含定制渠道） |
| 影响面 | macOS 安装包；Windows / Linux 安装包与所有运行时行为不受影响 |
| 产品代码变化 | 无（相对 v2.7.0，仅打包、校验与发布流程） |

## 一、macOS 安装包一律走完整签名 + Apple 公证

- **现象**：v2.7.0 的 macOS 安装包在企业定制渠道的机器上，首次打开被 Gatekeeper 拦成
  「Apple 无法验证此 App 是否包含恶意软件 / 未能验证开发者」，用户必须自己到
  「系统设置 → 隐私与安全性」手动放行才能用。
- **原因**：这批 DMG 只做了 Developer ID 签名，**没有提交 Apple 公证**。签名本身是有效的
  （包内 bundle id、teamID、hardened runtime 都正确），缺的是 Apple 侧的公证票据。
- **影响**：凡是把安装包交付到客户 Mac 的部署——尤其是定制渠道（客户从自己的服务器取包）。
  官方渠道在正式 tag 上一直走公证链，因此只有渠道包受影响；但两者共用同一份交付说明，
  口径必须一致。
- **修复**：正式 tag 上**所有渠道**的 DMG 与官方走同一条链——
  Developer ID 签名 → 提交 Apple 公证 → **装订公证票据（staple）**，用户双击即可打开。
- **自证**：打包流程内置校验——公证票据（`stapler validate`）与 Gatekeeper 放行（`spctl`）
  任一不过就终止发布：**宁可不出包，也不出没有票据的包**。公证提交可断点续等，
  同一次提交重试不会重复排队。

## 二、防止再次静默退回「只签名」

- 工作流静态门禁新增一条策略检查：任何打包渠道 DMG 的步骤必须带齐公证凭据，
  并且必须真的调用公证命令（只签名不算通过）。
- 这条门禁在 PR/分支上就会跑，不必等到发版才发现——上一版的问题正是「PR 全绿、发版才炸」。

## 升级

1. **服务端**：取 v2.7.1 镜像（更新服务器附件、GitHub Release 附件，或可出网时
   `docker pull ghcr.io/picoaide/picoaide-harness-server:v2.7.1`）；
2. 按部署说明 [`docs/deploy/AI-DEPLOY.md`](https://github.com/picoaide/picoaide-harness/blob/master/docs/deploy/AI-DEPLOY.md) 升级，
   注意四条数据安全铁律：**升级前必须备份、禁止使用 `latest`、禁止 `down -v`、不得覆盖已有 `.env`**；
3. **客户端**：安装包随服务端镜像分发，服务端升级后员工从**自己登录的那台服务器**取包
   （`/updates/client/…`），员工侧无需访问任何外网。

> 只想修 macOS 安装包的部署，升级服务端镜像即可，无需其他操作；
> 已经在用 v2.7.0 且不涉及 Mac 客户端分发的部署，可以等下一个功能版一起升。

## 附件与校验

- `picoaide-server-2.7.1-amd64.zip`：服务端镜像压缩包（`unzip -p 包 image.tar | docker load`）；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压使用。
