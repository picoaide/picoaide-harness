# PicoAide Harness v2.7.1（2026-09）

v2.7.0 的交付链路补丁版：**客户端与服务端代码与 2.7.0 完全一致**（未改任何运行时行为），
只修安装包的 mac 分发面。

---

## 一、mac 客户端安装包一律走完整签名 + 公证（含定制渠道）

- **问题**：v2.7.0 的企业定制渠道 macOS 安装包只做了 Developer ID 签名、**没有公证**。
  签名本身有效（包内 `bundle id` / `teamID` / hardened runtime 都对），但客户在 Mac 上
  首次打开会被 Gatekeeper 拦成「Apple 无法验证此 App 是否包含恶意软件 / 未能验证开发者」，
  必须去「系统设置 → 隐私与安全性」手动放行。
- **修复**：正式 tag 上所有渠道的 DMG 与官方走同一条链——签名 + 公证 + `staple`，
  构建流程内含 `spctl` / `stapler validate` 校验，公证失败即 fail-loud（不产出无票据的包）。
- **取包方式不变**：客户端安装包随**服务端镜像**分发（`GET /api/client/v2/updates/manifest`
  → `/updates/client/<文件>`）。要拿到本次修复后的安装包，升级到 v2.7.1 的服务端镜像即可，
  员工侧无需访问任何外网。

## 二、CI 防退化门禁

- 工作流静态门禁新增一条策略检查：任何打包渠道 DMG 的步骤必须带齐公证凭据、且必须真的
  调用公证命令——避免以后又静默退回「只签名」。这条与已有的凭据检查（R2/AWS）同源。

## 三、升级

- 服务端镜像：`picoaide-server-2.7.1-amd64.zip`（更新服务器与 GitHub Release 同步提供）；
- 升级与回滚步骤见部署说明（`docs/deploy/AI-DEPLOY.md`）：禁止 `down -v`、禁止用 `latest`、
  升级前必须备份、不得覆盖已有 `.env`；
- 客户端：随服务端镜像下发，服务端升级后员工的客户端即可从自己的服务器取到**已公证**的安装包。
