# v2.7.3-beta.1（2026-09-13）

> 一句话：一轮多 Agent 安全审计的修复版 —— **1 个 P0 与 20 个 P1**，覆盖服务端计费、
> 深链登录、客户端凭据保护与服务端管理台。**所有客户端与服务端都建议升级**；
> 服务端含数据库迁移（自动应用，无需手工操作）。

## 一、请优先关注这几项

### 1. 浏览器单点登录：链接里的服务器地址不再被信任（P0）

**现象**：员工点开一个指向**真实公司服务器**的登录链接并在公司统一登录页完成登录后，
登录凭证可能被发送到链接里指定的**其它服务器**。攻击者不需要伪造登录页、不需要密码，
用统一登录（SSO）或双因素（MFA）的同事同样会中招；被拿走的凭证有效期 90 天，等同于
该员工在公司服务器上的全部权限。

**本版怎么修**：服务端只接受来自"服务端自己配置的地址"的登录回跳（不再信任请求里带的
主机名）；客户端把"是否更换服务器"的判断提前到**发出任何网络请求之前**，没有正在等待
的登录目标时一律拒绝。客户端与密码登录、正常单点登录流程都不受影响。

### 2. 客户端凭据保护（P1，多项）

- **注入的凭据不再从错误提示里漏出**：此前机器人操作失败时，错误文案里可能逐字带上
  刚才注入的密码（当页面把密码当作元素 id 时）。现在所有对外文本（快照、错误提示、
  页面正文、执行结果）统一先脱敏再截断。
- **同一网站的另一个标签页不再能读回密码**：此前凭据保护只认"当前标签页"，
  在同网站新开一个标签页就能通过读取网页存储拿回刚注入的密码。现在保护跟随**网站**
  （并加 5 分钟上限与数量上限，避免长期占用）。
- **截图不再抢在保护生效前拍到密码**：此前的检查在排队之前做，若前面的操作（如等待页面）
  正占着执行权，截图会排在注入之后执行并拍到已填好的密码。现在检查与执行在同一临界区内。

### 3. 服务端计费（P1，多项）

- **流式对话在余额不足时不再"送完整回答却不扣费"**：此前余额不足的判定发生在回答已经
  全部发完之后，扣费失败会连带把这一次的用量记录一起回滚 —— 表现是员工拿到完整回答、
  账单上是 0，而且可以无限重复。现在这类欠款如实入账（欠款会拦住后续请求），
  非流式请求仍在**未交付**时就拒绝。
- **客户端无法再关掉自己的计量**：此前请求体里一个 `include_usage:false` 就能让上游不回报
  用量，输入侧因此永久按 0 计费（实测一次 16 元的调用只记 0.52 元）。现在计量开关由服务端
  持有。
- **补齐输入侧的兜底估算**，同时把"估算把图片按字节当 token"（会把一次调用算成 300 倍价钱）
  与"文本伪装成图片把费用压低"（最低可压到三百分之一）两个方向都收口。

### 4. 服务端管理台与共享内容（P1）

- **渠道素材脚本执行**：带脚本的渠道 logo 被直接打开时会在服务端域上执行，并可读走
  管理台的会话令牌。现在素材下发统一带沙箱策略并在下发前做脚本特征检查，管理台自身也
  补齐了安全响应头。
- **审计员角色**不再看到注定失败的写操作按钮（此前用户页/部门用量/模型分析整页 403 空页，
  登录后不刷新还会看到全套写按钮）。
- **共享库与市场内容不再互相串**：市场下架的智能体不再出现在共享库/审批队列/能力中心，
  市场授权替换不再连带删掉用户级授权，授权弹窗不再因为响应格式不一致而清空授权。

## 二、其余修复（按域）

**认证与会话**
- 管理员会话令牌只存哈希（迁移 0066：升级后**现有管理会话全部失效，管理员需重新登录一次**）。
- 双因素（TOTP）校验加入重放保护；第二步校验与登录失败共享限流，不可无限爆破。
- 未认证请求无法再靠大量密码校验耗尽内存；单 IP 失败预算与全局并发闸统一。
- 外部身份（统一登录/LDAP）与身份提供方主体绑定，同名不同主体一律拒绝，避免接管同名账号。
- 定时任务（cron）与桌面更新的本地接口补上持有性证明 —— 此前本机任意程序伪造请求头
  即可写入并立即执行定时任务、或触发更新安装。

**LLM 网关**
- 按**实际命中的上游**计价（迁移 0065），同名模型多上游时不再可能命中 0 价。
- 上游错误响应体只透传必要字段（不再原样回传可能含密钥的全文）。
- 单用户并发请求有上限；流式 pending 记录的保留时间从 1 小时延长到 6 小时。
- 极宽的同名数据分区不再被误判为"边界错误"（此前会导致整月计量写入失败且不自愈）。

**技能与智能体上架**
- 智能体的行为编排文件此前**从未被审核界面读取**（超过预览上限时静默变成空白且不报错），
  审核员看到的是空内容、员工装到的却是真实编排。现在编排必须可读且可解析才能上架，
  内容也真正展示给审核员。
- 上传归档的完整性校验覆盖全部条目（损坏的附件不再留到员工安装时才报错）。
- 归档解包闸门加固：YAML 别名/合并炸弹（曾用 573 字节换 131 秒 CPU）、同名文件重复、
  文件与目录同名、符号链接条目等。

**客户端其它**
- 记忆插件的全部写入落点统一加符号链接断言（此前目录级符号链接可让写入落到仓库之外）。
- 桌面更新协调器的定时器不再被并发操作互相取消（此前"检查更新"可能永久变成静默无操作）。
- 诊断包权限收紧到 0600，且渠道构建导出的诊断包不再指向官方数据目录
  （此前会把另一个安装的会话 id 混进给厂商的支持包）。

## 三、升级与回滚

- **服务端**：按 `docs/deploy/AI-DEPLOY.md` 执行 —— 从更新服务器取本渠道镜像包
  （`<渠道>/releases/v2.7.3-beta.1/picoaide-server-v2.7.3-beta.1-amd64.zip` +
  `SHA256SUMS`）→ `docker load` → 切换 `SERVER_IMAGE` → `docker compose up -d server`
  → 健康检查。**迁移 0064–0067 自动应用**；其中 0066 会让现有管理会话失效，
  升级后管理员重新登录一次即可。
- **客户端**：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包更新；
  也可从门户下载安装包手动重装。
- **回滚**：把 `SERVER_IMAGE` 改回上一版本标签并重启 server 容器。本版迁移为新增表/列，
  回滚镜像不会破坏数据，但**不建议**在回滚后继续使用新写入的外部身份绑定与会话哈希数据。
  仅回滚服务端**不会**把已升级的客户端降级 —— 若要回退客户端，请重装上一版安装包。

## 附件与校验

- 更新服务器：`<渠道>/releases/v2.7.3-beta.1/`（镜像包 + `SHA256SUMS`；同目录
  `latest.json` 指向本版）。
- 公开渠道另见 GitHub Release `v2.7.3-beta.1` 的附件
  `picoaide-server-v2.7.3-beta.1-amd64.zip` 与 `SHA256SUMS`。
- 校验：下载后 `sha256sum -c SHA256SUMS`（或与 Release 附件中的哈希逐字比对）再解压升级。
