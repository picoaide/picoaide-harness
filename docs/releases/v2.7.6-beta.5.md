## 一、登录可见的应用打不开（已修）

**谁需要关心**：所有用「登录可见 / 白名单」模式发布应用的团队。

- **现象**：打开这类应用会跳到换票页，然后提示「请求来源校验未通过」，**页面上没有地方输入账号密码**；
  应用自己的同源表单（例如留言墙的提交按钮）也一律失败。
- **原因**：平台页面下发了 `Referrer-Policy: no-referrer`。按浏览器规范，这会让**同源表单提交**
  的 `Origin` 变成字面量 `null`，平台的来源校验于是必然拒绝 —— 连员工登录入口本身都是 100% 不可用。
- **修复**：页面与响应头改用 `same-origin`（跨源仍然一个字节都不发，原有的隐私意图不变），
  来源校验失败时**保留登录表单**并给出可操作指引，失败路径补上诊断日志（此前完全静默，
  是这个问题长期无法定位的直接原因）。
- **自证**：真实浏览器探针跑通「匿名访问 → 换票 → 登录 → 进入应用 → 同源表单 POST 落库」全链路；
  `Origin: null` 与跨源仍被拒；门禁用例把「策略绝不能回到 `no-referrer`」钉死。

## 二、同一个应用的请求不会再有意义地并发（已修）

**谁需要关心**：应用会有多人同时使用的团队。

- **现象**：同一个人数稍多的应用，第二个请求要排队等第一个跑完，页面明显卡。
- **原因**：同应用串行由**四层**叠加造成（每应用并发=1、数据库句柄被整请求独占、应用库一把读写共用锁、
  连接池只有 2 条），只调大并发数并不生效 —— 阻塞点只是从队列挪到了锁上。
- **修复**：应用库启用 **WAL** 与 `busy_timeout`、只读连接池（默认 4 条）与读写锁拆分、
  句柄池不再整请求独占；同应用默认 **4 个请求并发读**（写仍由 SQLite 单写者串行），
  控制台可调 `app_running` / `app_db_readers`。
- **自证**：并发读的真实往返不再线性排队；连接关闭与在途读者之间有排空协议与 `-race` 用例；
  「限制项改了不生效」类问题有装配级用例钉住。

## 三、内存护栏在容器里也生效（已修）

**谁需要关心**：给服务端容器设了内存上限（compose `mem_limit`、K8s limits）的部署。

- **现象**：给容器设了 2 GB 上限，平台启动自检却按**宿主**的可用内存放行，运行一段时间后被内核 OOM-kill。
- **原因**：内存四笔账的"可用内存"只读 `/proc/meminfo`，而容器里这个值是宿主的，与 cgroup 限额无关。
- **修复**：改为 **cgroup v2 / v1 感知**（取 `min(宿主可用, cgroup 剩余)`），并把"数值来自哪里"
  （host / cgroup / none）同时写进启动日志与 `/readyz`；读不到时**明确声明"跳过内存自检"**，
  不再与"内存充足"混为一谈。
- **自证**：容器限额下自检按限额判定；cgroup 有/无/无限制/读不到四种形态都有单测。

## 四、运行期稳定性：应用收尾期间关闭实例会让服务端崩溃（已修）

- **应用写完响应后继续运行会崩服务端**：平台在收到合法响应帧后会立刻关闭该应用的运行实例，
  而此时应用可能还在执行收尾代码 —— 实测可触发运行期数据竞争并让**整个服务端进程崩溃**。
  现在改为"先取消、等实例真正退出（250 ms 宽限）、再关闭"，并给应用执行体加兜底恢复。
  `-race` 下对应用例已转绿（`-count=5` 复现命令见下）。

## 五、管理端：应用中心、审批闭环与限制项

- **应用中心合并为三页**：应用 / 限制项 / 设置（应用域名），侧栏不再有两个同图标入口，
  老路径自动重定向。
- **审批闭环补齐**：开启「更新审批」后，管理端可以列出待审版本并通过 / 拒绝；
  此前这条链路只有开关没有出口（等于"全组织永久停止接收更新"）。
- **限制项改动会说明后果**：内存账（实例池 + 编译峰值 + 上传峰值 + 模块缓存 + **应用库页缓存**）
  与可用内存水位同屏，超出水位直接拒绝保存；`instance_memory_mb` 明确标注"需重启"，
  并说明重启后**一定**等于设置值。
  ⚠️ 行为变化：SQLite 页缓存这笔最坏情况常驻以前**不在账里**（控制台可以把它配到远超物理内存
  而判据一动不动），现在计入并参与保存判定。

## 六、内置技能与作者手册

- 作者技能更名为 **`app-builder`** 并**随服务端镜像发布**（此前源码在客户端 vendored 包里），
  员工在能力中心按需安装；管理端新增「内置技能」页，可以看到平台内置了什么。
- 作者手册修正了「同应用串行 / 平台没有并发旋钮」的**过时表述**（与真源 `app_concurrency=4` 矛盾），
  并加了自动化门禁防止再次漂移。

## 七、并入的服务端审计修复（相对 v2.7.6-beta.4）

- **登录 / MFA 限流按真实客户端 IP 记账**：反代之后此前会坍缩成全组织一个桶 ——
  60 次失败登录即可让所有人锁 5 分钟。
- **审计读侧脱敏补全**：凭据型 URL 的各种形态（分号分隔、数组式、`access-token`/`api-key`/`authorization_code`）
  不再以明文出现在审计里。
- **归档解包**：tar 头 `'0'` + 尾斜杠 + 非零 Size 的条目不再被当成"已跳过数据区"，
  员工无法再装出审核页从未显示过的文件。
- 网关配置写入事务化、渠道同步不再静默停更、报表排序确定化、`/readyz` 依赖漏填改为装配期失败。

## 八、更新版本时的配置沿用（行为变化，作者需要知道）

- **改前**：发新版本时提交的 `config` 是**整体替换**。省略 `access` 会被按缺省落成
  `login` —— 也就是给一个白名单应用发"纯代码更新"，会**静默把它放宽成登录后全员可用**；
  省略 `purpose`/`data_sensitivity`/`owner` 则会把它们**清空**。AI 助手按工具描述
  （"省略未改动的，服务端沿用原值"）省略字段时正好踩中这条路。
- **改后**：更新版本时**缺席的字段从上一版"生效"配置继承**，然后照常校验；**显式给值仍然以
  提交为准**（想改成 `login`、想清空名单，照写即可）；首次发布的行为不变（缺省仍是 `login`）。
  继承基线是**已通过审核并生效**的那一版，待审版本的配置不会成为下一版的默认值。
- **同时修掉**：审核开关打开时，待审版本的配置不再立即投影到应用目录（此前目录会先展示未经
  审核的访问级别徽标）；**通过**审核时才按最新通过的版本重算目录配置，**拒绝**则目录保持原样
  （它从未被待审版本改动过）。

## 已知限制（本版认账，未修）

- **SSO（OIDC）组织暂时无法在浏览器里打开「登录可见」应用**：平台目前**没有浏览器会话式的 OIDC 登录**
  （现有 OIDC 接口是给桌面客户端深链用的）。规避：这类应用暂用 `public` 模式，或等后续版本的
  浏览器 SSO。白名单模式同样受影响。
- **归档保留期到期后的"真删"尚未实现**：应用数据进入保留期后不会自动物理删除（管理端文案已修正为如实描述）。
- **静态资源的缓存与 304 复验**：每个静态子资源仍会走一次"读盘 + 哈希"，复验（304）不比首次便宜；
  并发压力下的固定开销高于必要值（已列入后续优化，不影响正确性）。
- **`/readyz` 未认证**：会暴露磁盘余量、编译队列与缓存计数（水位信息，不含凭据）。
- **演示应用的删除入口**：作者可在客户端应用中心自助下架/删除自己的应用；管理端目前没有删除入口。
- **换票链接缺少"发起浏览器"绑定（安全问题，下版修）**：应用子域的换票兑换目前不校验来源/浏览器，
  因此一个已登录员工把自己拿到的换票链接发给别人，对方打开后会**以该员工身份**进入应用
  （登录 CSRF）。影响面：需要受害者主动点开链接，且主站与应用子域同域部署下的会话 cookie 仍是
  host-only。**规避**：不要把应用子域的换票链接转发给他人。下版按"签发时下发 SameSite=Strict 的
  一次性 nonce cookie + 兑换侧比对 + `Sec-Fetch-*` 纵深"修复。
- **应用日志可伪造平台日志行（安全问题，下版修）**：应用通过 `log` 原语写入的文本会被原样转写到
  服务端日志，理论上可拼出与平台组件同形的行、并注入 ANSI 转义。**审计链（数据库）不受影响**，
  仅影响日志/SIEM 与运维终端；下版加净化。
- **未识别主机名仍会回落主站**：配置了应用基域时，既不是主站也不是 `<标签>.<基域>` 的 Host 仍会
  命中门户/管理台（凭据钓鱼面，主站会话 cookie 为 host-only 不共享）。下版改为 404。
- **演示应用播种的失败顺序**：播种时先记录"当前版本"再写资源目录，中途失败会留下"指向不存在的
  资源目录"的应用（访问 500、重启不自愈）。仅影响随镜像内置的三个演示应用的首次播种。
- **`instance_memory_mb` 的下调不作用于发布期编译**：编译子进程仍按编译期默认 64 MiB 运行；
  把该值调到 64 以下时，可能出现"发布通过、首次请求 500"。
- **应用内存超限的诊断码不可达**：Go 应用超限实测报 `RUNTIME_GUEST_EXIT(exit 2)` 而不是文档承诺的
  `RUNTIME_MEMORY`（诊断里 `peak_memory_bytes` 会贴近上限，可据此判断）；作者手册的失败表下版同步。
- **驳回理由到不了发布者**：审核开关打开后被拒的版本，发布者只能看到"待审核"，看不到结论与理由
  （管理端已可筛选查看）。下版补员工面的版本查询出口。
- **内置技能的"更新"入口不生效**：能力中心里已安装的技能不会显示"更新到 vX"（判据被过滤掉），
  需要先卸载再安装；随镜像分发的作者手册里"哪些导入合法"也未随技能交付（作者只能按 422 报错试错）。
- **平台自带 HTML 页没有站点图标**：门户/登录/换票页未声明 `<link rel="icon">`，浏览器控制台每次
  会有一条 `/favicon.ico` 404（不影响功能）。
- **作者手册两条表述与实现不符（下版修）**：①"没参数化会得到 `DB_DENIED`"——平台并不检查参数化
  （SQL 注入仍须应用自己用参数写）；②"静态资源编进 wasm"缺官方打包工具，需要作者自行实现
  wasm 自定义段格式。
- **归档解包的保留期清理**、**管理端运行时水位有四项取不到**、**准入拒绝（429）不计入任何计数器**、
  **`/readyz` 的"执行槽已满"判据仍按编译期 32 计算**：均为已认账的运维可观测性/清理缺口。

## 升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级（**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
- 回滚：保留上一版镜像 tag，改回即可（本版**无新增数据库迁移**，回滚不涉及数据变换）。
