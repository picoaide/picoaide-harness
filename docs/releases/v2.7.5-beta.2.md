## 一、macOS：记忆写入恢复可用（必须升级）

- **现象**：macOS 客户端上，AI 的记忆**一条也存不进去**（待办、归档、记忆同步同样失败），
  记忆面板里报一句很像误报的错：「`.memory.lock` 是符号链接（或越出仓库边界）——已拒绝写入」。
  用户去查看目录，那里**没有任何符号链接**，`.memory.lock` 都是 0 字节的普通文件，
  而且每试一次就多一个（看起来像"锁没清干净"）。
- **影响**：读取一切正常，所以很容易被误判成"偶发"；实际是**写入全军覆没**——
  所有会话的进展、约定、待办都无法沉淀。
- **原因**：程序在"确认文件真正落在允许的目录内"这一步，用系统提供的"文件描述符 →
  真实路径"反查能力去核对落点；这项能力在 macOS 上**不生效**（返回的是查询入口自身，
  而不是真实路径），于是**完好的落点被误判成"跑到了目录外面"**，写入被安全闸门拦下；
  清理残留锁时又因为同一个原因删不掉文件，锁就一次次堆积。
  该问题只在 macOS 上出现，此前的自动化验证都跑在 Linux 上，所以一直没被发现。
- **修复**：只有在**真的查到真实路径**时才拿它做核对；查不到（macOS 的情形）就跳过这一步，
  由后续的"落点身份复核 + 路径链复核"继续把关——安全强度不降，误判消失。
- **自证**：把"macOS 的行为"在 Linux 上原样模拟出来复现现场——**修复前该用例抛出的正是
  用户看到的那句逐字相同的报错**；修复后锁能取到、记忆确实落盘、且不再产生残留锁。
  另有一条在真机上直接断言的用例。

## 二、不再因为一个损坏的状态文件导致客户端打不开

- **现象**：客户端启动后**直接退出**，没有任何界面，也没有提示。
- **原因**：记忆模块把"界面里改过的设置"存在一个小文件里；这个文件一旦损坏
  （断电写坏、被同步工具截断、误建成同名目录等），模块在**加载阶段**就报错并让整个
  插件树加载失败，客户端据此退出——用户只能自己去数据目录里删文件才能打开。
- **修复**：这类损坏改为**软着陆**：把坏文件改名留档（保留最近 3 份，便于排查），
  以默认设置继续启动；同时**主动告诉用户**——AI 会在你下一条消息里说明"设置被重置了、
  备份文件在哪"，而不是让你自己发现。
- **同批**：记忆模块里的评审功能在"数据目录不可写"（只读家目录、磁盘写满、目录被文件占位）时
  也不再拖垮整个客户端启动。
- **自证**：截断的 JSON / 0 字节 / 同名目录 / 不可读路径四种损坏形态逐个回归；
  留档、扫描与"只提示一次"的行为都有断言。

## 三、界面语言切换后，记忆相关面板真正跟着切换

- **现象**：在「设置 → 通用 → 语言」里把界面切成英文后，**记忆面板、CLI 调度、提示词、
  广播、评审面板、待办、同步**这些子页面的文案仍停在中文（或反过来）。
- **原因**：这些面板各自带了一份中英对照文案，但判断"该用哪种语言"时看的是**操作系统语言**，
  而且在程序启动那一刻就定死了——用户后来在设置里改语言，它们不会跟随，也没有任何报错。
- **修复**：改为**每次显示时**读取当前界面语言，切换立即生效。
- **同批**：桌面托盘与系统通知的语言现在也认得 `zh-CN` / `en-US` 这类带地区的写法
  （此前只认 `zh` / `en`，于是可能出现"中文界面配英文托盘"）。
- **说明**：这批修的是**跟随行为**；这些面板的文案本身仍是中文，英文界面的完整补译在后续版本。

## 四、AI 的记忆调用契约与语言一致性

- **`key` 轨（项目长期记忆）的列表查询**现在默认只显示**当前 git 分支**可见的条目——
  与"注入到上下文"和"按 id 展开"保持一致。此前列表会把只属于其它分支的条目也列出来，
  那些条目既不会注入也用不上，容易让 AI 误判。需要跨分支查看时，可以在
  「Memory Evolve 设置 → key 轨分支过滤」里关掉过滤，或查询时显式指定分支。
- **按需加载全文**的调用形态在提示词里写全了（此前给的是简写，AI 照做会撞上一条与当前操作
  无关的报错），缺参数的提示也按操作类型区分。
- **英文界面下**，记忆评审给出的建议与问答回答改为英文——此前无论界面语言都输出中文，
  而这些建议是**以用户指令的形式**进入主对话的，中英混排会直接影响阅读。中文界面的
  行为**逐字未变**。

## 五、随包内置技能恢复

- v2.7.5-beta.1 的安装包在瘦身时误把随包技能目录一起排除了，导致 5 个内置技能
  （含本版新增的「记忆合并梳理」）在客户端里一个都装不上，且**完全静默**。
- 本版恢复随包，并给打包流程加了一道逐条清单校验：清单必须覆盖技能目录里的每个文件，
  少一个就拒绝出包。

## 升级与回滚

- 服务端：取本渠道更新服务器上的本版镜像包（`beta/releases/2.7.5-beta.2/`，同目录
  `SHA256SUMS` 先校验），按 `docs/deploy/AI-DEPLOY.md` 升级；**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
- **macOS 用户升级后无需手工清理**：此前堆积的 0 字节 `.memory.lock` 会被判定为过期锁
  自动删除，重新写入即自愈。
- 回滚：保留上一版镜像 tag（`picoaide-harness-server:beta-2.7.5-beta.1`），改回
  `SERVER_IMAGE` 后 `docker compose up -d server` 即可（**本版无数据库迁移**）。

## 附件与校验

- `picoaide-server-2.7.5-beta.2-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），
  包内另含本渠道的客户端安装包；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压导入。
