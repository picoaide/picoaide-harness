## 一、应用标识：占用与否，填表时就知道

- **现象**：在应用中心发布自己写的应用时，应用标识（`app_id`）此前**没有任何检查**。
  用户填完名字、选好文件、等一次完整上传（最大 32 MiB）与服务端编译，
  才在最后一步收到「名称已被占用」——而这个名字可能在他开始填之前就被同事占了。
- **影响**：每一次重名都浪费一轮完整上传与编译；慢网络下这一轮可能要等几十秒到几分钟。
  更麻烦的是，用户往往在提交失败后才回头改名字，然后又撞上第二个已占用的名字。
- **修复**：
  - 输入应用标识时**自动检查**（停止输入约 0.4 秒后发起，不打断打字）；
  - 结论分四种、各自可辨：**可以用** / **这是你发布的应用，可以发新版本** /
    **已被占用，请换一个名字** / **名字不符合命名规则**；
  - **提交前再核一次**：即使界面上的结论是几百毫秒前的，提交那一刻也以服务端的
    当下事实为准。被占用时**一个字节都不会上传**，直接指出问题。
  - 名字不合规时**不发起网络请求**（本地规则就能判断），省一次往返。
- **为什么不能复用「应用列表」来判断**：应用中心列出的应用是**给人浏览**用的，
  它不显示已冻结的应用、也不显示"占了名字但从未发布成功"的记录 ——
  而这两类**都仍然占着这个名字**（平台规则：发布即占名，下架、删除都不释放）。
  拿列表判断唯一性会得出"这个名字没人用"的**相反**结论。因此本版新增了一条
  专门的只读查重接口，它与真正发布时用的是**同一套判定**，所以两者的结论必然一致
  （同一个错误码、同一句提示）。
- **查重失败不会挡住你**：如果查重接口本身暂时不可用（宿主故障等），
  界面会说明"暂时无法确认"，但**提交照常可以进行** —— 最终判定权始终在服务端。
  查重是为了省事，不能变成新的故障点。
- **不泄露**：只告诉你"这个名字被占了"，不告诉你是谁占的、他发布的是什么。

### 对作者与运维的提示

- 给已有应用发新版本时**不做**这个检查：应用标识一经发布就不能改，
  这种场景不存在"名字冲突"。
- 管理员仍可通过管理后台「应用中心」转移归属（离职接管等），不受本功能影响。

## 二、上游升级：DSH 0.1.6-alpha.2（访问模型不变）

本版把内置的 DeepSeek Harness 从 `0.1.5-rc.2` 升级到 `0.1.6-alpha.2`，
并处理了随之而来的兼容性改动（含 9 项 P0、13 项 P1 与 10 项打包门禁）。

- **对员工可见的变化**：客户端升级到 0.1.6 后，**新增终端面板**；
  右侧栏与设置页的插件组织方式跟随上游调整（定时任务配置卡从"设置"迁到"插件"页）。
- **对运维可见的变化**：服务端多了一层**模型名称清洗**（把上游可能透出的内部模型标识
  归一成对外名称），并**关闭了会话日志出境**与三行冲突的默认配置。
- **访问模型没有变化**：应用仍然只在桌面客户端内打开（2026-09-19 定的模型），
  浏览器入口依旧不可用，本版不涉及该模型的新变更。
- **必须同版本升级**：服务端与客户端**必须同版本**。旧版客户端连接到本版服务端会
  出现功能不可用；一句话结论照抄：**若你使用旧版客户端，请先升级到本版再使用应用功能。**

## 已知限制（本版认账，未修）

- **查重结论不是锁**：查重与提交之间存在时间窗，理论上他人可以在这一瞬完成抢注。
  遇到这种情况，提交仍会按既有规则返回「名称已被占用」——查重只是把问题提前暴露，
  不能替代服务端在发布那一刻的判定。
- **通用占位域名**：上游 0.1.6 的模型清洗只做名称归一，不改变任何计费口径。

## 升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**：应用数据 + 数据库；不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
  **本版客户端必须与本节服务端同版本**。
- **回滚**：本版**无数据库迁移**，属于「只加列 / 只建表」之外的最轻一档 ——
  保留上一版镜像 tag，改回 `SERVER_IMAGE` 后 `docker compose up -d` 即可。
  无需恢复数据库备份。
- 若本版**不提供降级通道**：不适用（新旧模型可以并存，回退镜像即可）。

## 附件与校验

- `picoaide-server-2.7.7-beta.1-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
