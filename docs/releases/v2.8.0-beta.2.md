# v2.8.0-beta.2

> 预发布（beta 渠道）。只影响 beta 渠道的客户端与服务端；正式渠道与客户渠道**不在本版范围内**。
> 本版是**纯客户端 UI 修复版**：服务端行为与 v2.8.0-beta.1 相同，无新增数据库迁移。

## 谁应该升级

- **beta 测试环境**：建议升级。本版修掉一个所有功能面板都会撞上的可用性缺陷（内容长出屏幕后
  翻不动页），以及一批"点了没反应/提示看不见/键盘走不通"的交互问题。
- **遇到下面任一现象的用户**：升级后即恢复（这些现象在 v2.8.0-beta.1 及更早版本上都能复现）：
  - 能力中心、应用中心、连接器、定时任务的下拉列表**滚不到底**，最下面的卡片看得见摸不着；
  - 定时任务卡片右端的「删除」被挤出卡片、被裁掉；
  - 在能力中心点开某张卡的「详情」后按 Esc，**整个面板被关掉**、回到会话区；
  - 在发布表单里按 Esc（或搜索框里按 Esc）把整个应用中心关掉，填了一半的表单直接丢失；
  - 定时任务保存失败只显示 `cron action failed: 400`，看不到原因。
- **不升级的影响**：以上问题继续存在；数据与配置不受影响，不会丢东西。

## 一、四个功能面板整体不能滚动（本版最重要的一条）

- **现象**：面板内容比窗口高时，页面向下滚不动 —— 卡片列表下半部分、卡片上的按钮都够不到。
  四个整页面板（能力中心 / 应用中心 / 连接器 / 定时任务）**全部**如此。
- **原因**：面板的高度在中间一层断了（面板根容器没有高度），导致内部滚动区拿到的是"内容高度"
  而不是"可见高度"，于是它永远不产生溢出、也就永远不出现滚动条；内容被外层裁掉。
  实测：内容高约 2714px、可见区域 813px，滚动位置设置无效。
- **修复**：把高度约束改到共享的面板外壳上，四个面板与后续新增面板一次性都拿到正确行为。
- **自证**：客户端端到端脚本新增「面板正文可滚动（内容超出时能翻到底）」断言 —— 往正文里注入
  超高内容后，必须真的产生溢出且滚动生效；四个面板在 720×560 到 1280×900 各档宽度下都通过。

## 二、定时任务卡片：动作行不再溢出

- **现象**：窗口或右栏窄一些时，卡片底部的「立即执行 / 编辑任务 / 执行详情 / 删除」一行放不下，
  「删除」被挤出卡片右边界、只露一半，需要横向滚动才能点到。
- **修复**：动作行允许折行；同时补上此前缺失的端到端覆盖（此前端到端脚本里的定时任务列表恒为空，
  卡片布局从未被渲染过，所以这条一直没被测出来）。

## 三、面板里的 Esc、焦点与反馈

- **Esc 分层**：能力中心的详情弹层、定时任务的编辑弹窗打开时，按 Esc 现在只关掉弹窗那一层，
  不会再连整个面板一起关（此前会把用户从面板踢回会话区、草稿全丢）。
- **焦点**：弹窗打开后 Tab 不会跑到遮罩后面看不见的按钮上；关闭弹窗后焦点回到打开它的按钮。
  定时任务的编辑器补上了字段名与控件关联（读屏不再念"未命名编辑框"）。
- **不再有"点了没反应"**：某个安装/卸载/上传正在进行时，其它卡片的按钮会明确置灰（此前看起来
  可点、点下去被静默忽略）；安装结果提示会自动滚进视口（此前它在滚动区顶部，列表滚到下面时
  完全看不到，用户以为按钮坏了）。
- **表单防重复提交**：发布前的名称查重窗口内按钮即置灰 — 此前连点两下会发起两次完整上传，
  后一次的错误还会把已经成功的界面改写成"失败"。
- **文件可重选**：选择文件失败后再选**同一个文件**现在会正常触发（此前浏览器不再派发事件，
  界面毫无反应）。

## 四、定时任务：失败原因可见、保存前拦下不可能的表达式

- **失败原因**：服务端返回的失败原因与操作指引不再被丢掉，界面显示的是具体原因而不是
  `cron action failed: 400`。
- **保存前校验**：像 `0 0 30 2 *` 这种"语法合法但在日历上永远不会触发"的表达式，现在会在保存前
  被就地拦下并说明；此前它会通过校验、弹窗关闭、任务没建成，用户只看到一个 400。
- **设置开关**：三个开关补上了名称与"正在读取"状态；设置读取完成前开关不可点（此前那一瞬间
  显示的是默认值而不是已保存的值），保存失败会显示原因而不是静默弹回。

## 五、连接器：清空预填值不再被改回来

- **现象**：把服务端预填的默认值删掉后约 2 秒它自己又回来了，导致无法提交"留空"的表单。
- **修复**：预填只在一次连接开始时做一次，之后不再覆盖用户输入。

## 六、内置浏览器

- **空格/回车不再误夺控制权**：AI 操作期间按空格（想翻页）不再变成"我来操作"、也不再把正在跑的
  工具调用打断；键盘操作仍然可用（Tab 到按钮后回车/空格照旧）。
- **首次使用的死路**：空态提示此前指向被蒙版盖住的 ＋ 按钮，现在指向真正可用的「我来操作」。
- **工具栏不再被遮挡**：打开活动面板时，右上角的「新建标签」与「更多」按钮保持可点。
- **Ctrl+L 一次到位**：此前第一次只把焦点还给页面、需要按两次才进地址栏。
- **中文界面不再混英文**：活动面板里的动作名称与时间线文案按界面语言显示，未登记的工具不再直接
  显示内部标识符。
- **标签栏可键盘操作**：标签可以用 Tab 聚焦、回车/空格切换，关闭按钮是真正的按钮且聚焦时可见；
  刷新不再把标签整条重建（此前刷新一次焦点就丢）。
- **失败提示可见**：持有控制权期间"交给 AI"或打开面板失败时，提示不再被裁在 172×34 的胶囊视图里，
  用户能看到具体失败原因。

## 已知限制（本版认账，未修）

- **渠道暗色 logo 在客户端不生效**（仍未修）：渠道配置了暗色版 logo 时，登录页与侧边栏在暗色
  主题下仍显示亮色版（服务端门户已按系统主题切换，两端不一致）。影响仅限视觉，计划中。
- **能力中心每 30 秒的市场刷新可能短暂回退刚完成的安装状态**（仍未修）：极端时序下卡片会短暂
  显示回"安装"，最多 30 秒后自愈。
- **详情弹层内的"按版本安装"结果仍显示在弹层外**（仍未修）：安装成功/失败的信息在弹层后面的
  列表面板顶部，需要关掉弹层才看得到。
- **内置浏览器的部分动作文案仍为英文**（本版已修四类高频文案，剩余低频动作未覆盖）。
- 本版**无新增认账项**；以上均为既有残留。

## 升级与回滚

- 服务端：取本渠道镜像（`https://release.picoaide.com/beta/releases/2.8.0-beta.2/`），按
  `docs/deploy/AI-DEPLOY.md` 升级（升级前必须备份；不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发；服务端升级后员工从自己登录的服务器取包，无需访问外网。
  客户端版本号为 2.8.0-beta.2，数据根仍为 `.picoaide-harness`（与上一版一致，登录态与历史会话延续）。
- **回滚**：本版无新增数据库迁移，回滚只需把镜像 tag 改回 v2.8.0-beta.1 并
  `docker compose up -d server`；客户端重装上一版即可（服务端数据无需恢复）。
  注意：回滚后本版修复的 UI 问题会随之回来。

## 附件与校验

- `picoaide-server-2.8.0-beta.2-amd64.zip`：服务端镜像压缩包（`docker load` 后使用，内含本渠道
  三平台客户端安装包）；
- `SHA256SUMS`：`sha256sum -c SHA256SUMS` 校验后再解压。
- 门禁：本版通过整仓检查（构建 / 类型检查 / 单元测试 / 9 项静态守卫）与客户端端到端脚本
  （含本版新增的面板滚动与卡片布局断言）。
