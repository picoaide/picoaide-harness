# PicoAide Harness v2.7.2-beta.2（2026-09-12）

本版是 **v2.7.2-beta.1 的修复版**，只修一个 P0：**Windows（以及 Linux）客户端的本地命令执行
与文件搜索全废**。不含新功能，**无数据库迁移**。

---

## 一、修了什么：`pwsh` 与 `glob` 在桌面端 100% 失败

### 现象

Windows 客户端上所有 `pwsh` 调用都返回：

```
Error: subprocess-local: Windows Job runner exited with exit code 0 before proving
its managed range empty
```

`glob`（内部走 ripgrep 子进程）同样是 `glob subprocess failed before reporting an outcome`。
用户会话包实测：78 次工具调用里 51 次失败，其中该错误 8 次、ripgrep 4 次；MCP 调用正常
（故障只在本地子进程这一条链）。

### 根因

上游子进程层用 `spawn(process.execPath, [runnerEntry, …])` 启动它的 runner 进程。
**打包后的 Electron 宿主里 `process.execPath` 是 GUI 二进制、不是 Node**，而 runner 的环境里
没有 `ELECTRON_RUN_AS_NODE` —— 于是子进程按"应用模式"启动（撞上单实例锁后立刻退出），
runner 入口（以 `import.meta.main` 守卫）一个字节都没执行。父进程要求 runner 经 IPC 回传结果，
拿不到就按 fail-closed 报上面那句，并且**不降级**到普通启动。

这个缺陷只可能出现在 DSH `0.1.5` 及以后（老版本没有这套 Windows Job runner），
即 **v2.7.2-beta.1 起受影响**。

### 修法

`patches/dsh-subprocess-local@0.1.5-rc.2.patch`：在 runner 的环境构造里，Electron 宿主下注入
`ELECTRON_RUN_AS_NODE=1`。

- **作用域安全**：只改 runner 自身的环境；用户命令的环境由另一条路径构造，不会把该变量泄漏给你
  执行的命令（否则你跑 `code .` 这类 Electron CLI 会被当成 Node 启动）。
- **一处修两个平台**：Windows 与 Linux 共用同一处代码（Linux 只是外面多套一层 `systemd-run`）。
  **macOS 不受此缺陷影响** —— 上游在 macOS 上直接走降级路径（代价是没有原生进程托管，属上游现状）。

## 二、验证

- `corepack yarn check` 11/11 全绿（桌面端单测 679 项通过，含本版新增的 3 项补丁守卫）。
- 干净重装（删掉依赖目录再 `yarn install`）后补丁可自行重现，打包产物 `app.asar` 内确认含注入。
- 真实打包二进制上复现了两种行为：不注入 → 脚本根本不执行；注入 → 脚本正常执行
  （`import.meta.main === true`）。
- 新增守卫单测 `packages/host/desktop/tests/subprocess-runner-env.spec.ts`：Electron 下必须注入、
  纯 Node 下不得注入、用户命令环境不得被污染 —— 下次升级上游时补丁被丢掉会立刻红灯。

## 三、升级与验证建议

- **服务端**：与 beta.1 完全一致（无迁移、无接口变化），只换镜像即可。
- **客户端**：**必须重装本版客户端**才能拿到修复 —— 从服务端下载新安装包（服务端会下发
  `client.version = 2.7.2-beta.2`）。
- **请复验这两条**：① 让 AI 跑一条命令（例如 `echo hi`）应正常返回；② 让它做一次文件搜索
  （`glob`）应正常返回。两者都通即修复生效。

## 四、已知边界

- 这是**补丁**而非上游修复：上游 `subprocess-local` 目前没有 Electron 宿主适配。
  升级 DSH 版本时需要重新切一版补丁（`patches/dsh-subprocess-local@<新版本>.patch`），
  守卫单测会提醒。
- 本地开发时若跑过 `e2e:sidebar`，它会在 `packages/host/desktop/.e2e-sidebar/cfg/…` 留下
  悬挂符号链接 `SingletonSocket/SingletonLock/SingletonCookie`，导致之后 `electron-builder`
  打包报 `ENOENT: stat '/tmp/scoped_dir…/SingletonSocket'`（报错指不到病根）——打包前清掉
  `.e2e-*` 目录即可。
