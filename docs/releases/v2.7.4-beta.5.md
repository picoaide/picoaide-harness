## 一、人工接管会真正暂停 AI 的浏览器操作

- **现象**：用户点「我来操作」后，AI **已经在执行**的那一个操作（等待元素、加载页面、求值等）
  仍会继续跑完，期间用户和 AI 可能同时操作同一个页面。
- **修复**：用户接管时会中止 AI 已启动的页面加载；长操作在下一个协作检查点以
  “用户已接管”失败退出，不再继续写页面。
- **同批**：删除书签、删除下载、清站点数据等会改状态的数据工具，也重新纳入同一把用户闸；
  用户操作期间不会被 AI 旁路执行。接管按钮的请求增加超时，loopback 卡死时不会永久禁用。
- **自证**：新增接管中断 `waitFor`、导航失败上报、数据工具等待用户交还等回归用例；
  客户端端到端（真实点击 + 真实窗口）全部通过。

## 二、连接器：重启恢复与授权流程

- **重启后恢复**：以 API Key 等“表单字段”为凭据的连接器（token / device），重启后不再
  被当成未连接；必填字段齐全即自动恢复工具。
- **先填设置再授权**：带“接入设置”表单的 OAuth 连接器，提交设置后会继续真正的浏览器授权，
  不再直接注册一个没有授权的 MCP 连接；token 模式也不会跳过必填 token 表单。
- **断开更可靠**：断开与后台注册的竞态已消除，断开后不会再有旧注册把工具“复活”。
- **目录更稳**：服务端下发的连接器目录会校验认证模式；缺字段不再导致设置面板搜索崩溃。
- **其他**：OAuth 发现支持带路径的签发方；启动目录拉取增加超时；表单默认值会正确预填；
  畸形提交返回 400 而不是 500。

## 三、定时任务

- 权限预设下拉改为读取本机部署的权限名单，不再硬编码；选“只读”等不存在的名称不再
  得到一个无法理解的失败。
- 设备长时间休眠/关机后的补跑取**最近一次**错过触发，而不是很早以前的一次。
- `*/n` 形式的工作日/日期语义与标准 cron 对齐（`0 0 */1 * 1` 表示每周一）。
- 登录态恢复型启动时，定时任务正确绑定当前账号。

## 四、企业与账号

- 重启后自动恢复的登录会话会正确同步模型网关配置，不再出现“重启后要用一次登录才恢复”。
- 退出登录失败时不再直接刷新页面假装已退出；失败会显示原因，登录状态保持不变。
- 安装包按实际解压体积做上限校验，降低恶意压缩包导致客户端内存耗尽的风险。
- 账号卡/关于页的状态与货币格式跟随当前界面语言。

## 升级与回滚

- 服务端：从自己渠道的更新服务器取本版本镜像包（`<channel>/releases/2.7.4-beta.5/`，
  同目录 `SHA256SUMS` 校验），按 `docs/deploy/AI-DEPLOY.md` 升级；**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包。
- 回滚：保留上一版镜像 tag，改回 `SERVER_IMAGE` 后 `docker compose up -d server` 即可
  （本版无数据库迁移）。

## 附件与校验

- `picoaide-server-2.7.4-beta.5-amd64.zip`：服务端镜像压缩包（`docker load` 后使用）；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压导入。
