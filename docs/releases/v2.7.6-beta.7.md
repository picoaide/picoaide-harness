## 一、四个功能面板统一为「整页接管中列」

- **现象**：定时任务早就是"点一下把主区换成任务中心"，而**能力中心、连接器中心、应用中心
  仍是浮在会话之上的模态浮层** —— 遮住正在进行的对话、浮层内滚动与页面滚动打架、
  窗口一窄内容就被压扁、两个面板可以同时叠着开。
- **修复**：新增一个共享的**面板装载器**（新工作区包 `@picoaide/dsh-panel-surface`），
  四个面板的打开/关闭/互斥语义只在它一处实现（页面根上的激活标记 + 一次点击入口），
  点侧边栏入口即把中列换成整页，页首一个「返回对话」回到会话。
- **视觉层同样是共享的**：按钮（含加载中与禁用态）、卡片、胶囊、标签、分段控件、开关、
  空状态、滚动条样式 ——— 四个面板从此是同一套语言，不再各写一份内联样式。
- **自证**：客户端 E2E 对四个面板逐一断言**内容真的出现在中列**（归属 + 可见性），
  而不是只断言"入口按钮在"（后者在浮层时代也是绿的）。

## 二、能力中心：描述不再撑爆列表、全文进详情、内置技能分区修正

- **描述超长（实测反馈）**：卡片描述原来最多三行、点一下就地展开，展开后**整页跳版**，
  一屏放不下两条。现在列表描述**固定两行截断**，全文进**详情弹层**（点卡片打开），
  弹层里给完整描述 + 作者/来源/评分 + 该有的动作按钮。
- **没安装的内置技能出现在「我的」（实测反馈）**：内置技能的分区原来按"是否出现"判定，
  导致**默认没安装**的那条也进了「我的」。现在按**动作**分区 —— 可安装的进市场、
  可更新的进「我的」；判定写成纯函数并单独有判据。
- **另修**：同一张卡片上重复显示两个自制标记。
- **顺带**：内置技能的展示名与作者改为**渠道中性**的「应用构建（WASM 应用）」/「平台内置」
  —— 原来的名字里带产品名，在非官方渠道的客户端里看着像第三方内容。

## 三、应用中心：卡片网格与信息层次

- 之前是一堆文字直接堆在面板里（标题、作者、时间、说明、按钮同样粗细、同样间距）。
  现在按**卡片网格**排布：标题/作者/时间/访问模式成组，底部动作按钮固定对齐，
  **卡片高度不再随描述长短参差**，访问模式用颜色区分（登录 / 名单）。

## 四、内置演示应用：从 1 个变成 3 个功能不同的小应用

装完即用、可删除（与之前一致：制品打进镜像，服务端启动时播种）：

| 应用 | 形态 | 演示什么 |
| --- | --- | --- |
| 演示 · 能力全集 | **手机比例**（9:19.5） | 把平台给应用的每一项能力当场跑一遍：身份注入、访问模式、建表与增删改查、事务提交与回滚、应用日志、包内资源、**客户端 AI**（含被拒时的错误码与平台给的建议） |
| 演示 · 内部小论坛 | 电脑比例（16:9） | 一个真的能用的内部工具：版块 / 主题 / 回帖、置顶、搜索、分页、多表关系与事务写入 |
| 演示 · 留言板 | 电脑比例（16:9） | 最小可用形态：一张表、一次写入、一个列表；准入走**名单**，不在名单里的账号会看到一页显示本人账号的提示 |

- 演示的不再是"同一份 wasm 按三种权限各播一次"，而是**三个功能不同**的小应用，
  各自的**窗口比例**写在应用配置里，应用窗口按比例锁定。
- **升级后旧的三条演示应用（`demo-public` / `demo-login` / `demo-whitelist`）不会被自动删除**：
  播种的判据是"库里是否已存在这个 `app_id`"（删除后不再重建，这是既定语义）。
  管理员可以在应用中心手动删掉旧的三条，不影响新演示。
- 演示的**入口页由应用自己应答**（先判名单、再返回页面），所以"不在名单里"看到的是
  应用给的一页提示，而不是宿主的错误页。

## 五、应用构建技能重写（内置技能 v2.0.0）

对象是**有想法、但不会写代码**的业务同事 —— 用户只说"我想做个 XX 登记表"，
底层设计（数据模型、页面、权限、错误处理、边界、打包、发布、交付深链）由技能全部做完，
用户只在**设计访谈**里回答业务问题：

- **九阶段流程**：只听想法 → 设计访谈 → 设计卡 → **多角色评审** → 技术方案 → 脚手架与实现 →
  编译与本地自测 → 打包与发布 → 交付与验收。
  其中"多角色评审"由产品 / 安全 / 运维 / 使用者四个视角**挑设计缺口**，
  缺口再变成**对用户的追问**（附访谈问题清单，新增 `references/design-interview.md`）。
- **技术形态固定为前后端分离**：静态前端（HTML/CSS/JS 作为随包资源，宿主按路径直出）
  ＋ 一个 wasm 后端只回 JSON —— 明确禁止"在 wasm 里拼 HTML 字符串"。
- **一条命令链打包发布**：打包脚本与随技能分发的那一份**是同一个文件**，规则不会漂。
- **修正两处会直接误导的做法**：
  - `_row_id` 是平台**保留列**：把它写进 SQL 会在运行期被拒（不是导入期），查询要显式列名；
  - `ai.chat` **已删除**：应用里的 AI 走**客户端 AI loop**（保留路径 `POST /__picoaide/ai/chat`），
    老产物能通过发布校验，直到**运行期第一次调用**才报 `未知的宿主方法: ai.chat`。
- 示例工程补上本地预览脚本（含单表更新与事务提交/回滚）与前后端分目录结构，
  照抄即可跑通"写 → 编译 → 打包 → 本地验证"。

## 六、工具说明与平台真源对齐

- 给模型的 `wasm_app_*` 工具参数里，`access` 原来列了三个取值（含 `public`），
  而平台**只接受 `login` / `whitelist`**（缺省 `login`）—— `public` 是历史只读值，
  模型照着填会**必然发布失败**。现在工具说明与平台真源一致，并加了一条**读取服务端配置
  对拍**的判据（防止两边再次各说各话）。已在用的应用不受影响。
- 事务超时的建议文案补正：应用日志与读随包资源同样不能在事务里做，不只是查询。

## 已知限制（本版认账，未修）

- **四个面板是"整页接管中列"**：面板打开时**不显示会话**，点「返回对话」回到会话 ——
  这是本版确定的设计口径（不再让浮层盖住对话），不是缺陷。
- **旧的三条演示应用需要手动删除**（见 §四）：播种不会清理历史 `app_id`。
- 应用窗口内的外链落点未实现：应用里的外部链接当前一律拒绝打开（计划中）。
- 应用内 AI 的控制权交互与"按应用寻址"属下一批（计划中）；应用内 AI 的模型链路本身可用。
- **三平台只在 Linux 实测**：Windows / macOS 的面板布局与窗口行为待真机复核（计划中）。
- 运营看板趋势 UV 的长期（>90 天）保留需要新增迁移，本版未做（口径见 v2.7.6-beta.6 说明）。
- 仓库隐私守卫的覆盖面：判据覆盖**已跟踪文件与提交信息**；GitHub 的 **Release 正文**与
  **PR 标题/正文不是文件 ⇒ 不在判据内**（靠流程约束）。

## 升级与回滚

- **服务端**：取本版镜像压缩包 → 按 `docs/deploy/AI-DEPLOY.md` 升级（**升级前必须备份**，
  不要使用 `latest`，不要 `down -v`）。
- **客户端**：随服务端镜像分发；服务端升级后员工从自己登录的服务器取包，无需访问外网。
  **本版服务端与客户端建议一并升级**（面板与演示应用的新形态在两端都生效；
  服务端与客户端不同版本的组合不会导致功能不可用，只是新面板形态与窗口比例要两端同版才完整）。
- **回滚**（本版**无新增迁移**，属平级版本）：
  - 服务端：把 `SERVER_IMAGE` 改回上一版 tag（`…:beta-2.7.6-beta.6`）+
    `docker compose up -d server` 即可，**不需要**恢复数据库。
  - 客户端：回退到上一版安装包即可；演示应用是**服务端播种的数据**，回退服务端镜像后
    新演示的行仍在库里，只是不再被播种逻辑接管（可手动删除）。
