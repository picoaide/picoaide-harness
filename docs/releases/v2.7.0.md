# v2.7.0（2026-09-11）

> **交付与升级方式的架构版**：客户端与服务端同包发版（安装包随服务端镜像分发），
> 更新通道从 GitHub Releases 迁到自有更新服务器，渠道之间彻底隔离；
> 同时带来**员工余额**（月度发放 + 网关硬闸门）与 2026-09-11 全仓审计修复。

| 项目 | 说明 |
| --- | --- |
| 版本类型 | 正式版 |
| 升级建议 | **必须升级**——升级方式与更新通道在本版发生变化，旧部署按新版部署说明执行 |
| 影响面 | 服务端镜像、客户端（三平台）、管理后台、部署流程 |
| 产品代码变化 | 有（相对 v2.6.7，含 2.6.9 预发线的全部内容） |

## 一、客户端随服务端镜像分发，升级源改为自有更新服务器 ⭐

- **一个版本 = 一个镜像**：三平台客户端安装包（Windows NSIS / macOS DMG / Linux AppImage+deb）
  打进服务端镜像，镜像启动后落到持久卷 `/data/releases/<版本>/client/`；
- **客户端从它登录的那台服务器取包**（`GET /api/client/v2/updates/manifest` + `/updates/client/<文件>`，
  支持断点续传）：企业内网员工机器**不需要访问任何外网**；
- **版本错配在结构上不可能发生**：服务端不升级，客户端就保持配套旧版；升级服务端即同时升级客户端。
  CI 断言 `client.version == server.version`，防止「镜像里的客户端」与镜像版本漂移；
- **不再依赖 GitHub Releases 做更新检查**：匿名 API 限流（60 次/小时/IP，企业出口共用一个 IP
  必然触发）与国内不可达是两个绕不过去的硬伤。服务端改为只读自有更新服务器的版本清单
  （`latest.json`），客户端升级同步改为清单协议（安装包地址与 SHA-256 都来自清单）；
- 更新检查**显式拒绝重定向**：前置跳转不会被伪装成「没有新版本」，通道断了会明确报「检查不可用」。

## 二、渠道隔离：预发 / 官方 / 定制互不越界

- 三种渠道：`beta`（预发内测）、`official`（正式）、定制渠道（客户白标）；
- 版本清单强制声明 `channel_id` 且必须与安装所属渠道**精确相等**，缺失或不匹配一律拒绝——
  混渠道最坏的后果是白标客户端接受官方清单、升级后被「洗」成官方版，因此这是正确性校验，不是配置项；
- 品牌渠道产物只走自有更新服务器的独立目录，**不进入公开 Release**；
- **本版新增：数据根与浏览器 SSO 深链随渠道隔离**——定制渠道客户端使用自己的数据目录
  （登录态、设置、会话、连接器凭据互不串用，也不会互相顶掉单实例锁），深链 scheme 同样按渠道隔离，
  渠道浏览器 SSO 回调可以正常走通。官方客户端的数据目录与行为**逐字节不变**。

## 三、员工余额（新功能）

余额是**存量金额**（元），与 `quota_money` 的「月度流量上限」正交：

- **管理员手动调整**：用户管理 →「余额」→ 增加 / 扣减 / 设为，可填备注并写审计；扣减不能超过当前余额；
- **每月自动发放**：调度器按北京月幂等执行（跨实例、重启、重入都不会重复加钱），停机跨月后启动补发；
  发放方式可选「增加」（余额 + 月额度）或「覆盖」（余额重置为月额度）；
- **保存即补发**：开启闸门并保存额度时立即补发本月，消除「保存设置 → 下一个调度 tick」之间
  全员 0 余额被拦的窗口；
- **网关硬闸门**：默认关闭（避免存量部署升级瞬间被拦）。开启后余额 ≤ 0 调用 AI 返回 429，
  消费与用量写入**同事务原子扣减**（微元精度，流式回填只扣差额）；
- **员工端**：账户卡在闸门开启时以余额为主数字展示。管理入口：用户管理 →「月度余额发放」。

## 四、部署方式：一个镜像 + 一份给 AI 执行的说明

- 移除全部部署脚本（`deploy.sh` / `install-server.sh` / `make release-export`）；
- **唯一交付物 = 一个镜像 + 一份说明**，一条命令即可把 compose、Caddyfile 与客户端安装包导出到部署目录：

  ```bash
  docker run --rm -v /opt/picoaide:/out -e PICOAI_UNPACK_STACK=/out \
    ghcr.io/picoaide/picoaide-harness-server:v2.7.0
  ```

- 部署说明 [`docs/deploy/AI-DEPLOY.md`](https://github.com/picoaide/picoaide-harness/blob/master/docs/deploy/AI-DEPLOY.md) 含首次部署、升级、回滚、排障与执行清单，
  以及**四条数据安全铁律**：禁止 `down -v`、禁止使用 `latest`、升级前必须备份、不得覆盖已有 `.env`；
- 导出改为**替换语义**：不会再残留上一版本的客户端安装包。

## 五、安全与稳定性修复

- **客户端 TLS 校验误判（P0，本版重发的直接原因）**：证书校验钩子把 Electron 的
  `verificationResult` 当成数字 `0` 判断，而它在当前 Electron 版本里是字符串（受信任为 `net::OK`），
  于是「平台已信任就放行」这条快路径从未命中——客户服务器的正规证书也被判「不受信任」，
  客户端登录直接失败。修正后：**没有配置指纹就完全不接管证书校验**（回到 Electron 默认校验），
  配置了指纹才安装钩子，并先按真实形状放行平台已信任的证书。
  > 如果你在 2026-09-11 上午拿到过 v2.7.0 的镜像，请以本次附件为准重新下载（版本号不变，内容已修正）。
- **2026-09-11 全仓审计修复（F1–F21）**，摘录：
  - CSRF token 与会话同寿命（不再出现「挂机 2 小时后所有保存 403」）；
  - 认证配置热更新：启用/禁用 LDAP、OIDC 保存即生效，无需重启；
  - 组织树缓存写路径主动失效 + 全部遍历加环保护（消除「30s 窗口内可造环 → 配额热路径死循环」）；
  - 流式断连继续结算：客户端断开后仍取回上游用量，不再「中途断开免费」；
  - 本地文件服务越权面收敛（html/svg 强制下载或 sandbox、cwd 覆盖只对已挂载会话生效）；
  - provider `base_url` 的 SSRF/metadata 防护（保存校验 + 出站 Dial 复检）、用户名全链路大小写不敏感、
    登录限流跨入口共享。
  完整清单：[`docs/decisions/2026-09-11-balance-and-audit-fixes.md`](https://github.com/picoaide/picoaide-harness/blob/master/docs/decisions/2026-09-11-balance-and-audit-fixes.md)。
- **统计口径**：用量按**北京日/月**聚合，不再依赖进程时区与数据库会话时区；
- **白标链路修复**：渠道 logo 裂图（素材地址绝对化 + 窗口策略放行）、侧边栏品牌名折行、
  登录页表单因脚本错误从未注册、运行期渠道配置未进包等一系列白标缺陷；
- **插件**：memory-evolve 升级到上游 `v26090901`（保留全部本地定制）。

## 升级与回滚

1. **服务端**：从更新服务器或本 Release 附件取 `picoaide-server-2.7.0-amd64.zip`，
   `unzip -p 包 image.tar | docker load`；可出网时也可 `docker pull ghcr.io/picoaide/picoaide-harness-server:v2.7.0`；
2. 按 [`docs/deploy/AI-DEPLOY.md`](https://github.com/picoaide/picoaide-harness/blob/master/docs/deploy/AI-DEPLOY.md) 升级：**先备份**（数据库 + `master.key` + `.env`），
   再替换镜像 tag 并重启；
3. 数据库迁移自动执行（本版含 0061：余额字段、发放幂等表、用户名大小写不敏感唯一索引；
   存在历史重复用户名时会跳过索引并在启动日志告警）；
4. **客户端**：随本次服务端镜像发布，服务端升级后员工从自己的服务器取到配套版本；
5. **回滚**：保留上一版镜像 tag，把 `.env` 里的镜像改回去重启即可（余额闸门默认关闭，不影响旧行为）。

## 附件与校验

- `picoaide-server-2.7.0-amd64.zip`：服务端镜像压缩包（内含三平台客户端安装包与部署说明）；
- `SHA256SUMS`：先 `sha256sum -c SHA256SUMS` 校验，再解压使用。

> 注：更新服务器只保留最近 3 个版本，更早的镜像以 GitHub Release 作为长期存档。
