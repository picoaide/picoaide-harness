# v2.8.2（2026-10-07）

> 一句话：`v2.8.1` 之后的第一个正式版，把整条 `v2.8.2-beta.*` 预发线（7 个预发版）转正 ——
> 上游 DeepSeek Harness 升到 `0.2.0-rc.2`、客户端新增**语音输入**（识别模型随包、本机识别）、
> 交付件改用最大压缩、内置浏览器引擎回到受支持的稳定版（修掉"AI 控制蒙版整层不显示"），
> 并合入第一至三十三轮全仓审计与一次区间回归审计的修复（安全、隐私、计费、保留期、发布链）。
> **服务端与客户端必须同版本升级**：本版含一次**会话格式换代（v3 → v4）**，
> 被迁移过的会话在旧客户端上打不开，而**"装回旧客户端"不算回滚**（见 §一）。
> **不升级的后果**：继续把"用户点反馈时的完整会话正文"上传到模型厂商的采集端（§二）、
> 内置浏览器的接管/交还入口在部分客户端上不可用（§四）、以及一批评审过的安全与计费缺陷（§八）。

## 一、升级前必读：会话格式 v3 → v4

本版跟上一个正式版之间隔着一次**上游固定点换代**（`dsh-v0.1.6-alpha.2` → `dsh-v0.2.0-rc.2`），
其中唯一需要提前告知使用者、并且**改变回滚姿势**的变更是会话格式从 `v3` 升到 `v4`。实测结论：

| 问题 | 事实 |
| --- | --- |
| 什么时候会迁移 | **只有继续一个会话**（发消息 / 让 AI 接着干活）才迁移；列表、查看、搜索、导出都是只读，**不迁移** |
| 怎么迁移 | **副本式**：在同目录**新增** `session.v4.jsonl[.zstd]`，源 `session.v3.*` **逐字节不变**（前后 sha256 相同）；不改写、不删除、不留临时文件 |
| 磁盘代价 | 迁移过的会话在盘上**留两份**（实测 ≈2.01–2.14×）。**不是** 2026-09-12 那次 `v0→v3` 的 ≈4× |
| 旧客户端看到什么 | 该会话**从列表里静默消失**；强行打开会明确报"需要用新版 Harness 打开"。文件完好，旧端**永不追加**（跨进程文件租约会先把并发写拦成明确错误，不会分叉） |
| "装回旧客户端"算回滚吗 | **不算。** 旧端按"最高世代"挑选文件，不会回落到完好的 `v3` ⇒ 迁移过的会话在旧端一样打不开 |
| 正确的回滚 | **停写 + 整目录恢复数据根（`DSH_HOME`）**。备份口径是**整个数据根**，不是某一个文件 |
| 预留空间 | 第一次写打开是同步的（1.8 万事件实测 ≈950 ms）⇒ 预留与 `sessions/` 等量的可用空间 |
| 迁移可能被拒绝吗 | 会（源不动、不产生新世代，但**新客户端也打不开它**）。本版**没有**为这种情况提供处理通道（已认账，见「已知限制」） |

**运维纪律**：预发布渠道与正式渠道共用同一个数据根。升级窗口内
**不要在同一台机器上交替使用两代客户端**，也不要让同一个会话被两代同时打开。

## 二、安全与隐私：三条上游遥测/分析行已关闭

本版在桌面组合里把三条上游行**显式关闭**。三条都在客户端侧，与"我们自己的错误上报"
（`error_reporting_enabled` + 客户自建的兼容采集端点）互不影响。

- **`product-analytics` + `desktop-product-telemetry`**（上游 `0.2.0` 新增，**默认对桌面开启**）：
  采集桌面使用事件并上报到 OTLP 采集端，事件含设备标识、账号标识、系统版本与使用行为；
  上报端点的默认值是**上游厂商自建的收集器**。本产品是自托管 + 白标交付，
  客户端使用数据出境到模型厂商不在交付承诺内，因此两条一起关闭。
  （其中一条另有硬理由：它要求一个我们不提供的构建版本变量，开着会让整个客户端起不来。）
- **`session-telemetry-otel`**（**既有行，此前在生产实际是开着的**）：它在用户**显式提交反馈时**
  （点赞/点踩、编辑、撤回）把**截至该事件的完整会话前缀** —— 消息正文、工具参数与结果、
  工作区路径 —— 导出到 OTLP 采集端。此前唯一的关闭手段是一个只在 CI 与测试里设置的环境变量，
  运行期没有任何地方设置它，所以线上一直是挂载的。本版改为**静态关闭**，
  与我们早已关闭的"会话日志随请求上传"（`session-log-deepseek`）对齐。
- **对用户的可见影响**：点赞/点踩、评分与撤回**照常可用、照常记录在本机会话日志里**；
  变的只是"不再向上游采集端上传会话内容"。没有开关，也不需要运维配置。

## 三、客户端新能力：语音输入（本机识别，模型随包）

- **现象**：会话输入框右侧出现麦克风按钮；点它开始录音，说话内容变成输入框里的**草稿文字**
  （可以改完再发）。
- **在哪儿识别**：客户端**本机**的子进程（SenseVoiceSmall + Silero VAD），**录音不出机器**，
  没有云端识别、也没有云端回退 —— 断网可用。中/英/日/韩/粤自动识别；单次最长 120 秒、上限 4MiB。
- **模型从哪来**：**随客户端分发**。构建时把权重打进产物（按上游清单校验大小与 sha256），
  客户端装配期把上游的官方配置项指到客户端目录里的那份 ⇒ **装上即可用：零下载、零网络**。
- **权限**：首次录音时向系统申请麦克风；客户端只放行**本应用主窗口**的纯音频请求
  （内嵌浏览器与应用窗口各走自己的权限面，不受影响）。**macOS 必须安装本版或更新的已签名包**
  （含麦克风用途说明与音频输入 entitlement）才会弹系统授权框。
- **诊断**：没有录音设备时给出可执行的中文提示（去系统声音设置看输入设备；虚拟机/远程桌面
  需要开启音频或麦克风重定向）；「语音输入准备」面板新增**麦克风自检** —— 显示系统报告的
  录音设备数与系统授权状态，并可在"尚未询问"时直接申请权限（已拒绝后系统不会再弹窗，
  此时按钮不出现，改为提示到系统设置里打开）。
- **随包模型的来源与许可已写进第三方声明**（合规评审请按两条分别引用，不要笼统写成"开源"）：
  **SenseVoiceSmall**（int8 ONNX，随 sherpa-onnx 导出分发）为 **FunASR 模型开源协议 v1.1**
  （模型卡标的是 `license: other`，**不是**代码仓的 MIT；协议 §2.2 要求署名来源与作者并保留模型名）；
  **Silero VAD** 为 **MIT**。
- **不想带模型的渠道**：在渠道包 `channels/<id>/channel.json` 写
  `"desktop": { "speech_bundle_model": false }`（缺省为 **true**）。关掉后客户端回到
  "首次使用时下载模型"，适合能直连公网或已配内网镜像的部署。另有三个**可选**部署字段
  （都只影响本地获取模型的方式）：`desktop.speech_model_dir` + `desktop.speech_vad_path`
  （本机预置文件，零下载）、`desktop.speech_model_origin`（内网镜像源，模型路径与文件名不变）。
- **构建期行为**：拉取不到权重会**直接让打包失败**（不产出"以为带了其实没带"的包）；重复打包幂等。

## 四、内置浏览器：控制蒙版整层不显示（用户报告，已在正式版修复）

**现象**：用「AI 操作浏览器」打开网页后，窗口里**看不到任何 AI 控制界面** —— 既没有
"AI 正在操作 / 我来操作"的蒙版，也没有右下角的"交给 AI"胶囊；网页与工具栏照常显示，
但**整窗点击都没反应**：点不到「我来操作」接管，也点不到「交给 AI」交还。把浏览器窗口
关掉再打开**不会恢复**（关窗只是隐藏窗口，那层视图还活着），要重启客户端才会重建。

**影响面（预发线）**：`v2.8.2-beta.2` ~ `v2.8.2-beta.6` 的客户端上，
内置浏览器的人工接管/交还入口不可用：AI 把控制权交给用户（例如引导登录）之后，
用户既无法交还、也无法确认状态，只能重启客户端。**正式版不含该缺陷。**

**根因**：预发线曾把引擎换到 `45.0.0-alpha.7`，该版本在"透明覆盖层叠在网页之上"这条能力上
出现回归 —— 覆盖层不再正确合成到网页之上：在软件合成的机器上表现为**整窗被一块灰白板盖住**，
在有硬件合成的机器上表现为**覆盖层什么都没画、却照样吃掉全部点击**。真机像素对拍
（同一个探针只换引擎）：`44.0.0` / `44.4.3` / `43.x` 上蒙版之下的网页颜色正常透出，
`45.0.0-alpha.7` 上**一个像素都透不出来**。

**本版怎么做**：

- 客户端引擎回到 **Electron `44.0.0`**（稳定版，且仍在上游包解析原生插件支持的运行时列表里）；
- 该引擎在 **`app.asar` 归档路径**上取文件元数据时会退化成"数字版"统计信息
  （会导致**文件系统技能整片消失**：预设自带技能、项目 `.dsh/skills`、`$DSH_HOME/skills`、
  `~/.agents/skills`）—— 本版用自己的补丁把这条补齐（权限位与纳秒时间戳按形状取值）；
- 打包门禁随之改成**能力判据**：不再要求"引擎必须返回某种统计形态"，而是要求打包后的客户端
  **真的能在归档里 stat / 列举 / 读取预设技能**（列举结果与产物反推的期望逐元素相等），
  引擎形态只打印到构建日志。

**同时保留前一版的可用性改进**：交还入口放大到 300×44，提示在**控制权一到用户手里就出现**
（此前要等"AI 的下一次浏览器调用被拦下"），AI 交权时在会话里留下"操作完成后请在浏览器窗口
点「交给 AI」交还"的指引；控制权入口仍然只有一个（蒙版空白处、活动面板、Esc 都不改变控制权）。

## 五、应用平台：运行预算收进后台，默认放宽

**默认值变化**：

| 预算 | 旧 | 新 | 含义 |
| --- | --- | --- | --- |
| guest 执行预算 | 10 秒 | **30 秒** | 应用单次请求里真正执行的时长上限（等数据库/等宿主调用时**不计时**） |
| 发布干跑预算 | 2 秒 | **30 秒** | 发布/预检时跑一次真实实例化的预算 |
| 客户端出站超时 | 30 秒 | **75 秒** | 客户端等平台答复的上限（随包） |

- **干跑预算为什么必须与 guest 一致**：干跑要回答的是"这次运行到底能不能跑起来"。
  它的预算比真实执行更短时，就不再回答那个问题，而变成"预检拒绝了一个线上其实跑得动的应用"
  —— 现场正是这个形态：一个 PDF 打水印类应用启动就要十几秒，2 秒的干跑把它判死，
  而它在 30 秒的 guest 预算下完全正常。
- **这些数值现在可以在后台改**：管理后台 → **运维 → 应用平台** → 「时间预算」一节。
  可调六项：guest 执行预算、发布干跑预算、宿主调用预算、请求端到端墙钟、单条 SQL 硬超时、
  编译超时。保存即生效（**不需要重启服务端**），并进入审计。保存时会做**一致性校验**
  （端到端墙钟必须严格大于 guest 预算、干跑不得大于 guest、宿主调用不得大于 guest、
  单条 SQL 不得大于墙钟且必须大于 SQLite 的 busy timeout、编译超时不得超过服务端 ReadTimeout），
  不合规当场拒绝并点名是哪一项。取值区间：通用 1–300 秒；guest 单独 1–120 秒。
- **客户端必须同版本**：客户端等平台答复的上限是**随包固定**的（75 秒），它必须**严格晚于**
  平台侧每一个请求预算 —— 否则平台还没来得及返回可读的错误（带错误码与修复建议），
  客户端就先放弃，员工只会看到"网络错误"。**认账的边界**：后台可以把端到端墙钟配到 75 秒
  以上，超出的部分会退化成"网络错误"；确有需要时可在客户端侧用 `requestTimeoutMs` 同步抬高。
- **顺带修掉三处"旋钮静默失效"**：编译子进程超时过去只在启动时固化（后台调大后子进程仍按旧值
  终止），现在每次编译都读当前值；单条 SQL 硬超时的语义明确写成"**下一个应用库句柄**生效"；
  诊断建议与错误明细里的数字改为按**当前生效值**渲染（否则作者会照着过期的数字去优化应用）。
- **发布链路的其他修复**：13 个此前"发不出新版本"的应用名恢复可用（例如与平台路由静态段同名的
  名字；`uploads` 仍然保留，它确实与分片上传入口冲突）；**分片发布的最后一跳断网可续传**
  （此前最后一步遇到网络中断只能整条重传，现在返回带 `upload_id` 的结构化失败，
  用同一个 `upload_id` 重发即可，一个分片都不重传）；已保存的旧限制项在升级后**不会被丢弃**。

## 六、交付件：最大压缩 + 语音模型随包（**运维必读**）

- 打包改用最高压缩级别。三平台的形态不同，方向一致（安装包更小、解压与首次挂载更慢）：
  Linux 的 AppImage 把 squashfs 压缩器由 **gzip 换成 xz**（这是唯一换了压缩器本身的平台 ——
  AppImage 是运行时挂载的 squashfs，所以**首次挂载与冷读文件更慢**，这是行为变化、不是故障）；
  macOS 的 DMG 由 zlib(UDZO) 换成 bzip2(UDBZ)；Windows 安装器的 7z 级别由 `-mx=7` 提到 `-mx=9`。
- 同时三平台安装包**都带上了语音模型**（int8 权重，约 230 MiB）。实测（部署环境下发的正式
  交付件，预发线 `2.8.2-beta.2` → `2.8.2-beta.3`）：

  | 交付件 | 带模型前 | 带模型后 | 变化 |
  | --- | --- | --- | --- |
  | Linux AppImage | 183.4 MiB | **435.9 MiB** | +252.5 MiB |
  | macOS DMG | 184.0 MiB | **323.7 MiB** | +139.7 MiB |
  | Windows 安装器 | 195.6 MiB | **345.2 MiB** | +149.6 MiB |
  | 服务端镜像 zip（内含三平台安装包） | 约 537 MB | **约 1.13 GB** | +约 593 MiB |

  差异按平台不同，是因为模型权重在各打包格式里的压缩率不同；**服务端 zip 的增大最明显**：
  取包、`docker load`、上传/下载时间都会变长，请预留时间与磁盘。
- CI 打包时长已实测无风险（Linux 打包作业 9m53s → 9m56s，作业预算 60 分钟）。

## 七、连接器、网关与运维面的行为变更

- **连接器出站地址钉扎**（默认无感；**只有经代理才能出公网的部署必须读**）：连接器出站
  （OAuth 发现与换票、MCP 服务、令牌刷新等）此前只校验"域名解析到的地址"，校验与真正建连之间
  存在重新解析的窗口。本版把**被校验过的那次解析结果固定为建连地址**，出口只剩一个判定点与
  一份传输实现。**代理部署**：默认仍然**禁止**使用系统代理；若为这台机器打开了代理逃生门
  （渠道包开关，或真实进程环境变量），连接器出站会经代理 `CONNECT` 建隧道，并打印一行
  `connector outbound proxy mode: …` 日志。**注意**：经代理时域名由代理解析，本地的地址钉扎
  不可达，这条链路的出站策略由代理自身承担 —— 需要严格出站管控的部署，请把规则配在代理侧，
  或不要打开代理逃生门。
- **保留期观测**：`/readyz` 新增"未被管理的残留关系"统计（含被搬出 `public`、被改名进账本族的
  带标记残留），逐条可解释；此前这两类会**静默**留在磁盘上、任何读数面都看不见。保留期本身
  仍然**不会**对它们做破坏性动作（fail-closed），需要人工决定怎么处置。
- **登录限流**：一次成功登录不再**整键清空**该 IP 的失败计数（改为只退还本次尝试那一格），
  暴力尝试不会被"偶尔成功一次"洗掉；清理动作也挪到"登录真的完成"之后（被拒/禁用/签发失败都不清）。
- **网关错误码**：模型路由信息读不出来时，此前收敛成"未定价模型"的 429；现在给出可区分的
  `MODEL_ROUTING_UNAVAILABLE`（`reason=routing_lookup_failed`）。未定价模型仍然默认拒绝（fail-closed）。
- **渠道配置**：镜像里的 `channel.json` 存在但形态不对（符号链接/目录/读不出/解析失败）时，
  此前会**静默**回落成中性占位（品牌渠道看起来像官方版）；现在会**出声**并在启动期拒绝启动。
  正常的"没有渠道配置"仍然安静回落，不受影响。
- **迁移文件不可变**：新增迁移校验登记表与守卫（已登记文件被改写 / 新增未登记 / 死条目 /
  非法登记表全红），以已发布基线 tag 为不可变基准（取不到远端校验时**响亮降级**）。
  它与下面「迁移清单锚点」是两件事：锚点管"本版引入了哪几条迁移"，本表管"已登记的迁移字节
  不许被人就地改写"。
- **连接器凭据按（账号, 服务端）隔离**：同一账号切换到另一台服务端后，不再把上一台服务端的
  密钥交给同名连接器（内置浏览器的"填充凭据"读的是同一份目录，也一并跟随）。
  ⇒ **升级后需要重新授权一次**：升级前保存的凭据**不会被采用**（也**不会**被删除，
  原文件保留原处）；同一账号重新登录**同一台**服务端后凭据仍然保留。
- **`/readyz.usage_retention` 两处读数语义变化**（接监控的环境请核对）：
  `last_round_at` 由"本轮开始时刻"改为"本轮**结束**时刻"；新增 `configured_months_known`
  区分"保留期被关掉（0 = 永不删除）"与"还没跑过第一轮"。把"保留期被关掉"的告警条件收紧成
  `configured_months_known == true && configured_months == 0`。另外，计量写入路径在需要自愈时会
  执行 DDL 并短时取 `usage` 的 `ACCESS EXCLUSIVE` 锁 ⇒ 那一刻并发的计量写入会**毫秒级排队**
  （随后照常落账），对写入延迟尖刺敏感的告警请把"分区自愈"纳入采样窗口/白名单。
- **运维动作**：如果你的环境里有"定期删编译缓存文件"的临时脚本，**升级后请停用** ——
  新版本由进程内回收统一负责（直接删文件会与编译写并发）。
- **上游设置模型换代**：上游把设置存储并入设置服务，**命名空间就是一个 profile 条目 id**；
  旧数据根里的 `settings.yaml` 由上游**只导入一次**、随后改名 ⇒ 运维不要继续在 `settings.yaml`
  里手写配置，请改走设置界面或 profile 补丁。另有一处**用户可感**的上游默认值换代：
  长工具结果的溢写阈值由 5 万**字节**改为 12 500 **token**（schema 只认新键），
  "何时落盘 / 何时内联"的时机因此改变；**如果你的流程依赖旧阈值，请在 profile 里显式覆写**。
- **`web_fetch` 的地址策略整体放行（本版唯一一处明确的安全取舍，请知悉）**：部署环境用了
  透明代理的假 IP 模式（任何域名都解析到保留网段），上游基于 `ipaddr.js` 的公网判定会把
  **每一个** URL 都判成"非公网地址"⇒ 该工具完全不可用。放行之后**客户端 `web_fetch` 不再做
  地址层防护**；代理路由、DNS 固定、协议白名单等其余约束不变。只有经代理才能出公网的部署
  不受影响，但**内网可达性不再被这一层拦住** —— 需要该防护的环境请单独评估。

## 八、这一版还修了什么（审计修复总览）

`v2.8.1` 之后主线合并了第一至三十三轮**全仓对抗审计**的修复，以及一次针对
「`v2.8.1` → 主线」全区间（34 个提交 / 1274 个文件）的**回归审计**修复。后者由 13 条独立
只读泳道按文件切分（覆盖面 1274/1274），每条发现由独立代理修复、再由**另一名**独立代理做
对抗验证（每条修复都必须有"能被改回去打红"的判据与变异矩阵）：结论 **0 条 P0 / 22 条 P1
（全部属于该区间引入或改恶，已全部修复）/ 约 50 条 P2**。用户可感的部分分散在上面各节，
其余集中在下面几类：

- **计费与账本**：不可逆的长期汇总不再被错误丢弃；月报重推不再重复投递；
  `embeddings` 请求不再零计费；余额不足的交付/扣费语义收口；多级分区布局下删除保留期
  不再误删活分区、也不再重复计账，且"当月经由中间父表覆盖"的布局不再让当月对话全部不可用。
- **凭据与令牌**：连接器 401 续期不再被自己掐断（凭据变更事件只重注册 stdio 子集，
  HTTP/SSE 传输由 provider 每请求读取活令牌）；会话中途令牌被作废时并发 401 **合并成一次续期**
  （此前对启用「刷新令牌轮换」的授权服务器会触发复用检测、把整条授权吊销，
  用户侧表现为随机的「重新认证后仍然 401」）；声明的 `Authorization` 解析为空时不再遮蔽
  服务端刷新的活令牌。
- **技能库与能力中心**：商店技能被本地修改后，"更新"不再静默整树覆盖用户改动；
  内置技能的"卸载"会持久生效；本机已安装但当前账号在服务端看不到的技能，不再被推断成
  "已被管理员下架"并给出删除本机那一份的动作；归属不可证明时一律不出破坏性动作。
- **客户端宿主**：连接器对"永久拒绝"类 OAuth 错误不再无限重发；cron 在"应用关闭期间错过
  触发点"时现在可观测；浏览器工具的预算不再被内部等待/排队吃掉；深链打开应用与面板打开走
  **同一个**打开闸门；会话级开关的读失败一律改为 fail-closed（此前一次瞬时 `EACCES`
  会静默清空全部会话级开关）。
- **发布链与门禁**（决定"以后能不能少踩坑"）：CI 触发器与被钉住的步骤不可被静默摘除
  （`if: false` / `continue-on-error` / 删 `push:` 之类会直接红）；`patches/` 若一处都没生效，
  门禁必然失败（旧行为只打一行 warning）；迁移文件形状自检（版本号重复或文件名不合规会
  fail-loud 并点名文件）；渠道仓取源日志不再回显凭据；发布说明的章节归属、迁移清单锚点与
  迁移字节不可变性都变成了机器判据。

## 已知限制（本版认账，未修）

- **会话迁移被拒绝时没有处理通道**：极小概率下 `v3 → v4` 迁移会被上游拒绝（源文件不动、
  不产生新世代），此时**新客户端也打不开那个会话**。遇到请保留该会话目录并联系我们；
  不要删除 `session.v3.*` 文件。
- **`web_fetch` 不再做地址层防护**（§七最后一条）：这是为可用性做的显式取舍。
  需要"内网不可达"这一层的部署请单独评估。
- **连接器在代理模式下没有地址钉扎**（§七第一条）：经代理时域名由代理解析，出站策略由代理承担。
- **应用平台的预算粒度是全局一套**，不能按单个应用单独放长（平台并发是全局槽位，
  按应用放开等于让"谁的应用更慢"决定谁能占住槽位）。端到端墙钟配到客户端出站超时
  （75 秒）以上时，超出部分退化为"网络错误"。
- **内置浏览器的控制权提示走 5 秒轮询**（未接长连接）⇒ 控制权变化到侧边栏提示之间最长约 5 秒；
  **"蒙版画不出来"这一类故障仍缺自动兜底** —— 本版修的是根因（引擎），
  但"看不见的蒙版不允许占着整窗吃点击"这条自我保护还没做（计划中）。若再次遇到
  "整窗点不动且看不到任何控制入口"，请**重启客户端**并在会话里反馈。
- **创建模式里的插件管理能改到本产品自己的行**（本版修复组合面缺陷的直接代价）：
  在创造模式里可以让 AI 禁用这些行，其中 19 条是必需行，禁用后**下次启动会响亮失败并点名
  是哪几行**（不是静默少功能）。恢复：删掉数据根 `profiles/<name>/cordis.patch.yml` 里对应的
  `disabled` 项（或整份删掉）。缓解方案需要上游提供"受保护模块"注入点，已登记、本版未做。
- **网关地址目前只允许"当前会话的那台服务器"**（模型链路加了端点硬边界，不允许把网关令牌
  发到别的地址）。当前所有部署都不受影响；"网关部署在另一个域名下"这种形态本版没有入口。
- **语音识别的验证边界**：录音与识别只在有麦克风的真机可验（无音卡的 CI 环境点录制会得到
  明确的"未找到设备"，是预期行为）；macOS 的系统授权弹窗只在真机、且安装已签名且公证的包时
  出现；**预置/镜像来源的模型文件**由上游只查"文件存在"、**不校验哈希**（显式来源的既定语义），
  版本匹配由部署方负责，配错的表现是准备阶段明确报 `Speech model verification failed`；
  语音转写只作为草稿插入输入框（不写入会话、不自动发送）。
- **macOS 替换安装仍是手工的**：更新提示会打开 DMG，替换「应用程序」里的副本由用户完成，
  替换后客户端不做版本自校验。计划中。
- **Windows 与 macOS 安装包未在对应平台本机复核**：打包与验证在 Linux 上完成（含完整客户端
  自动化），Windows 安装程序与 macOS 磁盘映像由 CI 三平台构建（macOS 走签名 + 公证 + 装订）。
  **请在对应平台的首次升级后反馈启动与登录情况。**
- **上游遥测行的默认值可能再次变化**：本版关闭的是当前三条；上游后续版本若新增默认开启的
  采集行，需要在下一次升级时重新对照（已写进升级脚本的人工核对清单）。
- **审计收敛判据未达成**：从第一轮到第三十三轮，每一轮都至少掉出一条 P1；另有若干**判据面**
  残留（不影响产品行为）与约 50 条 P2 未修。完整台账、方法论与接手清单见
  `docs/AUDIT-2026-09-23-FULL.md`。

## 升级与回滚

- 服务端：取镜像（更新服务器附件）→ 按 `docs/deploy/AI-DEPLOY.md` 升级
  （**升级前必须备份**，不要使用 `latest`，不要 `down -v`）。
- 客户端：随服务端镜像分发，服务端升级后员工从自己登录的服务器取包，无需访问外网。
  **服务端与客户端必须同版本**（会话格式换代 + 客户端出站超时随包 + 内置浏览器引擎修复）。
- **升级前**：备份**整个数据根**（`~/.picoaide-harness`，或你的渠道数据根），
  并预留与 `sessions/` 等量的可用空间（§一）。
- **迁移类别**：从上一个正式版 `v2.8.1` 升级会依次应用三条**只加列**迁移 ——
  `0080`（`models.catalog_missing`）、`0081`（`gateway_files.reap_gen`）、
  `0082`（`report_subscriptions` 的三个重投递列）；三条都带缺省值，不回填、不改写既有数据，
  DDL 是 `ADD COLUMN IF NOT EXISTS` 幂等形态。
- **回滚**：口径**唯一真源**是 `docs/deploy/AI-DEPLOY.md` §7，本节不给第二套处方。
  回退到**不含 `0080`/`0081`/`0082`** 的版本属该节定义的**跨代回滚**（库比二进制新）
  ⇒ 按 §7.2 的**四步顺序**执行：**① 停服 → ② 恢复升级前的 `pg_dump` → ③ 回退镜像
  （`SERVER_IMAGE` 改回上一版 tag）→ ④ 客户端回退到与镜像同版本**。
  **不要只改 `SERVER_IMAGE` 就重启** —— 本版起服务端对"库比二进制新"是 fail-loud 的
  （`schema_migrations` 里有二进制不认识的版本号就直接拒绝启动，报 `schema 与二进制不同代`）。
  `0082` 的迁移头部另记了一条更轻的路径（只删版本登记行、不恢复库），是否采用**以 §7.1 为准**。
- **客户端回滚**：**"装回旧客户端"不算回滚** —— 被迁移过的会话在旧客户端上打不开（§一）。
  正确姿势是**停写 + 整目录恢复数据根**。
- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无
  - 该锚点比较的是**发布链上相邻两版**（`v2.8.2` ↔ `v2.8.2-beta.7`），两版之间**没有**数据库迁移；
    从上一个正式版 `v2.8.1` 升级要应用的那三条见上面的「迁移类别」。

## 附件与校验

- `picoaide-server-2.8.2-amd64.zip`：服务端镜像压缩包（`docker load` 后使用），
  内含该渠道的三平台客户端安装包；
