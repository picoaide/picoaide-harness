# v2.8.0-beta.1

> 预发布（beta 渠道）。只影响 beta 渠道的客户端与服务端；正式渠道与客户渠道**不在本版范围内**。

## 谁应该升级

- **beta 测试环境**：建议升级到本版，它包含一批安全修复与 WASM 应用平台的功能接线。
- **使用 WASM 应用平台（自建小程序）的团队**：本版把此前"设计已冻结、实现没接通"的五处接线补齐，其中**应用作者数据面**与**AI 读取应用数据**的默认行为有变化（见下）。
- **不升级的影响**：不升级则继续保留已修复的安全问题（详见各节）与未接通的平台能力。

## 一、安全修复（建议所有环境升级）

1. **编译缓存目录的信任边界**：缓存目录被符号链接重定向、权限漂移、或条目被替换时，执行侧不再"读一份来源不可信的机器码"，编译侧也不再把产物写进被重定向的目录；两侧拿不到可信缓存时都**降级为进程内/临时缓存**（功能不变，只影响首次编译耗时），不再因此拒绝启动或静默照用。
2. **本机控制面的凭据隔离**：内置 AI 浏览器不再把应用的登录凭据复制进模型可驱动的浏览器分区（此前它必须这么做，因为接管蒙版跑在该分区）。蒙版已改到应用默认会话，凭据不再与模型共处一个 jar；同时 AI 浏览器**禁止访问任何本机地址**（含重定向、子框架、`window.open`、下载等全部入口），此前可被用来绕过本机接口的持有性证明。
3. **应用日志与审计的文本注入**：应用可控文本（日志、审计明细里的应用标题、LDAP 对端错误）统一按同一份策略转义换行与不可见控制字符，无法再伪造日志行或审计行。
4. **应用作者数据面**：只读行浏览端点默认按列名脱敏，`unmask` 需显式请求且单独记审计；只读打开不会建库、不跟随符号链接。

## 二、WASM 应用平台：补齐的能力

- **编辑器/工具链**：段序判据与运行时编译器同判（带 DataCount 的合法产物此前发不出去）；`.debug_*` 调试段不再被当作应用资源，段总量预算口径在打包脚本、平台校验、本地预览三处统一。
- **作者数据面**：应用作者可以在客户端「应用中心 → 详情 → 数据」查看自己应用的表结构与一页行数据（默认脱敏，原值需人在面板里显式查看并单独记审计）。
- **AI 读取应用数据改为默认关 + 显式授权**（本次行为变更）：AI 工具 `wasm_app_rows` 在未授权时返回结构化拒绝（附操作指引、零出站）；授权由**发布者本人**在该应用的「数据」面板上开启，逐应用、可撤销。AI 始终拿不到未脱敏的原值。
- **作者可声明敏感列**：`picoaide.app.json` 新增可选字段 `sensitive_columns`（上限 100 条、单条 ≤64 字节）。声明的列一定按敏感处理（与平台的列名启发式取并集），用于覆盖"列名不含敏感词"的真实 PII 列。
- **应用窗口**：作者声明的 `window.ratio/width/height` 现在真的进入建窗路径；AI 可以通过应用窗口的 `app_id` 定位到**该窗口自己**（不再误落到用户的浏览器标签页），并且无法驱动未声明的工具参数。
- **静态资源缓存**：F11 的读写两半都接通（此前只接了失效半环，等于每次全量回源）；下架/冻结/删除与退出登录会清理相应缓存。
- **多服务端隔离**：浏览器与应用窗口的分区名带上服务端地址哈希，换服务端不再串用同一份本地存储。

## 三、运维可见性

- `/readyz` 新增 `exec_cache_mode`（`disk` / `memory`）与 `compile_cache_mode`（`configured` / `temporary`）。缓存降级此前只有一行日志，现在可以直接从健康探针读到。

## 四、已知限制（本版新引入或仍未修）

- **应用窗口内的「我来操作 / 交给 AI」按钮尚未挂载**：AI 目前可以直接驱动应用窗口，但人**无法在该窗口内**交还/接管控制权（浏览器的接管按钮不受影响）。当前可用的处置是关闭该应用窗口（会停止 AI 对该窗口的操作）。逐窗口的控制状态 API 已就绪，挂载点属于后续工作项。
- **接管蒙版的窗口内表现未做真机验证**：本次把蒙版改到应用默认会话，离线判据覆盖了路由、会话与证明链路，但"蒙版合成/透明与按钮实测可用"需要在装有图形界面的机器上人工确认一次。
- **作者数据面的两条残留**（已认账、非本版引入）：只读打开不防硬链接与检查—打开之间的竞态（前提是攻击者已拥有数据根写权限）；指向同一服务器的其它主机名不在本机禁访判据内。
- 编译缓存条目仍无内容签名：与宿主同 uid 的写者理论上仍可投毒，闭合需要独立 uid / 只读挂载（部署面）。

## 五、代码扫描（CodeQL）处置

本版代码扫描出现 6 条 high 告警，逐条判定如下（均已按"误报"关闭并写明理由，面板上可复查）：

- `go/sql-injection`（`appdb/stmt.go`）：**误报**。这里的 SQL 文本是**应用作者自己写的语句**（平台按 R15 不对应用 SQL 做行级过滤），平台侧只做单语句/内部对象/限额的语句闸门，不存在"平台拼接使用者输入"的注入面。
- `go/path-injection` ×4（`appdb/appdb.go`、`api/read.go`）：**误报**。路径由平台推导（`<data_root>/apps/<app_id>/app.db`），`app_id` 在进入该包前先过白名单形态校验，且该包不接受任何外部路径参数。
- `js/polynomial-redos`（浏览器导航判据）：**误报且已在本版消除**（改用无正则的首尾剥离循环）。

## 六、附件与升级

- 附件：`picoaide-server-2.8.0-beta.1-amd64.zip`（内含服务端镜像与该渠道客户端安装包）与 `SHA256SUMS`。校验方式见 `docs/deploy/AI-DEPLOY.md`。
- 升级：按 `docs/deploy/AI-DEPLOY.md` 的镜像升级流程执行；beta 渠道的取包地址为 `https://release.picoaide.com/beta/releases/2.8.0-beta.1/`。
- 回滚：改回上一版镜像 tag 并 `docker compose up -d server`（本版无新增数据库迁移，回滚不需要恢复数据库）。
