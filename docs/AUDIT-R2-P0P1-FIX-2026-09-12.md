## 二、两条 P0

### P0-1｜`skillmanifest` YAML 深度炸弹 → 进程级 `fatal error: out of memory`

- **位置**：`server/internal/skillmanifest/manifest.go:271`（`yaml.Unmarshal`）、`:527`；
  入口 `server/internal/sharedskills/routes.go:226`（`POST /api/client/v2/shared-skills`，仅 `BearerAuth`）
- **根因**：goccy/go-yaml 解析嵌套流式集合无深度/节点上限，成本二次方；
  Go 的 `fatal error` **不可 `recover()`**
- **复现**：381 字节 zip（嵌套 20 万层 `[` 的 frontmatter）→ 3GB+ RSS → 进程退出；
  40KB frontmatter → RSS 83MiB → **652MiB**。
  ⚠️ 三道"有界"闸门（16MB/64MB/1MB）**全部放行** —— 它们约束字节数，
  **约束不了解析器节点成本**
- **修复**：四层闸门 —— 输入长度上限（128KB）+ O(n) 单遍字符统计（集合/序列/锚点计数超阈值即拒）
  + 嵌套深度上限 32 + 预览上限 1MB → 128KB

### P0-2｜服务端下发的连接器定义零校验地进入 `spawn`，并把该用户令牌交给该命令

- **位置**：`packages/host/connectors/src/index.ts:302-310`；服务端
  `serverstore/connectors.go:37-69` 的 `validateConnector` **`command`/`args`/`env`/`url` 一个都不查**
- **复现**：真 MCP SDK transport + 真 spawn → `/bin/sh -c` 真执行，
  子进程 env 读到 `PICOAIDE_CONNECTOR_ACCESS_TOKEN` / `REFRESH_TOKEN` 与自定义字段
- **可达性**：持 `connector:write` 的管理员（仅 super_admin）或服务端/会话被攻陷；
  `restoreAll` 在启动与每次会话变更时执行 ⇒ **无需用户交互**
- **维持 P0 的理由**（复核员主动否决了自己的下调）：本产品**自己的威胁模型**已把
  "攻击者可控服务端"与"凭据不得导向任意目标"写进 `deep-link.ts` 的 F12 守卫与
  `assertServerURLAllowed`，但客户端对服务端下发的可执行内容**零纵深防御**
- **修复**（用户拍板「本地确认 + env 白名单」）：
  1. **保留**服务端下发 stdio MCP 的能力
  2. **首次 stdio 连接需本地确认** —— 新增 `approvals.ts`（按用户 scope、0600 原子写、
     损坏 fail-closed），记录 `(command+args+env)` 的 sha256 指纹；复用既有连接器面板，
     未新造 UI 框架
  3. **env 白名单** —— 拒绝 `PATH`/`NODE_OPTIONS`/`NODE_PATH`/`LD_*`/`DSH_*`/`ELECTRON_*`/`PICOAIDE_*`；
     `credential.fields` 只注入声明的键
  4. 服务端 `validateConnector` 同步校验（客户端**不假设服务端可信**）

## 八、方法论盲区反思

1. **"只堵了一个出口"是本轮最大的复现模式** —— 上轮 4 条修复都被同一条思路绕过。
   **防御要按"数据能到达哪些出口"枚举，而不是按"我在哪个入口看到的"修补。**
2. **"修复会引入新回归"** —— P0-C 修好了"扣钱"，却让失败路径变得**更不可见**
   （从"记了账没扣钱"变成"没记账也没扣钱"）。**修一个失败路径时，必须同时问"失败之后
   调用方会怎样"** —— 加了新错误类型却没改调用方，等于把问题挪到了更隐蔽的地方。
3. **"测试在功能静默失效时依然全绿"** —— cron 的 117 项测试、webadmin 的自引用权限集断言
   （恒真）、browser 只断言"字段存在"的 11 条，都是**假保护**。
   **回归断言必须是行为级/内容级的。**
4. **"用时间比做判据的测试会假红"** —— 我自己新写的性能测试就犯了这条（见 §5）。
   复杂度判据应优先用**确定性**手段（绝对预算 + 语义对拍），比值仅作诊断。
5. **审计员的诚实与复核的价值** —— 本轮 31 条**一条都没被推翻**，但复核仍做了三件关键事：
   ① 主动否决自己对 P0-2 的下调（回到产品威胁模型论证）；② 逐条校订行号
   （`tools.ts:735`→`:734`、`jobs.ts:115`→`:120` 等）；③ 更正措辞
   （"云元数据自动发现"实为"攻击者指定的 SSRF 目标"）。
   **复核的价值不只是"推翻"，还包括"加固"与"精确化"。**
