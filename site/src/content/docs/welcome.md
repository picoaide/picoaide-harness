PicoAide Harness 是**企业级 DeepSeek Harness 一体化平台**：桌面客户端 + 本地 Harness 服务 + 企业服务端三层，会话与文件留在员工机器、账号与管控留在客户自己的服务器，整个产品一切皆插件。

这一页是全站入口：先看清三层各负责什么、自己该按什么顺序读，再看边界清单确认你要的能力在不在。

## 三层结构

```text
员工机器                                    客户内网一台机器（一个容器镜像）
──────────────────────────────              ────────────────────────────────────
桌面客户端（Electron 应用）                 企业服务端 · Caddy + Go + PostgreSQL
  原生窗口 / 托盘 / 自动更新                  认证 / 模型网关 / 计量计费
本地 Harness 服务 · 127.0.0.1               能力中心与审批 / 连接器目录 / 应用中心
  会话 · 文件 · 工作区 · 沙箱 · 审批          审计 / 客户端分发 / 门户页与后台

            └──────── HTTPS + Bearer token ────────▶
            ◀──────── 安装包与升级清单 ────────────┘
```

| 层 | 位置 | 负责 |
|---|---|---|
| **桌面客户端** | 员工机器 | 原生窗口与托盘、登录页与账户、自动更新，以及全部界面面板：对话、能力中心、连接器、定时任务、内置浏览器、语音输入、五轨记忆、应用中心 |
| **本地 Harness 服务** | 员工机器，`127.0.0.1` 上的随机端口（可固定） | 跑固定版本的上游 DeepSeek Harness：会话与消息日志、文件读写、工作区、沙箱与审批、工具执行 |
| **企业服务端** | 客户内网一台机器（一个容器镜像） | 账号与认证、模型网关与密钥、计量计费与余额闸门、能力中心与审批、连接器目录、应用中心、审计、客户端分发、门户页与管理后台 |

一次模型请求的路径：客户端登录服务端 → 拉取模型清单（`/api/client/v2/config/bootstrap`）→ 请求打到服务端的 `/v1/chat/completions` → 服务端过限流与余额闸门 → 按模型匹配上游 provider → 计量与余额扣减同事务。**上游 API Key 只存在于服务端**，客户端拿不到。

## 企业视角：它抬高的是一条水位线

企业买 AI，最终要的不是「某个人用得很顺」，而是**组织整体的能力往前挪一格**。这套平台正对着后面三步：

| 水位 | 典型特征 | 平台里对应的东西 |
|---|---|---|
| 个人尝鲜 | 员工各自用外部工具，数据出企业，成本是一笔糊涂账 | 客户端随服务端分发，员工只访问企业域名；上游密钥只在服务端 |
| 部门试点 | 每个部门各接一套，成果无法横向复制 | 统一模型网关与模型目录（接新模型是改配置，不是改代码）；能力中心按用户或部门授权 |
| 平台化复用 | 技能、智能体与应用变成可检索、可审批、可复用的资产 | [能力中心](/desktop/)（员工上传 → 管理员审批 → 全员复用，归属清晰）、五轨记忆（项目经验按目录与分支沉淀）、[应用中心](/apps/)（业务自建小工具，同事直接打开） |
| 可度量的 AI 原生 | 管理层看得到水位：谁在用、用在哪、花了多少、哪些能力被复用了 | [用量中心](/admin/)（按部门 / 成员 / 模型拆账，账本可逐笔对账）、余额闸门、审计日志（哈希链） |

水位是**量出来的，不是问卷估出来的**：采用面看用量中心，沉淀面看能力中心与应用中心里的资产，
治理面看审计与余额 —— 三面在同一台服务器上，口径一致。实现细节见[安全与合规](/security/)。

## 当前支持什么

| 能力 | 形态 |
|---|---|
| 平台 | Windows x64（NSIS 安装程序）、macOS Apple 芯片（DMG）、Linux x64（AppImage） |
| 部署 | 企业内网容器化（Caddy + server + postgres）、并入已有反代、单二进制 + 外部 PostgreSQL、离线部署 |
| 客户端登录 | 服务端配置的本地账号 / LDAP / OIDC（浏览器授权）；管理员可开两步验证（TOTP） |
| 会话与工具 | 会话绑定工作区；权限三档（只读 / 工作区内修改 / 完全权限）；写文件、跑命令、操作浏览器按次审批 |
| 沙箱 | Linux 走 Landlock，Windows 走目录 ACL，macOS 走 Seatbelt |
| 能力分发 | 能力中心：技能与智能体；来源「市场 / 组织 / 本地」；上传走审核 + 授权「双门制」 |
| 外部系统 | 连接器：一条标准 MCP 配置（`type` + `url`，或 `command`/`args`/`env`），OAuth 授权码 + PKCE，令牌自动续期 |
| 自动化 | 定时任务：cron + 提示词 + 工作区 + 智能体预设 + 权限，执行历史可查；应用完全退出期间错过的触发默认跳过 |
| Agent 操作浏览器 | 独立浏览器窗口、多标签、控制权按钮交接、下载默认 100MB 上限、操作日志 |
| 语音输入 | 本机子进程识别（音频不出机器、离线可用），中英日韩粤自动识别，上限 120 秒 / 4MiB |
| 记忆 | 五轨记忆（用户档案 / 全局事实 / 项目关键记忆 / 项目日志 / 每日日志），确认制写入 |
| 员工自建应用 | 应用中心：WASM 应用在客户端独立窗口打开，**服务端不需要为应用准备公网入口或证书** |
| 客户端升级 | 升级源只有一个 = 它登录的那台服务端；启动 60 秒后首次检查、之后每 6 小时一次；按 SHA-256 校验 |
| 随包运行时 | Node.js 24 / pnpm 11 / CPython 3.12 随客户端分发，只影响应用派生的子进程 |
| 渠道白标 | 名称、标语、欢迎语、标识、主题色、数据根、深链 scheme 在构建期注入镜像 |

## 当前不支持什么（边界）

这些不是「以后会做」，而是有意的边界；写在这里是为了让你在部署前就能判断可行性。

| 边界 | 具体含义 |
|---|---|
| 没有云端托管版 | 产品不自建 SaaS。服务端跑在客户自己的机器上，安装包随镜像分发，不经任何镜像仓库 |
| 客户端不直连模型厂商 | 模型清单、单价、可用性由服务端决定，上游密钥只在服务端；客户端没有本地模型配置入口 |
| 企业交付面不含 Linux deb | Linux 只交付 AppImage（本地构建的 deb 不对外） |
| macOS 只有 Apple 芯片 | 只产出 arm64 的 DMG，没有 Intel 版 |
| Windows 与 Linux 安装包未签名 | macOS 正式版已签名 + 公证；Windows SmartScreen 可能提示「未知发布者」，请用 `SHA256SUMS` 校验 |
| 不做静默重启安装 | 检查与下载是后台静默的，**安装一律由用户显式触发**（Windows 向导 / macOS 拖入 / Linux 手动替换） |
| 客户端默认不使用系统代理 | 系统代理、代理环境变量、PAC 与启动参数一律忽略；只有渠道字段或真实进程环境变量能打开退路 |
| 固定 `desktop` profile，无切换器 | 没有 profile 选择器、没有终端入口；`dsh plugin --profile desktop …` 会被 CLI 直接拒绝；第三方插件走用户补丁层，重启生效 |
| 员工端没有 MFA | 两步验证（TOTP）只保护管理后台登录；员工登录方式由服务端配置的 local / LDAP / OIDC 决定 |
| 应用不出公网 | 应用只在客户端窗口内打开，没有可被浏览器直连的应用地址，也没有应用子域与通配证书 |
| 记忆与内容写入不即时生效 | 会改变 AI 行为或对外可见的写入先进入待确认 / 待审核队列，由人或管理员拍板 |
| 品牌不在管理后台编辑 | 名称、标语、欢迎语、标识、主题色来自构建期注入的渠道内容；改品牌 = 重新构建对应渠道镜像 |
